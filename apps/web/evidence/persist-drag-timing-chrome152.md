## 口径

- 驱动方式 = **真实指针事件**（`mousedown → mousemove×N → mouseup`）走 `useGesture` 的同一条入口；
- **开关两组**分别导航：`?persist=0` 关掉自动保存（应用层测量旁路，默认开启）；
- 拖动**之前**先 `flush` 一次（把之前积压的变更清干净）⇒ "拖动期写入次数"只反映拖动期；
- 拖动跨度 = **3 个工作日**，拆成 **12** 个测试帧；
- **帧间隔** = 连续 rAF 的间隔（记录用；**不能用双 rAF 测帧时长**）；
- **主线程工作量** = 派发事件 + `await nextTick()`（不含帧等待）——与 G4 的滚动口径同源；
- **松手 → 落盘** = 松手后调一次 `flush()` 的墙钟（≤5s 那条出口条件的时效数字）；

> **强制杀进程 / 关页后重开**按 ADR 0009 §8 的口径归**人工复验**（浏览器杀进程不触 `beforeunload`，
> 活下来的只是"最后一次已完成的写入"）；上表证明的是**写下去的能被重开读到**。

## 判定口径

- **拖拽期间不产生可见掉帧**：帧间隔 p95 ≤ 33.3 ms（≥30 fps），**两组都要成立**；
- **回退栈相对全量快照的收益**：拖动期自动保存写入次数 = **0**（写盘不落在拖动帧里）；
- **自动保存 ≤5s**：松手 → 落盘完成的墙钟必须远小于 5,000 ms；
- 开了持久化的那一组**不得比关掉的那组更差**（帧间隔 p95 差 ≤ 1 帧）；

- **开组 errors**：持久化还没就绪（启动恢复未完成）
