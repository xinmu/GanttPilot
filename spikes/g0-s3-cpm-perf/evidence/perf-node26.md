# S3 · L2 性能证据（测量快照 · Node 26.7.0）

> 由 `node src/run-all.mts` 生成。**本文件是测量快照**：数值随机器、负载与运行时版本变化，
> 重跑必然不同（这是唯一允许逐字节变化的证据，见 README 的稳定性纪律）。

口径：`p50/p95/p99` 为 **median-of-suites**（同一场景跑多个 suite 后取中位数），
同时给出最差 suite 的 p99；单位自适应（低于 1 ms 用 µs 显示）。日期维度一律是**工作日序号**（整数），因此热路径上没有 `Date`。

## 一、门禁判定

| 门禁 | 判据 | 实测 | 判定 |
|---|---|---|---|
| **G3-a** | 全量重算 p99 ≤ 100 ms @1,000/1,500 | 最差数据集 p99 = 78.20 µs（3 个数据集） | ✅ 通过 |
| **G3-b** | 非关键编辑的后继闭包传播 p99 ≤ 10 ms | 最差数据集 p99 = 0.90 µs（2 个数据集） | ✅ 通过 |
| **G3-c** | 关键路径编辑的耗时被量化（预期不满足 10 ms） | 关键编辑闭包传播最差 p99 = 49.40 µs；受影响子图规模 D1-wide-shallow:27/1000，D2-deep-chain:940/1000，D3-dense-cross:89/1000 | 📏 已量化 |
| **IX-04** | 松手后合并重算（含逆向/浮动/关键路径）p99 ≤ 200 ms | 最差数据集 p99 = 71.10 µs（3 个数据集） | ✅ 通过 |
