## 二、更正文档中的一处笔误（必须回写）

[证伪实验计划.md](../../docs/00-baseline/证伪实验计划.md) 与 [评估报告.md](../../docs/00-baseline/评估报告.md) 中写作：

> `<p:cNvCxnSpPr><a:stCxn id idx/><a:endCxn id idx/></p:cNvCxnSpPr>`

**正确写法是 `<a:cNvCxnSpPr>`（`a:` 前缀），且外层容器是 `p:nvCxnSpPr`。**
依据：WPS 原生 `AddConnector` 产物的真实 XML（`evidence/wps/D-native-slide1.xml`）。

另有两处**新发现**（原文档未提及，直接影响 G7 实现）：

1. **原生产物不写 `<a:cxnSpLocks/>`**（全局检索 0 次命中）。补丁应与原生一致，不要凭习惯加上。
2. **`a:stCxn@idx` 是 preset geometry 的连接点序列，不是 PowerPoint COM 的枚举值。**
   实证：脚本对 `bar-a` 调 `BeginConnect($barA, 3)`，WPS 落盘为 `idx="2"`。
   对 `roundRect` 而言 OOXML 序列是 `0=上 1=左 2=下 3=右`，而 COM 是 `1=上 … 4=右`——**相差 1**。
   这是最易踩且最难自查的坑：写错 idx 通常**不报错**，只是端点吸附到错误的边。

## 三、关键证据

### 3.1 权威形态基准：让 WPS 自己写出正确答案

`src/wps-native-reference.ps1` 用 WPS **原生** `AddConnector` + `BeginConnect/EndConnect` 造出
`out/D-wps-native.pptx`，再解包 dump 其 `slide1.xml`。补丁器是按这份真实产物逐属性对齐写的，
而不是按记忆或第三方文档——这避免了"照着文档写、文档本身写错"的循环。

### 3.2 L1 结构：27 条断言全过

见 [`../structure-report.md`](evidence/structure-report.md)。其中值得一提的几条：

- `ids-unique`：id 全树唯一（**含 `<p:grpSp>` 内嵌子形状**——组 id=6 与子 id=7、8 同处一棵树）；
- `connector-anchors-a-namespace`：锚点确实落在 `p:nvCxnSpPr > p:cNvCxnSpPr`；
- `group-child-space-distinct`：`chOff/chExt` 与 `off/ext` 是**两套不同数值**，
  确保坐标换算公式真的参与了（若两者相同，写错也看不出来）；
- `group-absolute-crosscheck`：**两条独立路径**复算子形状绝对坐标并逐值比对——
  一条是补丁器内存中的映射，另一条**只依据从 XML 解析出的 `off/ext/chOff/chExt`**。

### 3.3 L2 往返：WPS 接受并以同值保留

见 [`../wps/A-absorption-roundtrip-report.md`](evidence/wps/A-absorption-roundtrip-report.md)。

| 项 | 补丁刚写出 | WPS 保存后 |
|---|---|---|
| `cxnSp` / `grpSp` | 1 / 1 | 1 / 1 |
| `stCxn` / `endCxn` | `id=2 idx=2` / `id=3 idx=0` | **同值** |
| 形状 id 集合 | `#1,bar-a#2,…,grp-child-2#8` | **完全一致** |
| `cxnSpLocks` | 0 | 0 |

### 3.4 L3 视觉：模型视觉判读 + 像素量化

见 [`../vision/判读记录.md`](evidence/vision/判读记录.md) 与 [`../vision/pixel-quantification.md`](evidence/vision/pixel-quantification.md)。

- 连线两端**确实终止于目标形状边框**：连线像素到 `bar-a` 最近 **1.0 px**、到 `bar-b` 最近 **1.0 px**（线宽约 2–3 px）；
- 走线为规整正交折线，不穿越形状内部；
- 菱形里程碑以菱形呈现，所有元素未被画布裁剪（**此处曾发现真实缺陷**，见 §六）。

### 3.5 L4 自动化拖动：端点跟随 **且走线改道**

用 COM 把 `bar-b` 从 `L=420,T=240` 移到 `L=300,T=280`（左移 120、下移 40 pt）后：

| 时点 | off.x | off.y | ext.cx | ext.cy | xfrm 属性 |
|---|---|---|---|---|---|
| 移动前 | 2032000 | 1346200 | 4572000 | 1701800 | （无） |
| 移动后 | 2451100 | 927100 | 2209800 | 3048000 | `rot="5400000" flipV="1"` |

即 **WPS 主动重算了连接符几何并新增旋转/翻转属性**，视觉上端点仍吸附在
`bar-a` 下边中点与 `bar-b` 新的上边中点（像素距离 2.0 px）。

> **这个实验为什么有判别力**：WPS 引擎本身**确实支持**连接符跟随——
> 用原生 `AddConnector` 建的连线，移动形状后端点保持吸附且走线重算（已单独实测）。
> 因此若补丁产物不跟随，原因只能落在"补丁写出的 `cxnSp` 形态不被接受"，即**证伪**，
> 而非"工具本来就不支持"这种无信息的失败。

### 3.6 附加发现：拍平与保留 group **渲染逐字节相同**

`C-flat.pptx`（把子形状写成幻灯片绝对坐标）与 `A-absorption.pptx`（保留 `<p:grpSp>` + 映射）
渲染结果 **sha256 完全相同**（`1DD22A20E6EF28E41F1786FF6A1D5E7B20667BAAFFA9A53B088478FFD0284C65`），
且同一文档重复导出 4 次全部同值（渲染可复现）。

**价值**：这同时证明了两件事——
1. group 坐标换算实现正确（两种表达方式几何等价）；
2. 若 G7 阶段遇到 group 兼容性问题，**"拍平成绝对坐标"是一条已验证的降级路径**。

## 五、本结论的边界（必须与结论一起读）

1. **验证环境是 WPS，这是有意的决策而非环境限制。** 本机没有 Microsoft PowerPoint
   （全盘与注册表均无 `POWERPNT.EXE`），但按 §七 引述的裁决 P-4，WPS 即为一等验证环境，
   因此这**不再是一个缺口**，而是选定的口径。PowerPoint 为备查。
2. **WPS 的 COM 会伪装成 PowerPoint。** 它自报 `Name = "Microsoft PowerPoint"`、`Version = "12.0"`，
   而实际是 WPS Presentation 12.1.0.28505。**这个字符串绝不能作为"用 Microsoft PowerPoint 验证过"的证据。**
   本 spike 的所有脚本一律通过 `KWPP.Application` 创建实例以避免混淆。
3. **"合法"不等于"路由正确"。** 按 [评估报告 §5.1](../../docs/00-baseline/评估报告.md)：
   正确的 `stCxn/endCxn` 仍可能渲染出错误走向——这正是 G1-a 必须**人工拖动观察**而不能只看 XML 的原因。
   本结论据此只主张"端点吸附与几何跟随"，不主张走线美观在不同实现间完全一致。
4. **视觉层由 WPS 渲染。** 视觉与像素证据**能证伪、不能定论**；对精确端点索引与亚像素吸附不可靠。
   （因此 §四 的 G1-a 判定依赖**人工真机操作**，不以模型视觉单独定论。）
5. **未用 LibreOffice 作为证据**（本机未安装，且协议明确它不构成成功证据）。
6. **spike 代码不进主干。** 本目录只交付"可行性与正确形态"；补丁算法在 G7 由
   `@ganttpilot/pptx-renderer` 重新实现（`spikes/` 不在 pnpm workspace 内，不参与门禁构建与许可审计）。

## 六、过程中发现并修正的真实缺陷（值得记录）

1. **manifest 的幻灯片尺寸与容器不一致（`960×540` vs 实际 `720×405` pt）。**
   后果：所有边界断言都拿错误的常量比较，`group` 底边落到画布外**被裁掉**却"L1 全绿"。
   修正：把 `SLIDE` 改为容器实测值，并新增 `container-slide-size-matches-manifest` 断言——
   让"常量与容器漂移"这件事本身失败，而不是让下游断言集体失灵。
   *教训：边界断言的价值取决于边界常量是否可信，因此必须有一条断言专门校验该常量。*
2. **group 目标宽高比与子形状包围盒不匹配**（10:1 vs 12.5:1）。
   守卫 `buildGroupMapping` 直接报错而非静默拉变形——**非等比缩放会把圆角矩形与菱形拉坏**。
   修正：由 `chExt` 比例推导目标高度，避免手写两个数字再次写错。
3. **校验器无法下钻 `<p:grpSp>`**（`sliceShapes` 的配对正则匹配到外层组即停止），
   导致"组内子形状数 = 0"而误报。修正：为组内子形状单独写 `sliceGroupChildren`。
4. **像素量化的包围盒被同色非连通像素污染**（`bar-a` 一度被量成 490×572 px，真实 443×78）。
   修正：改用**连通域**分组再取包围盒。
5. **WPS 打开文档时会锁定 pptx 文件**，导致"打开后再解包原件"失败。
   修正：把"移动前"的 XML 提取移到打开之前。

## 七、验证环境口径（裁决 P-4，2026-10-03）

> 本条是**决策记录**，不是实验发现。它改变了 §四 门禁的"真机"定义。

**决策**：

1. **开发过程全部使用 WPS**；
2. **门禁以 WPS 验证为准**——包括人工操作验证与 COM 自动化验证；
3. **Microsoft PowerPoint 作为备查，不阻塞**开发与合并。

**该决策的落地影响**：

| 项 | 原口径 | 现行口径 |
|---|---|---|
| G1-a 的"真机" | Microsoft PowerPoint 2016/365 | **WPS Presentation** |
| EX-05 兼容矩阵 | Office 2016+/365/WPS **必过** | **WPS 必过**；Microsoft PowerPoint **备查**（不承诺） |
| Keynote | 明确不保证 | 不变（Apple 官方兼容矩阵已证连接线降级为直线） |
| G7 出口条件 | 含"PPTX 在 PowerPoint 2016/365 打开无修复弹窗" | 该项降为"备查记录"，不作为门禁 |

**必须同时接受的代价（诚实记录）**：

- 产品对外**不承诺** Microsoft PowerPoint 下的拖动跟随行为；
  这比"三端必过"是**收窄**的承诺，需在 README 的已知限制中明写，以关闭超范围 issue。
- 输出的仍是**标准 OOXML 原生形状**（`p:cxnSp` + `a:stCxn/endCxn`、`p:grpSp` + 显式 `chOff/chExt`），
  未使用任何 WPS 私有扩展。因此"在 PowerPoint 下大概率可用"是合理预期，
  但**未经验证**，故只写"备查"、不写"保证"。
- 早先记录的一个真实风险仍然成立：WPS 的 COM 会自报为 "Microsoft PowerPoint / 12.0"，
  容易让人误以为做过 PowerPoint 验证。**该伪装字符串不构成证据**。

**本决策已正式裁决**：见 [裁决记录 P-4](../../docs/00-baseline/裁决记录.md)（第四轮）。本文件 §七 是其落地记录；
条款级改写（EX-05）已由 P-4 授权，[需求基线 EX-05](../../docs/00-baseline/需求基线.md) 与
[首版能力顺序](../../docs/01-roadmap/首版能力顺序.md) 的对应条目均已同步。

## 十、如何复现本结论

```bash
cd spikes/g0-s1-pptx-connector
pnpm install --ignore-workspace        # 隔离安装，不影响根 workspace

node src/run-all.mts                   # 生成 fixture + L1 结构自检（27 条断言）
pwsh -File src/wps-native-reference.ps1  # 重新生成"权威形态"基准 XML
pwsh -File src/wps-capture.ps1         # L2 往返 + L3 渲染取证（A-absorption）
pwsh -File src/wps-capture.ps1 -Fixture C-flat   # 拍平对照
pwsh -File src/wps-drag.ps1            # L4 自动化拖动实验

# 像素量化侧证（需本机 Python + Pillow）
python src/verify-pixels.py evidence/vision/A-drag-after.png
```

复现时请注意：`wps-*.ps1` 会启动 WPS 并通过 `finally` 释放 COM 实例；
若中断，`wpp.exe` 可能残留，需手动结束。
