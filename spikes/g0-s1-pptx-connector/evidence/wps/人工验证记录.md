## 这条证据的地位

按 [评估报告 §5.1](../../../../docs/00-baseline/评估报告.md) 的原则——**"合法"不等于"路由正确"，
必须真机拖动观察**——本条是**人工真机观察**，因此它闭合了 G1-a 的实质判据（原来缺的正是"人工在真机里拖动"这一环）。

它与自动化证据的关系是**同向互证**，而不是重复：

| 证据 | 类型 | 观察者 | 结论 |
|---|---|---|---|
| `A-drag-before.png` / `A-drag-after.png` | COM 移动几何 + 导出渲染 | 模型视觉判读 + 像素量化 | 端点跟随、走线改道（1–2 px 贴合） |
| `A-after-drag-saved-by-wps.xml` | 落盘 XML | 结构断言 | `xfrm` 被重算、锚点存活 |
| **本文件** | **人手拖动真机操作** | **人** | **端点跟随；且与上述自动化结果一致** |

三条独立路径（模型看渲染 / 断言看 XML / 人手动操作）给出一致结论，可信度高于任何单一证据。

## 仍不在本条覆盖范围内的（诚实标注）

1. **Microsoft PowerPoint 未验证。** 按裁决 P-4，PowerPoint 为**备查**、不阻塞；
   因此产品对外**不承诺** PowerPoint 下的拖动跟随行为（见 README 已知限制）。
2. **Keynote** 已有反证（Apple 官方兼容矩阵：连接线导入为直线），明确不保证。
3. 本条验证的是**吸附与跟随语义**，不是走线美观（`bentConnector3` 的肘形走向在不同实现间可能有差异）。
