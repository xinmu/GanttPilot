## 一、结论速览（能 / 不能 / 需降级 + 代价）

| 能力 | 判定 | 依据层级 | 代价 / 附注 |
|---|---|---|---|
| ExcelJS 写出规范工作簿 | **能** | L1 | 固定 `created/modified` 后，同一模型两次写出的**部件内容逐字节相同**；**整文件字节并不确定**（zip 条目时间戳 = 写入时刻）——golden 比对须用部件指纹（§六.2） |
| ExcelJS 读回自家产物 | **能** | L1 | 写→读零漂移；214 格与 zip 层原始读取逐格一致 |
| 日期以真日期（序列号）往返 | **能，但有硬约束** | L1 + L2 + L2b | **必须 `Date.UTC` 构造**；本地零点构造在 UTC+8 下落盘为 `…6667` 的小数序列号，Excel 显示前一天（§三.4） |
| 日期编码选型 | **选「真日期 + `yyyy-mm-dd`」** | L1 + L2 | 序列号全为整数、WPS 保存后仍是日期类型；代价：必须接受第三方对**数字格式码的转义**（`yyyy\-mm\-dd`），解析只判「是否日期格式」而不能比对格式码文本 |
| 里程碑以布尔（`t="b"`）往返 | **能** | L1 + L2 + L2b | WPS 保存后仍是布尔单元格；解析侧另需接受 `是/否`、`TRUE/FALSE`、`1/0` |
| 进度以 0..1 + `0%` 往返 | **能** | L1 + L2 + L2b | 解析规则「≤1 为分数，>1 为百分数」对两种编码同时正确 |
| 依赖列 `编号[FS\|SS\|FF\|SF][±lag]` 往返 | **能** | L1 + L2 + L2b | 16 条边（四类关系、正/负/0 lag、分号多前置、省略类型）逐条相等 |
| 层级由 WBS 编号承载（缩进仅显示） | **能** | L1 + L2 + L2b | 清空 `alignment.indent` 后解析结果不变（剔除缩进字段后逐字节相同） |
| `=`/`+`/`-`/`@` 前缀文本安全往返 | **能** | L1 + L2 + L2b | 以共享字符串落盘，**从未被当作公式**；见 §六.3（这收窄了 G-9 的必要范围） |
| WPS「打开 → **仅保存**」后语义存活 | **能** | L2 | 0 处语义差异、0 诊断；WPS 重写了 11 个部件但未触碰任何单元格的值与类型 |
| WPS「打开 → **编辑** → 保存」后语义存活 | **能** | L2b | 恰好 3 处已声明的差异（名称/进度/日期），其余 0 漂移；改后的日期被正确读为 `2026-10-12` |
| **Microsoft Excel 往返** | **未验证（备查）** | — | 本机无 Microsoft Excel；`Excel.Application` 被 WPS 劫持（§五.1）。不对外承诺 |
| **Google Sheets 往返** | **本轮不做（遗留）** | — | 用户裁决：仅在结论记一句，不交付工具与流程（§七） |

**没有出现需要产品叙事降级的证据。** 按 [首版能力顺序.md §四](../../docs/01-roadmap/首版能力顺序.md) 的延后规则，
「可见列自足」这一路线**不触发**任何降级分支；变的是**实现约束**（日期构造方式、格式码不可比对），
这些约束已写入 §八 的 G3 交接清单。

## 三、关键证据

### 3.1 L1：自往返 + 双路径 + 编码落地 + 负向对照（15 条全过）

见 [`evidence/structure-report.md`](evidence/structure-report.md)。要点：

- fixture：**28 行 / 16 条边 / 最大深度 2 / 4 个里程碑 / 7 行无日期**，覆盖 FS·SS·FF·SF 四类关系、
  lag 正/负/0、分号多前置、省略类型（默认 FS）、空单元格、中文与 emoji、超长文本、
  `=`/`+`/`-`/`@` 前缀文本；
- 规范化产物 **8892 字节 / 10 个部件**，**部件指纹** `084936632dcc8ab8…`
  （条目名 + 各条目内容哈希的摘要；这是可比对的工件身份，见 §六.2）；
- **部件级确定性**：同一模型两次写出的 10 个部件内容逐字节相同；
  **整文件字节不保证相同**——exceljs 会把写入时刻写进 zip 条目时间戳（实测：跨秒两次写出的
  文件哈希不同而部件指纹相同）；
- **双路径逐格一致 214/214**：ExcelJS 对象层（会把序列号解释成 `Date`）与 zip 层原始单元格
  （直接读 `t`/`<v>`/`styles.xml` 的 numFmt）互不共享代码；
- **比对基准是声明式期望值表**，不是「重新序列化的模型」——避免写入器与读取器共享同一个错误而全绿。

**负向对照（判据有判别力的证明）**——把写出的文件按字节变造 5 处，要求判定集必须报出：

| 变造 | 结果 |
|---|---|
| NC1 把某日期单元格的落盘类型从数值改成 `t="str"` | 被 `raw-cell-types` 等 7 条判据报出 |
| NC2 把某日期序列号 +1 天 | 被 `field-equality` 等 4 条报出 |
| NC3 把某进度值 0.5 → 0.75 | 被 `field-equality` 等 4 条报出 |
| NC4 把表头「前置任务」改名 | 被 `header-row` 等 5 条报出 |
| NC5 删掉一行 | 被 `raw-cell-types`、`field-equality`、`edge-equality` 等 6 条报出 |

### 3.2 L2：WPS「仅保存」——语义 0 漂移，但 WPS 重写了 11 个部件

见 [`evidence/wps-save/roundtrip-report.md`](evidence/wps-save/roundtrip-report.md) 与
[`entry-diff.md`](evidence/wps-save/entry-diff.md)。

| 项 | 结果 |
|---|---|
| 语义字段差异 | **0 处**（28 行 × 7 字段逐字段相等） |
| 依赖边 | 16 条全部一致 |
| 结构判据（与 L1 同一套） | 全部通过，**0 诊断** |
| 落盘单元格差异 | 42 处——**全部只是数字格式码的转义**（`yyyy-mm-dd` → `yyyy\-mm\-dd`），数值与类型未变 |
| 部件级 | 10 个部件被**重写**、1 个**新增**（`docProps/custom.xml`）；`styles.xml` 从 2176 字节涨到 20577 字节 |

**这就是解答「第三方到底重写了什么」的直接证据**：WPS 会重写容器与样式（并注入自己的自定义属性），
但**不触碰任何单元格的值与类型**。

### 3.3 L2b：WPS「编辑后保存」——声明式差异恰好 3 处

见 [`evidence/wps-edit-save/roundtrip-report.md`](evidence/wps-edit-save/roundtrip-report.md)。

| WBS | 字段 | 基线 | 变体 |
|---|---|---|---|
| 2.1 | 任务名称 | 渲染内核 | 渲染内核（已改名） |
| 2.1 | 进度 | 0.5 | 0.75 |
| 3.1 | 开始 | 2026-10-05 | **2026-10-12**（WPS 存为日期序列号并被正确读回） |

未声明的任何差异都会判失败，因此「读错了」不会被当作「改过了」放过。

### 3.4 时区陷阱：现场取证（**本 spike 最要紧的一条**）

依据（源码核验，`exceljs/lib/utils/utils.js`）：

```
dateToExcel(d) = 25569 + d.getTime() / 86400000
```

**序列号由绝对时刻推导，而不是由「年月日」推导。** 实测（`out/tz-probe.xlsx`，
见 [`evidence/structure-report.md`](evidence/structure-report.md) 末表）：

| 构造方式 | 落盘序列号 | 是否整数 | Excel 会显示的日期 | ExcelJS 读回的日期 |
|---|---|---|---|---|
| `new Date(Date.UTC(2026,9,5))` | 46300 | 是 | **2026-10-05** | 2026-10-05 |
| `new Date(2026,9,5)`（本地零点） | **46299.66666666667** | **否** | **2026-10-04** | 2026-10-04 |
| `new Date('2026-10-05')` | 46300 | 是 | 2026-10-05 | 2026-10-05 |
| `Date.UTC + 12h` | 46300.5 | 否 | 2026-10-05 | 2026-10-05 |

**结论**：规范导出必须用 `Date.UTC(y, m-1, d)`（或 `new Date('yyyy-mm-dd')`）；
**禁止** `new Date(y, m-1, d)` 与任何带时刻的 `Date`。这不是「风格问题」——它会让用户看到差一天的日期。

### 3.5 规模与体积观测（**非门禁**）

见 [`evidence/timing.md`](evidence/timing.md)：

| 行数 | 产物字节 | 写出 | `xlsx.load` | zip 直读 + 解析 | ExcelJS 对象层 + 解析 |
|---|---|---|---|---|---|
| 200 | 17095 | 27–30 ms | 23–24 ms | 15–24 ms | **2 ms** |

## 五、过程中发现并记录的环境事实（值得留痕）

1. **WPS 伪装成 Microsoft Excel。** 实测：

   | ProgID | 解析到 | 自报 |
   |---|---|---|
   | `KET.Application` | WPS 表格 12.1.0.28505 | `Name="Microsoft Excel"`、`Version="12.0"`、`Path=…\Kingsoft\WPS Office\12.1.0.28505\office6` |
   | `Excel.Application` | **同上（被劫持）** | 同上 |

   与 S1 的 `KWPP.Application` 伪装成 "Microsoft PowerPoint" 完全同类。
   **该字符串不构成「已用 Microsoft Excel 验证」的证据**——本 spike 一律用 `KET.Application`。
   本机 `C:\Program Files (x86)\Microsoft Office` 为空目录，全盘无 `EXCEL.EXE`。
2. **WPS 打开会锁定文件**（S1 已踩）：「打开前」的字节事实必须在打开之前取完，否则解包读原件会失败。
3. **`docProps/core.xml` 与 `docProps/custom.xml` 每次运行字节必然不同**（WPS 写入时间戳）。
   因此二者不能进「哈希比对」型证据，否则每次重跑都会让工作区变脏——本 spike 在报告中显式排除它们。
4. **PowerShell ↔ WPS COM 的 `Cells.Value2` 不能混用 String 与 Double**：
   同一次会话里混用会抛 `Unable to cast object of type 'System.Double' to type 'System.String'`（复现两次）。
   统一走字符串 put 即稳定，且 WPS 自行解析：`'0.75'` → 0.75、`'2026-10-12'` → 序列号 46307。
5. **工程坑两处**（已在代码中就地注释）：
   - `exceljs@4.4.0` 的 `index.d.ts` **首行**是全局 `declare interface Buffer extends ArrayBuffer {}`，
     与 `@types/node` 的 `Buffer` 发生接口合并，导致 `xlsx.load(nodeBuffer)` 类型报错 → 见 `src/exceljs-interop.ts`；
   - JSZip 的类型名是 **`uint8array`**，不是 `uint8`（`entry.async('uint8')` 会抛「not supported by this platform」）。
6. **exceljs 会把写入时刻写进 zip 条目的 DOS 时间戳**：同一个模型在**跨秒**写两次，整文件字节不同
   （内容部件相同；实测跨进程两次写出的文件哈希不同、部件指纹相同）。因此本 spike 的确定性判据落在
   **部件指纹**上，`evidence/*` 的稳定性也据此成立。

## 六、三条与既有文档直接相关的发现

1. **T-2 的收益被实测确认**：不再有影子表，于是「隐藏态 bug（ExcelJS #2911）」「Google Sheets 剥离 veryHidden」
   「行键对账」三件事全部消失；WPS 仅保存后语义 0 漂移，说明「可见列自足」是成立的路线。
2. **导出必须固定文档时间戳，且 golden 比对要落在「部件」上。** 固定 `created`/`modified` 后，
   部件内容完全可复现；但 `exceljs@4.4.0` 会把**写入时刻**写进 zip 条目的 DOS 时间戳，
   因此**整文件字节**在跨秒重跑时不同（实测：跨进程两次写出的文件哈希不同、部件指纹相同）。
   G7 的「同一文档两次导出结构一致」以及 G3 的 golden 比对都应比对**部件内容**而不是文件哈希，
   否则会得到「永远不一致」的假失败。
3. **G-9（导出公式注入转义）的必要范围被收窄**：`=`/`+`/`-`/`@` 前缀文本在 ExcelJS 中以**共享字符串**
   落盘，WPS 保存前后都是 `t="s"`，**从未被解释为公式**。因此 xlsx 导出路径上的转义**不是必须**的
   （仍建议保留，且 CSV 路径属 G3 决策，见 §八）。

## 八、G3 交接清单（本 spike 证明的协议约束，供 `@ganttpilot/xlsx-protocol` 重写）

**A. 规范工作簿形态（提案，G3 定稿）**

- 单工作表 `任务`（可见、无隐藏表）、首行表头、**9 列规范列序**：
  `WBS | 任务名称 | 开始 | 完成 | 工期 | 前置任务 | 进度 | 里程碑 | 备注`；
- 层级由 **WBS 编号**承载（`1.2.3` → 深度 2），另在「任务名称」上施加 `alignment.indent` **仅作显示**；
  **解析不得依赖缩进**（有专门断言）；
- 空值 = 单元格缺失（不写空串）；汇总行可以没有日期与工期（DM-05）。

**B. 编码与容差（有实测支撑，属硬性要求）**

| 字段 | 导出 | 导入必须接受 |
|---|---|---|
| 日期 | **`Date.UTC(y,m-1,d)` + `yyyy-mm-dd`**（序列号必须为整数） | 真日期 / 数值序列号 / ISO 文本 `yyyy-mm-dd`（可加 `y/m/d`） |
| 工期 | 整数工作日 | 数值或数值文本 |
| 进度 | `0..1` + `0%` | 分数与百分数点位（**≤1 视为分数，>1 视为百分数**）、`50%` 文本 |
| 里程碑 | 布尔（`t="b"`） | 布尔 / `是`·`否` / `TRUE`·`FALSE` / `1`·`0` |
| 依赖 | `编号[FS\|SS\|FF\|SF][±lag]`，分号分隔，类型可省略（默认 FS） | 半角与**全角分号**；空片段容忍；未知编号进问题清单 |
| 文本 | 原样字符串（含 `=`/`+`/`-`/`@` 前缀、emoji、超长文本） | —— |

**C. 绝对不能依赖的东西（WPS 会改写）**

- **不能比对数字格式码的文本**：WPS 会把 `yyyy-mm-dd` 转义成 `yyyy\-mm\-dd`（42 处差异全部是这一类）。
  只判「是否日期格式」；
- 不能依赖部件哈希、`docProps/*`、`styles.xml` 体积、zip 条目顺序；WPS 会重写容器并新增 `docProps/custom.xml`；
- 不能依赖 `alignment.indent` 的取值（`0` 与「缺省」在两条读取路径上的表现不同，需归一化）。

**D. 工程约束**

- 写出时**固定** `workbook.created/modified`；**确定性判据取「部件指纹」**（条目名 + 各条目内容哈希），
  **不要用整文件哈希**——exceljs 会把写入时刻写进 zip 条目时间戳（§六.2）；
- 日期构造统一走 `Date.UTC`（或直接写序列号），并在代码里留注释说明原因（§三.4）；
- ExcelJS 只用于 xlsx：许可 MIT、4.4.0（2023-10-19，维护偏弱、813 个开放 issue）、不支持 `.xls`(BIFF)、
  不重算公式缓存；浏览器包体代价需在 G3 用真实 bundler 复核；
- **G-9 的收紧**：xlsx 导出路径上的公式注入转义**不是必须**（实测文本落为共享字符串）；
  但 CSV 路径仍应转义，且该决定的最终责任在 G3。
