### G1.1 日历与日期算术（工作日序号化）

> **状态：已完成（本块仅存档，不随新裁决更新，细则见块尾指针）。** 落地记录见本节的「落地记录」小节；用法见 [CONTRIBUTING](../../CONTRIBUTING.md)。

**内容**
- **日历与日期算术（D-4 / R-1）**：工作日语义、默认周一至周五 8h、项目时区"日期"基准、
  项目日历经 `workDays` + `exceptions`（"工作日→非工作日"与"休息日→工作日"两个集合；
  **同日冲突时非工作日优先**）；`calendars[]` 字段保留但 **v0.1 仅项目日历生效**（DM-06）；
- **按 S3 结论 §八 A/C 重写主干 `packages/engine/src/date.ts`**：日期以**工作日序号（整数）**承载
  （索引前缀和 + 序号表，查询 O(1)），日历**不进入传播热路径**；新增序号 ↔ ISO 日期翻译；
  现有 `countWorkdays` 的逐日循环（无 `exceptions`，实测慢约 340×）一并替换；
- `dayOfOrdinal(k = workdayCount)` 的语义定为"**最后一个工作日之后的首个工作日**"
  （与地平线长度无关，否则差分/黄金比对会因容量差异假失败）；
- **地平线容量**：按"全部工期 + 正 lag"的上界规划，不足时扩容重算；
- 保留 `parseIsoDate` 的严格校验与 `[start, end)` 半开区间语义（现有 `date.spec.ts` 用例作为回归基线）。

**出口条件**
- [x] 现有 `packages/engine/src/date.spec.ts` 全绿（语义不回归）；
- [x] 日期算术单测覆盖：跨周末、跨 `exceptions`（两类覆盖 + 同日冲突优先级）、负向推进、跨年、月中起算；
- [x] 序号 ↔ 日期往返一致（含 `k = workdayCount` 边界，以及地平线不足时的扩容路径）；
- [x] 索引前缀和与逐日循环两套实现互证一致（S3 结论 §三.1 的做法）；
- [x] lint 证明 `engine` 包零 DOM/框架依赖。

**可延后**：多日历（v0.1 仅项目日历生效，R-1）；小时级日历/日工时建模（D-4 已定 8h，v0.1 不做小时粒度）。

**细则**：→ [落地记录 G0–G4](首版-记录-归档-G0-G3.md)（本块仅存档）

  （依据：全量 p99 最差 60.3 µs，对 G5 的"引擎侧 ≤1ms/帧"有约 16× 余量，深链上增量与全量同阶——
  v0.1 没有需要增量算法的场景）。[S3 结论 §八 B.7](../../spikes/g0-s3-cpm-perf/结论.md) 的"增量传播"
  按裁决 P-12 映射解读（**证据层不改写，映射由裁决承担**）；
- **锚点规则（ADR 0004 §2）——本块唯一没有 spike 覆盖的设计面**：无前置者以**文档日期**为锚
  （无日期则回落项目起点，DM-05）；**有前置者被推导覆盖**并给 `dateOverridden` 诊断；
  拖拽的"会话内锚点"经 `anchors` 入参进入，**不进文档**；
- **汇总任务不参与排程**（日期/进度/里程碑计数等派生值由**引擎**产出，G4/G7 只排版）；
  依赖边端点为汇总任务时保留 G1.2 已有的 `LINK_SUMMARY_ENDPOINT` 警告并**在传播中忽略该边**；
  **里程碑（工期 0）照常参与传播**（US-2 的"威胁可见"对象）；
- `compute` 是**纯函数、唯一排程真相源**；**排程结果不写回文档**（文档只存输入，撤销只需回退输入 + 会话锚点）；
- **4 类关系 FS/SS/FF/SF + lag**（DM-03），lag 按工作日、归属项目日历（R-1）；
- 正向传播：由前置推 ES/EF；
- **检环**（DM-04、EN-05）：`wouldCreateCycle` 预检**返回成环路径**（G5 的高亮要用），
  `compute` 遇成环**不产出排程**；导入时丢弃成环边并进问题清单（丢弃发生在 G3）；
- 无日期节点容错（DM-05）：无日期/无关联的 WBS 节点不破坏传播（回落项目起点 + `undated` 诊断）；
- **日期表示与日历（S3 结论 §八 的硬性约束）**：日期一律以**工作日序号（整数）**承载，
  日历**不进入传播热路径**；序号 ↔ 日期的翻译用索引前缀和（O(1)），
  `Schedule` 因此**只出序号**，ISO 由 `Calendar` 翻译——**G1.1 已完成**（含 `exceptions` 双集合）；
- **验证策略（R-4 连锁影响 B 的落地）**：① 不变量/性质测试（`EF = ES + duration`、4 类关系边界方程、
  lag 传递性、`anchored`/`driven` 与文档日期的一致性）；② 小规模手工推导用例
  （4 关系 × 正/负/0 lag × 跨层级 × 日历例外 × 无日期节点 × 汇总端点）；
  ③ **独立参照实现差分测试**（跨语言 + 随机图差分）。**S3 已把 ① ② ③ 的可运行基建做好**，G2 直接复用；
  资产落 **`tools/cpm-reference/`**（`engine` 包内不放非 TS 资产），
  **差分进 `pnpm gate`，缺 Python 3 时失败而不是跳过**（裁决 P-12；Windows 上缺 `python` 表现为退出码 9009，
  静默跳过是实测过的真实风险）。

**出口条件**
- [x] **实现与 [ADR 0004](../02-adr/0004-排程契约.md) 的契约一致**（锚点规则、汇总/里程碑语义、
  项目起点与负 lag 截断、`Schedule` 形状与诊断码表、检环 API）；契约变更须追加 ADR 并同步本节。

  `createScheduleCalendar` 容量入口、两处有意抛出、诊断 severity 表）；

  另有三条负向对照（FS→SS 必须改变结果、打坏期望值必须不一致、20 个种子里必须出现截断）；
- [x] 不变量测试在随机生成的 ≥1,000 个图上通过；
  `schedule.invariants.spec.ts` 在 **1,000 张随机图**上零违规（独立检查器：逐日循环重算工期、
  沿父链重算汇总、边界方程、`anchored`/`driven` 与文档日期一致性、`clampedStarts` 与诊断同数），
  并有一条"偷换依赖类型必须被边界方程检出"的负向对照；
- [x] **差分测试**与独立参照实现在 ≥1,000 个随机项目图（含 200 个成环图）上结果一致，
  且**差分步骤在门禁中真实运行**（缺 Python 3 即失败，不得静默跳过）；
  `schedule.differential.spec.ts` + [`tools/cpm-reference/cpm_reference.py`](../../tools/cpm-reference/cpm_reference.py)
  （**独立写法**：`datetime` 逐日日历 + DFS 三色检环 + 递归记忆化 + `list`/`dict`），
  **1,000 DAG + 200 成环图、0 不一致**（实测约 4.5 秒）；缺少 Python 时抛错失败并给出
  `GANTTPILOT_PYTHON` 提示；
- [x] 1,000 任务 + 1,500 依赖**全量传播 p99 ≤ 1ms**（原文 EN-08 的 100ms **保留为产品侧不回归天花板**；
  收紧依据见裁决 P-6：S3 实测最差 p99 = 52.1 µs，余量约 19×）。
  **实测（Node 24，本机）**：产品口径的 `compute()`（含日期解析、工期解析、诊断收集与结果分配）
  **p50 = 326 µs / p99 = 530 µs**（最差 suite p99 = 644 µs）⇒ 对 1ms 有约 **1.9×** 余量；
  注意 S3 的 52.1 µs 是**只测传播内核**的窄口径（预建 CSR、无日期与诊断），两者不可直接比较；
- [x] `affectedClosure` 只断言**结构性事实**（闭包规模、深链覆盖全图），**不加时序门禁**；
  `schedule.closure.spec.ts`：深链 1,000 节点上闭包 = 全图、从链尾出发 = 1 个、结果按文档序且与种子顺序无关。

（含"闭包内逆后序重算"）一并延后——若 G5 的浏览器实测整帧不达标再引入，届时以实测为依据。
**原因**：浮动/关键路径全局耦合（评估报告 §5.3），成本高且不支撑首版卖点；增量在 v0.1 无收益（见内容第 1 条）。

**内容**
- 导入：缩进式 与 WBS 编号列 **双解析**（XL-01，优先级与冲突口径见 ADR 0006 §6）+ 列映射向导 ≤3 步（XL-02；
  协议层只交 `detectColumns`，向导形态在 `apps/web`）；
- 依赖列语法 `编号[FS|SS|FF|SF][±lag]`，分号分隔多前置（XL-03）；
- 导入即接入 G2 内核 → 得到可渲染的 `Schedule`（`createScheduleCalendar` → `compute`）；
- 导出：**规范化 schema 输出**（XL-06 改写）——按 WBS 顺序、规范列序、规范日期格式与依赖语法；
