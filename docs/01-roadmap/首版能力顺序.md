## 一、排序原则

1. **证伪优先**：最可能推翻产品假设的未知项先做，只花 1–3 天，且**不写产品代码**。
2. **内核先行、分析层延后**（T-3 修正）：日期传播内核是**几何来源**（条形位置、连线端点、SVG/PPTX 坐标全由它推导），必须早做；而 CPM 分析层（浮动/关键路径）全局耦合、成本高、不支撑首版卖点，延后。
3. **一条主链路走通胜过五条半成品**：优先级按"能否让'导入 → 出图 → 拖动 → 导出'闭环推进"排序，而非按模块重要性排序。
4. **导出后置**：SVG/PPTX 导出依赖渲染几何与排程结果，必须在 G4/G2 之后；提前做只能得到空壳。
5. **护栏先于功能**（原文前提）：测试框架与 CI 是"正确性关键模块"的准入门槛，与 spike 同期建立。

### G2 最小正向传播内核（**T-3 修正后的新增必做项**）

> 这是本次排序与原文/初版权衡**最关键的差异**。没有它，甘特图只能画"手填日期"，拖拽不会传播，US-2 做不出来，且首版相对"Excel + 截图"没有增量。

**内容**
- `compute(tasks, links, calendars, constraints) → Schedule`（原文 §6，纯函数、唯一排程真相源）；
- **4 类关系 FS/SS/FF/SF + lag**（DM-03），lag 按工作日、归属项目日历（R-1）；
- 正向传播：由前置推 ES/EF；
- **检环**（DM-04、EN-05）：建边预检 + 导入时丢弃成环边并进问题清单；
- 无日期节点容错（DM-05）：无日期/无关联的 WBS 节点不破坏传播；
- **验证策略（R-4 连锁影响 B 的落地）**：① 不变量/性质测试（`EF = ES + duration`、4 类关系边界方程、lag 传递性）；② 小规模手工推导用例（4 关系 × 正/负/0 lag × 跨层级 × 日历例外）；③ **独立参照实现差分测试**（另一语言/写法的数十行实现 + 随机图差分）。

**出口条件**
- [ ] 4 类关系 × lag（正/负/0）× 跨层级 × 日历例外的手工用例全过；
- [ ] 不变量测试在随机生成的 ≥1,000 个图上通过；
- [ ] **差分测试**与独立参照实现在 ≥1,000 个随机项目图上结果一致；
- [ ] 1,000 任务 + 1,500 依赖**全量传播 p99 ≤ 100ms**（原文 EN-08，已核验为可达成）。

**明确延后至 v0.5**（EN-01/02/03）：逆向遍历 LS/LF、总浮动/自由浮动、关键路径高亮、增量优化。**原因**：浮动/关键路径全局耦合（评估报告 §5.3），成本高且不支撑首版卖点。

### G3 xlsx 导入 / 导出（仅可见列，T-2）

> **本块的实现约束以 S2 的实测结论为准**（日期构造方式、编码容差、不可依赖项、工程代价）：
> 见 [G0-S-S2 结论](../../spikes/g0-s2-xlsx-roundtrip/结论.md) §八「G3 交接清单」。
> 三条最容易踩的：**日期必须 `Date.UTC` 构造**；**不能比对数字格式码文本**（WPS 会转义）；
> **不能依赖缩进/部件哈希/样式体积**。

**内容**
- 导入：缩进式 与 WBS 编号列 **双解析**（XL-01）+ 列映射向导 ≤3 步（XL-02）；
- 依赖列语法 `编号[FS|SS|FF|SF][±lag]`，分号分隔多前置（XL-03）；
- 导入即接入 G2 内核 → 得到可渲染的 `Schedule`；
- 导出：**规范化 schema 输出**（XL-06 改写）——按 WBS 顺序、规范列序、规范日期格式与依赖语法；
- **删除影子表 `__gantt_meta__`（XL-04 作废）**；可见列必须自足：身份、层级、依赖、日期/工期、进度、里程碑全部可在可见列表达；
- **导入失败的结构化诊断报告**（G-8）：未识别列、缺日期行、依赖语法解析失败、因成环被丢弃的边；
- 边界：不解析公式/条件格式/宏（XL-08）；导出时对 `=`/`+`/`-`/`@` 开头的文本做**公式注入转义**（G-9）；
- CSV 尽力导入（XL-07）。

**出口条件**
- [ ] US-1 的核心：**200 行常见结构 xlsx 导入后 ≤3 秒内得到带依赖连线的任务图**（原文 3 秒口径，现在可测，因为 G2 已存在）；
- [ ] **自往返一致性**：导出 → 重新导入 → 语义等价（这是 T-2 下新的、更弱的往返要求，但必须成立）；
- [ ] 脏文件用例集：合并单元格表头、多行表头、混合层级表达、缺列、日期为公式（扁平化后）——均有明确诊断输出而非崩溃；
- [ ] 导出的文件用 Excel 与 WPS 打开无修复提示。

**注**：CSV 无损不在 v0.1 承诺内。

### G4 纯 SVG 甘特渲染（T-4）

**内容**
- **纯 SVG**（弃 Canvas+SVG 混合）：刻度、条形、进度、里程碑菱形、汇总条、依赖连线（正交路由 + 类型箭头）全部为 SVG；
- 左表右图分屏 + 行内编辑（VW-02）；
- 刻度缩放：日/周/月/季（VW-04）；
- **虚拟滚动（VW-05）+ 裁剪（硬性架构要求）**：
  - **行窗口裁剪**：可见行 + 缓冲行；
  - **边窗口裁剪：必须用「边所跨行区间 ∩ 可见行窗口」求交**——仅按"两端点是否可见"裁剪会错误隐藏跨屏长箭头；
  - **裁剪先于几何计算**；拖拽期不做逐帧 DOM 重建；
- 工程细节：`shape-rendering="crispEdges"` 避免 1px 模糊；缩放用 `vector-effect="non-scaling-stroke"`；交互热区用独立透明 `<path>`；
- **Vue 落地约束（T-1）**：任务集合用 `shallowRef`/`markRaw` 承载，**只对可见窗口 + 受影响子图做响应式**；固定行高（虚拟化前提）；
- 把"裁剪策略"写成 **ADR**（这是纯 SVG 路线唯一的失败模式）。

**出口条件**
- [ ] 1,000 任务**首屏 ≤1s**；
- [ ] **裁剪有效性可测**：1,000 任务下 SVG 元素数与"总任务数"解耦——滚动到任意位置，**渲染的边数只与窗口相关**（给出实测数值）；
- [ ] 滚动 10× 无可见掉帧（记录实测耗时，对照评估报告 §5.4 的 2.0s 反例）；
- [ ] 依赖线正交路由正确、4 类关系箭头可区分；
- [ ] 行内编辑不破坏虚拟化与裁剪（不触发整表重建）。

**可延后**：季刻度（保留日/周/月）、折叠展开动画。

### G5 编辑体验：拖拽三语义 + 撤销重做

**内容**
- 拖拽三语义：改开始 / 改工期 / 整体移动（IX-01）；
- **拖拽期间下游实时跟随**（US-2 的核心）——依赖 G2 的传播内核；
- 违反依赖的拖拽策略（IX-05）：默认吸附到约束边界 + 冲突标记，可切换"允许 + 标红"；
- 拖拽建线（IX-02）+ **检环即时反馈**（G-7：预检即拒绝建边 + 高亮成环路径）；
- 撤销重做：**一次手势 = 一个 Command**（IX-03），Ctrl+Z 一步回退整次连锁变更；
- 性能：拖拽期间只做**受影响子图的日期传播**（非关键编辑 ≤10ms/帧）；松手后合并重算 ≤200ms（IX-04）；必要时移入 Worker。

**出口条件**
- [ ] US-2：任务延期 3 天 → **下游立即跟随、里程碑威胁可见**、松手 ≤200ms 完成重算与冲突标记；
- [ ] 拖拽 ≥30fps（记录实测；不含浮动的传播使该指标可达）;
- [ ] 拖一次手势 → 一次 Ctrl+Z 完整回退整次连锁变更；
- [ ] 建环被拒绝并高亮成环路径；导入的成环边进问题清单。

**注**：关键路径随拖拽变化属 v0.5（分析层延后），US-2 措辞同步去掉该项。

### G6 持久化：自动保存 + 命令回退栈（R-2）

**内容**
- **后端：IndexedDB**（G-6 裁决；不使用 localStorage，2,000 任务会超配额）；
- **L1 命令回退栈（会话内）**：每条 delta，O(变更量)，作为撤销/重做的唯一真相源；
- **L2 检查点快照（低频）**：每 5 分钟 / 每 200 条命令 / 关闭文档时，保留 **2–3 份**（跨会话恢复）；
- **L3 当前状态自动保存 ≤5s**：不做历史；
- 异常退出草稿恢复（PRD-08）；配额超限时降级为"仅保留最近 1 份检查点"并提示；
- 多标签页并发写冲突的基础防护（如按文档 id 的写锁或最后写入告警）。

**出口条件**
- [ ] 自动保存 ≤5s，且**拖拽期间不产生可见掉帧**（这是回退栈相对全量快照的主要收益，需实测证明）；
- [ ] 会话内可逐步撤销 ≥50 步；LIFO 语义正确；
- [ ] 强制杀进程后重开可恢复至最近检查点；
- [ ] 2,000 任务文档的存储占用与写入耗时被实测记录（验证 R-2 的收益）。

**同步改写**：PS-02、US-5 措辞 → "命令级撤销/重做 + 低频检查点恢复（会话内逐步撤销；跨会话恢复至最近检查点）"。

### G7 导出：SVG → PNG → PPTX 模板 A

**内容**
- **双投影**：`RenderProjection` + `ExportProjection` 共享几何（原文 §7.2 铁律 #2）；
- SVG 导出（语义化，EX-01）→ PNG（多倍率，EX-02）→ **PPTX 模板 A**（EX-03/EX-06）；
- 单位统一：像素 → 英寸 → EMU 仿射变换；页面 16:9 可配（EX-04；A4 可延后）；
- **PPTX 原生形状（EX-03，已核验 pptxgenjs 不支持 connector/group）**：
  - 低风险、可直接支持：任务条 = 圆角矩形、里程碑 = 菱形 preset；
  - **需自研 OOXML 补丁引擎**：connector（`<p:cxnSp>` + `stCxn/endCxn` 吸附）、group（`<p:grpSp>` + `off/ext` 与 `chOff/chExt` 坐标换算）；
  - 管道：`pptx.write({outputType:'uint8array'})` → JSZip → 重写 `ppt/slides/slideN.xml` → 重新打包；`shapeName` → `id = idx+2` 映射；断言无 id 重复且 `idx` < 目标连接点数量；
  - **永不退化为位图**；connector 异常时降级为折线 `custGeom`（**走线直接取自 SVG 的 path 端点，保证降级后视觉差异最小**——这是 T-4 的收益）；
- 模板 A 内容：单页总览 = 甘特 + 图例 + 自动摘要（完成率 / 里程碑数 / **里程碑清单**）。原文的"关键节点表"依赖分析层，**降级为里程碑清单**（T-3）。
- 兼容矩阵：**WPS 必过**；**Microsoft PowerPoint 备查（不承诺、不阻塞）**——依 [G0-S 的验证环境口径](#g0-s-三项证伪实验详见-证伪实验计划)；Keynote 明确不保证（Apple 官方已证连接线降级为直线）。

**出口条件**
- [ ] SVG 与 PNG 导出与屏幕所见一致（**几何同源**，非截屏）；
- [ ] WPS 打开**无修复弹窗**；任务条/里程碑为原生形状；
- [ ] WPS 中拖动任务条，**connector 端点跟随**（S1 门禁 G1-a 的产品化验证；S1 已在实验件上验证通过，此处验证产品导出物）；
- [ ] group 坐标正确（父子分组无偏移、无修复弹窗）；
- [ ] 模板 A 可重复生成：同一文档两次导出结构一致（golden 文件比对）。
- [ ] **备查（不作为门禁）**：记录 Microsoft PowerPoint 2016/365 的打开与拖动结果，并据此写入 README 已知限制；
      **不得**在未经该验证前对外承诺 PowerPoint 下的跟随行为。

**可延后**：模板 B/C、主题跟随（P1-05）、A4 页面。

## 六、v0.1 完成定义（DoD 汇总）

**一句话**：把一个常见结构的 Excel 计划拖进网页，**3 秒内看到带依赖连线的甘特图**，拖动任务条时**下游跟着动**且一步 Ctrl+Z 可整体回退，然后**导出一份图形原生可编辑的 PPTX**；全程断网可用，数据存在本地。

**必须同时成立**
1. `packages/engine`、`xlsx-protocol`、`pptx-renderer` 三包零 DOM/框架依赖，CI 全绿为合并门槛；
2. 排程与 xlsx 协议有**独立验证手段**（不变量测试 + 手工用例 + 差分测试），不依赖外部商业工具；
3. 1000 任务下渲染与传播性能达标，且**裁剪有效性可测**；
4. PPTX 为原生形状（**永不为位图**），兼容性结论**有真机证据**（**真机 = WPS**；Microsoft PowerPoint 备查、不阻塞）；
5. 所有已知限制（**PowerPoint 未验证**、Keynote、MSP 互操作、规模上限、导出不做格式保留）**写入 README**。

**不构成 v0.1 阻塞**：模板 B/C、关键路径、浮动、基线、筛选分组、云同步、飞书。
