## 一、排序原则

1. **证伪优先**：最可能推翻产品假设的未知项先做（1–3 天，**不写产品代码**）。
2. **内核先行、分析层延后**（T-3）：日期传播内核是**几何来源**，必须早做；CPM 分析层全局耦合、不支撑卖点。
3. **一条主链路走通胜过五条半成品**：按能否让「导入 → 出图 → 拖动 → 导出」闭环排序，而非按模块重要性。
4. **导出后置**：SVG/PPTX 依赖渲染几何与排程结果，必须在 G4/G2 之后。
5. **护栏先于功能**：测试框架与 CI 是"正确性关键模块"的准入门槛。

## 四、每块的「延后规则」（替代原文降级序列）

排序本身即降级策略：**任何一块做不下去，其后的导出类工作整体后移，而主链路（导入 → 出图 → 拖动）保持可用**。

| 若此块受阻 | 延后动作 | 首版仍保留的卖点 |
|---|---|---|
| S1 判定 connector 不可交付 | EX-03 删除"拖动跟随"，改折线降级 + README 声明 | 原生可编辑形状仍在（可改色/挪位），优于贴图 |
| G1.1 序号化日历受阻 | G2 退回逐日循环日历且无 `exceptions`（接受约 340× 常数差），全量重算的 **DoD（p50 ≤ 1 ms / p99 ≤ 2 ms）退回 100 ms 天花板**，日历例外延后 | 传播语义与 4 类关系完整，规模承诺不变 |
| G1.2 文档 schema 受阻 | **不可延后**——它是 G3/G4/G6 与命令层的公共输入 | 无（必须先解决） |
| G1.3 命令层受阻 | G6 先只上"全量状态检查点 + 单向编辑"，撤销/重做在 G6 内补齐 | 自动保存与跨会话恢复仍在，US-5 收窄 |
| G2 传播内核遇到语义困难 | 不可延后——这是首版卖点本体；只允许按**收窄顺序**降级：① 4 类关系 → 仅 FS；② lag → 仅 0；③ 锚点规则退化为"全任务锚定"（[ADR 0004](../02-adr/0004-排程契约.md) §2 的备选 A）。**每级降级都是契约变更**（追加 ADR 并同步 README） | "下游跟着动"仍在（仅关系类型 / lag 减少） |
| G3 配置向导超预期 | 向导降到"自动识别 + 手工兜底"两步（协议层见 ADR 0006 §1/§7） | 导入仍可用 |
| G4 裁剪未达标 | 规模上限暂时下调至 500 任务并明确声明（**触发点与判据来源见 [G4-S（依据）](../00-baseline/证伪实验计划.md) 的 `S4-a`**；**只影响规模声明，不改纯 SVG 路线**）。**当前未触发**（实测见 [归档细则 G4–G5](首版-记录-归档-G4-G5.md)） | 功能完整，规模声明诚实 |
| G5 拖拽性能不足 | 拖拽期只更新被拖条 + 松手后传播（牺牲"实时跟随"的丝滑度） | 传播语义与撤销仍完整 |
| G6 检查点机制受阻 | L1 回退栈先上，跨会话恢复降级为"仅最近状态" | 撤销完整，US-5 收窄 |
| G7 PPTX 受阻 | 先交付 SVG/PNG，PPTX 单独发布 | 导出能力部分可用 |

## 六、v0.1 完成定义（DoD 汇总）

**一句话**：把一个常见结构的 Excel 计划拖进网页，**3 秒内看到带依赖连线的甘特图**，拖动任务条时**下游跟着动**且一步 Ctrl+Z 可整体回退，然后**导出一份图形原生可编辑的 PPTX**；全程断网可用，数据存在本地。

**必须同时成立**
1. `packages/engine`、`xlsx-protocol`、`pptx-renderer` 三包零 DOM/框架依赖，CI 全绿为合并门槛；
2. 排程与 xlsx 协议有**独立验证手段**（不变量测试 + 手工用例 + 差分测试），不依赖外部商业工具；
3. 1000 任务下渲染与传播性能达标，且**裁剪有效性可测**；
4. PPTX 为原生形状（**永不为位图**），兼容性结论**有真机证据**（**真机 = WPS**；Microsoft PowerPoint 备查、不阻塞）；
5. 所有已知限制（**PowerPoint 未验证**、Keynote、MSP 互操作、规模上限、导出不做格式保留）**写入 README**。

**不构成 v0.1 阻塞**：模板 B/C、关键路径、浮动、基线、筛选分组、云同步、飞书。
