| 件 | 位置 | 作用 |

**只判一个方向**：规范点名的符号 ⊆ 包入口（`packages/<pkg>/src/index.ts`）的导出面。
反向（哪些导出进"发布承诺"）**不在本检查**——`render-core` 有 302 个导出名，逐条要求文档化只会制造噪声；
那是 **P4-b 的公开面分类**。

### 2. 负向对照（新检查在现状上必须翻红）

在**未加 `allow`** 的现状上运行，恰好 **1 条 error**：

```
error [API] xlsx-protocol ← packages/xlsx-protocol/PROTOCOL.md ## 二、公共 API 点名了 `XlsxInput`（type），
      但 packages/xlsx-protocol/src/index.ts 不导出它（packages/xlsx-protocol/PROTOCOL.md:33）
```

这一条与 [06 §C2](06-批次记录-P3.md) 登记的观察**逐字一致**（"消费者能传值、叫不出类型名"）⇒ 判定面没有虚设。
其余 **88 个被点名的符号**（engine 77 / render-core 1 / xlsx-protocol 9 / pptx-renderer 1）全部命中入口导出面。

四条防静默失效的负向对照（selftest 逐条钉住）：段标题找不到 ⇒ 报"登记表已腐烂"；候选数掉到 `minCandidates`
以下 ⇒ 报"提取面塌了"；入口解析不出任何导出 ⇒ 报"解析器与写法已分叉"；`allow` 缺 `reason` ⇒ 报错。

**提取面是实测调出来的**（三次假阳都被钉进了用例）：① 行注释里的 `// max(ef)` 会把 `max` 当符号
（`SCHEDULE.md` §三）⇒ 先剥行注释；② 子节是"用法示例"，`PROTOCOL.md` §2.1 的 `applyCommand` 属 `engine`
⇒ 段范围截到下一个标题（子节不算）；③ 模块表列的是**文件名**（`manifest.ts`）⇒ 表格模式只认"首格由反引号
符号起头"的形态。

   （后者是当时的另一套计数），**不据此判分叉**；P4-b 做分类时以自己的判据为准。
