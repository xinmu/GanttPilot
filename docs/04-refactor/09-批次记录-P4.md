### 2. 负向对照（新检查在现状上必须翻红）

在**未加 `allow`** 的现状上运行，恰好 **1 条 error**：

```
error [API] xlsx-protocol ← packages/xlsx-protocol/PROTOCOL.md ## 二、公共 API 点名了 `XlsxInput`（type），
      但 packages/xlsx-protocol/src/index.ts 不导出它（packages/xlsx-protocol/PROTOCOL.md:33）
```

这一条与 [06 §C2](06-批次记录-P3.md) 登记的观察**逐字一致**（"消费者能传值、叫不出类型名"）⇒ 判定面没有虚设。
其余 **88 个被点名的符号**（engine 77 / render-core 1 / xlsx-protocol 9 / pptx-renderer 1）全部命中入口导出面。

四条防静默失效的负向对照（selftest 逐条钉住）：段标题找不到 ⇒ 报"登记表已腐烂"；候选数掉到 `minCandidates`
以下 ⇒ 报"提取面塌了"；入口解析不出任何导出 ⇒ 报"解析器与写法已分叉"；`allow` 缺 `reason` ⇒ 报错。

**提取面是实测调出来的**（三次假阳都被钉进了用例）：① 行注释里的 `// max(ef)` 会把 `max` 当符号
（`SCHEDULE.md` §三）⇒ 先剥行注释；② 子节是"用法示例"，`PROTOCOL.md` §2.1 的 `applyCommand` 属 `engine`
⇒ 段范围截到下一个标题（子节不算）；③ 模块表列的是**文件名**（`manifest.ts`）⇒ 表格模式只认"首格由反引号
符号起头"的形态。

## P4-f 精简层结构复核（维护者插入批，先于 P4-b…e）

### 1. 触发与做法

触发：P4-a 收口时实测 **精简层 495.8/500 KB**（余量 4.2 KB），而 P4-b/c 还要往 L1 文档里加内容。

## P4-b 公开 API 面的完整分类 + `N13` 路径标签同步

### 1. 判据（不手工维护分类表）

按计划的措辞"每个符号**要么被 L1 规范点名、要么只有仓内消费点**"，把它做成**可重算**的五分类
（规则进 [DOC-SPEC §4.8](../DOC-SPEC.md)，实现在 `check-api-surface.mjs` 的 `classifyPublicSurface`）：

| 类 | 判据 |
|---|---|
| **发布承诺** | 在 L1 文档的 **API 段**里被点名（= P4-a 的提取面） |
| **内部·跨界** | 未点名，但被别的包 / `apps/web` / `scripts` import |
| **内部·仓内** | 未点名，只在**自己包内**（含 spec）被 import |
| **结构性** | 无 import，但在仓内被引用（类型位置、常量表、文档） |
| **零引用** | 全仓既无 import 也无提及 ⇒ **error** |

**为什么不落一张 605 行的手工分类表**：反重复规则 1（同一事实只留一处权威陈述）——表会腐烂，
而判据可重算。故 `pnpm docs:check` 每次打印计数，**只有"零引用"判红**（它就是"不新增零引用导出"的可执行形式）。

### 4. C1 的遗留：`measure-render` 与 `smoke-build` 的公共基建要不要合并

C1 当年只抽了公共基建（`cdp.mjs` / `paths.mjs`），把"是否合并"留给 P4 在**证据重取之后**评。现在评：

- **两者是两层**：`smoke-build.mjs`（含 `--file`）是**门禁断言**（进 `pnpm gate`，判三条主链路 + DOM 互证）；
  `offline-artifact-probe.mjs` 是**记录制探针**（不进 gate，回答 P-49 §3 的四问并写 environment+数字+口径+raw）。
- 重取时两者**都在跑**（P4-d），输出形状**本来就该不同**（前者 exit code + 断言，后者证据文件）。
- **结论：不合并**（维持 C1 时写的"分工是刻意的，不要合并"），**新的判据**是"合并会让门禁多出
  Chrome + IndexedDB 的依赖，而那条依赖正是记录制要单独承担的东西"。
