### §一.1 N1 多标签写保护的"未来实现"要点

**问题**：`PERSISTENCE.md` 的不变量④与内存适配器注释承诺"`writerId` 不同且更新 ⇒ 返回
`PERSIST_BLOCKED_BY_OTHER_TAB` 且不覆盖"；但 `apps/web/src/persistence/idb.ts` 的 `saveLatest` 是**裸 `put`**，
该失败码在正常浏览器路径**不可达**（只有降级到内存适配器时才生效）。

**本轮动作**：**只改文档与注释**（目标措辞见 [基线与决策](01-基线与决策.md) §四(a)），
并订正注释里"更旧/更新"写反的方向。

**未来实现的要点（供 v0.5 直接接手）**：
- 判据是 `existing.writerId !== record.writerId && existing.updatedAtMs > record.updatedAtMs`（与内存适配器同口径）；
- 需要一次 `get` 再 `put` 的读改写，注意 IndexedDB 事务边界（现有 `withStore` 每操作开一个事务）；
- 需要一条浏览器侧判据（`smoke:build` 或记录制探针），因为这条路径**目前没有任何自动化覆盖**；
- 实现后要把 `PERSISTENCE.md` 的限定措辞改回"两条路径都成立"。

### §一.2 N2 PPTX 进度条内缩的"未来实现"要点

**问题**：`PPTX.md` 写"高内缩 2 px"，实现（`template.ts` 的 `progressEmu`）在 **EMU** 上做 `y+1`/`cy-2`
（1 EMU ≈ 1/9525 px，实际无可见内缩），而 SVG 孪生实现用 px。

**本轮动作**：在 `PPTX.md` 里**如实描述**当前行为 + 标注"与 SVG 不一致，归 v0.5 统一"；不修代码。

**未来实现的要点**：把 px 换算成 EMU（`ptToEmu`/`EMU_PER_PX` 一族已在 `units.ts`），
换算后**必然改变 PPTX golden 字节数** ⇒ 需要一次 golden 重取并登记。

## 二、N3：CI 补两步（决策 6 = 现在不做，纳入计划）

**实测依据**（决定"能不能补"）：`scripts/bundle-offline.mjs` 只 import
`node:child_process` / `node:fs` / `node:path` / `node:url`，全文 **0 次** `chrome`；
`scripts/check-docs.mjs` 只 import `node:fs` / `node:path` / `node:url`。
⇒ 这两步**不需要 Chrome**，与 `smoke:build` / `smoke:build:file` 不同。

**要做的动作**：在 `.github/workflows/ci.yml` 的 `Build → Typecheck → Test` 之后、
`License audit` 前后，加 `pnpm bundle:offline` 与 `pnpm docs:check` 两步，并更新文件头的
"这里只跑不依赖无头 Chrome 的那几步"注释（现在它把 `bundle:offline` 与 `docs:check` 一并归入被排除项）。

**为什么值得**：`docs:check` 是九步里**最便宜**的一步，却是 63 份文档**唯一**的自动守卫；
而它缺席的代价已经显现——**23 处引用已删的 spike 目录、其中 12 处不在白名单内，门禁仍然是绿的**。

**同时登记**：`ci.yml` 的文件头注释应改为"哪些步没有、为什么"的**显式**清单；
`smoke:build` / `smoke:build:file` 是否可补（`ubuntu-latest` 自带 Chrome，且脚本已支持
`GANTTPILOT_CHROME`）**标记为未验证**，不在此批决定。

## 三、N4 / N5：两项只读验证（决策 7 = 现在不做，纳入计划）

### §三.1 N4 悬停行带的非 0 滚动验证（进 C5 批）

**可以现在就确定的**：`ADR 0007 §16.3` 的标题就是一条自定规则——"**凡坐标换算类判据，
至少取一个非 0 滚动位置**"，并用它约束了几何不变量、手势、记录制三层；而 `hover-band` 的用例
（`packages/render-core/src/clipping.spec.ts`）**只在 `scrollLeft = 0` 上断言**（连它的负向对照也写 `scrollLeft: 0`）。
⇒ **规则未被执行，这是确定的缺口**，与"偏移是否真的存在"无关。

**未定的**：`hover-band` 在窗口坐标下取 `x = 0`，而 `GanttChart.vue` 把它渲染在按 `−scrollLeft` 平移的内容组里；
按 `clipping.spec.ts` 的口径它应落在屏幕的 `−scrollLeft`。这与 `smoke-build.mjs`（在门禁内、当前绿）
"右滚后行带仍铺满"的断言看起来矛盾。

**因此 C5 的动作**：给该用例补一个 `scrollLeft = 600` 的视图，断言行带的**窗口 x** 与内容组平移后
落在同一屏幕位置。
- 若**绿** ⇒ 缺口关闭，把这条补进 `SPEC.md` 的验证矩阵；
- 若**红** ⇒ **停止该批**，把它升级为"行为变更"，按不变量 1 走单独裁决（并检查 `smoke-build` 为什么没抓到）。

### §三.2 N5 spike 删除影响面清单（进 D9 批）

## 六、风险与回滚

| 风险 | 触发条件 | 处置 |
|---|---|---|
| **文档拆分导致锚点静默失效** | 重命名/拆分文件后，不带锚点的引用会静默落到文件顶部 | 拆分动作**必须与引用修改在同一批**；`check-docs` 的"细则列必须带锚点"只保护台账，正文链接靠批内自查 |
| **拆分改变产物字节** | 拆 `template.ts` 后 PPTX golden 变化 | **视为动了输出 ⇒ 回退重做**（拆分不应影响产物）。若确认是必需变化，按行为变更走裁决 |
| **常量单点化改变行为** | 声明处与副本的值本就不一致 | 单点化**之前**先确认"哪一份是权威"（尤其 `assertWorkDays` 的两份已语义分叉、`sidebar` 类数值），不一致的进 [§四] 待裁决，不硬并 |
| **承重判据翻红被误当"重构噪声"** | `c₃`/元素预算/性能判据变红 | **不许放宽数值**（`P-38` 纪律）：动作是隔离并行度或修实现。若确认是实现回归，回退该批 |
| **记录制证据被反复作废** | 零散改动影响 `c₃`/golden | 按 [验收与门禁](04-验收与门禁.md) §四"同批次集中重取" |
| **CI 弱于本地门禁造成"远端绿=安全"的错觉** | 只依赖 CI | 合流前的稳定判定必须包含**一次本地九步全绿**，且明确 CI 只跑 6 步 |
| **本计划自身变成新的文档负担** | 计划写完就没人读 | 入口 ≤ 6 KB、按需注入（见 [入口](README.md) §一）；合流后按 §七 收口 |

**回滚**：所有批次都在 `refactor/v0.2` 上、**一批一提交**（决策 1）⇒ 回滚粒度就是提交粒度。
不改写已推送的历史（若将来推送），用 `git revert`。
