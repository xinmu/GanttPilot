**4. 为什么许可清单**写死**，而不从 `package.json` 推导**

推导会让规则**自动跟随**最危险的那一步：把 `@ganttpilot/render-core` 加进 `engine` 的 `dependencies`、再 import 它，就成了合法代码。
因此契约与事实**分开**、各守一半：

- `pnpm lint` 守**代码 ⊆ 契约**（"我声明了、我也 import 了"仍会被拦——方向是裁决，不是声明）；
- `boundary.spec.ts` 守**声明 ⊆ 契约**（契约不许比事实更窄：有人加了真实的跨包依赖却忘了改清单，会在这里得到一句指明去哪改的失败信息）；
- 外加**每个目录都已登记**（新包不能整块绕开方向规则）。

**5. 有意排除的一项**：**自我引用**（`packages/engine` 里 `import ... from '@ganttpilot/engine'`）**不在**方向契约内——它不是依赖边，
拦它属于另一类判定（自引用会经 `exports` 解析到自己的 `dist`）。此排除写在 `eslint-rules.mjs` 的注释里，避免被读成疏漏。

`pnpm build` / `pnpm typecheck` / `pnpm smoke:build` 与 `pnpm gate` 九步全绿。

**1. 为什么是"转 spec"而不是"加门禁步"**

`chrome-harness.mjs` 守的是**不可逆**动作（收尾无头 Chrome 时不许按名字杀进程），
而它的回归测试原先是一份**独立脚本**：只有记得手动跑才会执行（P3 立项时登记为"不在门禁里"）。
加一步要改 `STEPS`——那是**门禁契约**：按 [ADR 0001 §门禁](../02-adr/0001-本地质量门禁与零框架依赖护栏.md)
必须同步 ADR 与 `.github/workflows/ci.yml`，而"九步"在活文档与 CI 里都有名字。
转成 spec 则**零契约变更**：`test` 步的覆盖面变大（本地与 CI 一起受益），断言有名字，失败能定位到具体一条。

**2. 转换的三处口径变化**

| 处 | 变化与理由 |
|---|---|
| `scripts/chrome-harness.selftest.mjs` → `scripts/chrome-harness.spec.mjs` | 39 项 `check(...)` 变成 **18 个 `it`**（同一条判据的多个断言合并成一个用例，失败时仍能一眼看出是哪条闸）；`vitest.config.ts` 的 `include` 加 `scripts/**/*.spec.mjs` |
| "命令行含本文件名"的断言 | 转成 spec 后测试跑在 **vitest 的 worker** 里，该进程的命令行属于 vitest、不含 spec 文件名 ⇒ 断言改为"**同步**返回 `string` 且非空"（这才是它真正守的东西） |
| 超时 | 两处显式给 `20_000` / `30_000`：用例里有两段 800 ms 的等待与 `powershell.exe` / `ps` 调用，默认 5 s 会偶发假红 |

**3. 负向对照**（这一条**先证明了我的转换有毛病**，值得记下来）

把 `psCommandLine` 改成 `async`（正是它注释里说的那次真实回归：一旦返回 Promise，闸会判定"不是字符串"
⇒ 每次都拒绝动手 ⇒ 无人收尾）：

| 版本 | 结果 |
|---|---|
| 我第一版转换（`const selfCmd = await psCommandLine(...)` 再断言 `typeof`） | **18 例全绿**——`await` 会把 Promise 拆开，`typeof` 仍然是 `string` ⇒ **断言其实没牙**（原文那份独立脚本也是这么写的：同一个洞） |
| 改后（**不 `await`**，直接 `typeof psCommandLine(...)`） | **1 例红**：`expected 'object' to be 'string'` ✓ |

**4. 实测**

`npx vitest run scripts/chrome-harness.spec.mjs`：**18 例全绿 / 3.8 s**（不需要 Chrome，但需要能读命令行：
Windows 用 `CIM`、其余平台用 `ps`）；`pnpm test` 从 **56 文件 / 828 例**变成 **57 文件 / 846 例**（只增不减）；
门禁九步与 `STEPS` **一字未动**。

### C7-g 记录（**`tmp/` 回收 + `.gitignore` 的注释与规则对齐**）

**1. `tmp/` profile 回收：为什么"按年龄"、为什么挂在 `ensureProfileDir` 上**

`chrome-harness` 每次运行都新建带时间戳的 profile 且从不回收（C7 立项时 802 MB，写到这一批时 **1,181.7 MB / 26,259 文件**）。
新增 `pruneStaleProfiles({ root, now, olderThanMs })`（默认窗口 **24 h**），清理点选在 **`ensureProfileDir`**——
它是所有拉起路径的唯一入口（`scripts/cdp.mjs` 的 `spawnChrome` 是唯一调用方），因此不会有"某条链忘了清"的破口。

- **按年龄而不是"清光兄弟"**：并行的两条链（两个终端、或测量与冒烟同时跑）各自的 profile 都是"新"的；年龄窗口只回收没人再用的那些；
- **只认时间戳目录**：`tmp/<白名单根>/<全数字>` 之外的任何东西（手放草稿、半成品）一律不碰；
- **失败不致命**：并发删除 / 文件占用只跳过（清理不是判据，不该让任何一步红）；
- `now`/`olderThanMs`/`root` 可注入 ⇒ 自检能在**造出来的小树**上确定性地判"超期的走、未超期的留"，不去碰真实的那 1 GB。

**2. 实测回收**（默认窗口，真实 `tmp/`）

| 时刻 | `smoke-profile` | `measure-chrome-profile` | `ui-shot-profile` | `batch-c-profile` | `tmp/` 合计 |
|---|---|---|---|---|---|
| 回收前 | 362.9 MB | 619.1 MB | 23.2 MB | 125.9 MB | **1,181.7 MB / 26,259 文件** |
| 回收后 | 0 | 376.9 MB | 0 | 0 | **427.6 MB / 7,765 文件** |

⇒ 一次调用回收 **60 个 profile / ≈754 MB / 18,494 文件，耗时 1,980 ms**。
`measure-chrome-profile` 剩下的 376.9 MB 是 **24 h 以内**的（设计如此：窗口保护并行的链），下次运行自然回收。
**负向对照**：把年龄判据去掉（清理变成清光）⇒ 两条用例红（`expected [ 'smoke-profile/1000', …(1) ] to strictly equal [ 'smoke-profile/1000' ]`）。

**3. `.gitignore`：注释与规则不一致本身就是缺陷**

原文件里只有 spike 段的一句注释说"生成的 pptx 不入库"，却**没有任何 `*.pptx` / `*.xlsx` 规则**（实测：
`git ls-files '*.pptx' '*.xlsx'` 为空 ⇒ 从来没真发生入库，只是没有任何东西**拦得住**它）。补齐两条规则、
把 spike 段那句注释改成指回规则，并写明逃生口：**确需入库的手写样例要显式 `git add -f` 并在同目录留一行说明**
（否则"被静默忽略"会变成下一个坑）。
