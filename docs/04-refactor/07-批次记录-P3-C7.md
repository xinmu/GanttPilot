**2. 三处实测发现的假绿**（探针 `tmp/probe-direction-rule.mjs`，用完即删）

| # | 处 | 实测（改动前） | 为什么算假绿 |
|---|---|---|---|
| ① | **工作区依赖根本没有规则** | `packages/engine` 里 `import { routeEdge } from '@ganttpilot/render-core'` ⇒ **`pnpm lint` 零报错**（子路径 `@ganttpilot/render-core/align` 同样零报错；构建也照过） | ADR 0008 §1 把方向冻结成 `engine ← render-core ← xlsx-protocol`，§3 要求"不靠人记"，但落下的只是 `render-core` 自己那份**文本扫描**（只看得见本包、只看得见字面量）⇒ "engine 不得依赖 render-core"确实只是口头约定 |
| ② | **两个包的夹具无人加载** | `xlsx-protocol` / `pptx-renderer` 的 `lint-boundary/*.fixture.ts` **没有任何文件读它们**（夹具被 ESLint 全局忽略，而这两包没有 `boundary.spec.ts`） | `CONTRIBUTING` 写的是"每个计算层包都要放一组故意违规的夹具，否则'受铁律约束'只是口头约定"——夹具在、**加载它的自检不在**，等于没放 |
| ③ | **框架的子路径声明是空转的** | `FORBIDDEN_FRAMEWORKS` 里明明有 `'vue/*'`、`'@vue/*'`，但 `import 'vue/dist/vue.esm-bundler.js'` ⇒ **零报错** | 原规则用 `paths`（**字面名称全等**），glob 条目永不命中 ⇒ 声明面比实际面大，与 C6-g 收窄 `HighlightSet.styleKey` 是同一类问题（留着永不出现的取值/永不平配的模式） |

③ 的修法：改用语义等价的 `patterns`（gitignore 语义的 glob 组）。`FORBIDDEN_FRAMEWORKS` 的**取值与文案一字未改**——它终于真的生效了。

**4. 为什么许可清单**写死**，而不从 `package.json` 推导**

推导会让规则**自动跟随**最危险的那一步：把 `@ganttpilot/render-core` 加进 `engine` 的 `dependencies`、再 import 它，就成了合法代码。
因此契约与事实**分开**、各守一半：

- `pnpm lint` 守**代码 ⊆ 契约**（"我声明了、我也 import 了"仍会被拦——方向是裁决，不是声明）；
- `boundary.spec.ts` 守**声明 ⊆ 契约**（契约不许比事实更窄：有人加了真实的跨包依赖却忘了改清单，会在这里得到一句指明去哪改的失败信息）；
- 外加**每个目录都已登记**（新包不能整块绕开方向规则）。

**5. 有意排除的一项**：**自我引用**（`packages/engine` 里 `import ... from '@ganttpilot/engine'`）**不在**方向契约内——它不是依赖边，
拦它属于另一类判定（自引用会经 `exports` 解析到自己的 `dist`）。此排除写在 `eslint-rules.mjs` 的注释里，避免被读成疏漏。

（C6-g 是 820 例：`packages/engine/src/boundary.spec.ts` **7 → 14**、`packages/render-core/src/boundary.spec.ts` **6 → 7**，合计 +8）；

**1. 落成的东西**

| 处 | 内容 |
|---|---|
| `packages/engine/tsconfig.check.json` | 改为 `extends ../../tsconfig.base.json`（**不再 extend 构建项目**）+ `include: ["src/**/*.ts", "test/**/*.ts"]` + `types: ["node"]` + `allowJs` ⇒ **spec 与测试侧参照实现都进了 tsc 程序**。两条链共用 base 的 strict 开关，各自只管自己那半边 |
