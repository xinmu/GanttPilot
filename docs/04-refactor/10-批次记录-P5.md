### 2. 验收（实测，不是"看着对"）

| 判据 | 手段 | 结果 |
|---|---|---|
| `ci.yml` 仍是合法 YAML | `yaml.safe_load`（PyYAML 6.0.3，本机） | ✅ 解析通过，`jobs.gate.steps` 共 9 个 `run` |
| 步骤**相对顺序**是 `STEPS` 的子序列 | 一次性探针 `tmp/p5b-ci-consistency.py`（用完即删）：从 `ci.yml` 取 `pnpm <step>`、从 `gate.mjs` 正则取 `STEPS` 名，逐项比对 | ✅ 子序列成立；**多出的步 0 个**；缺的恰好 `['smoke:build', 'smoke:build:file']` |
| 两步本身在现状上能过 | `pnpm bundle:offline` / `pnpm docs:check` 各自单跑 | ✅ 均 `exit 0`（`bundle:offline` 顺带报"形状判据通过：单文件 1594.5 KB"） |
| 文档侧 | `docs:check` 12 类全绿 | ✅ `exit 0`、警告 0 |

**探针的第一版是假红，如实记下**：它把 `pnpm install --frozen-lockfile` 也当成一个门禁步
⇒ 报"多出的步 1 个、顺序不是子序列"。核对 `scripts/gate.mjs` 后确认 `STEPS` 里**没有** install
（安装是前置动作，只有文件头把它与九步并列叙述）⇒ 探针补一条**显式分类**（打印"前置动作，不计数"），
而不是把判据放宽成"缺的步 ⊆ 某个集合"。改完才 PASS——**先分清"判据错"与"实现错"**。

### 4. 两个生成物**互相影响体量**（`docs:index` 一次跑不到不动点）

**(a) 现象**：这一批第一次生成后，`docs:check` 报
`error [生成物] docs/01-roadmap/首版-文档索引.md 与它的来源不一致（陈旧）`。

**(b) 根因**：`首版-文档索引` 的「合计」与**它自己那一行**都按**盘上**体量算（C8-d 已治过这层自指）；
但**还有一个更外层的自指源**：`轮次导读` 新增一行（R55）会改变**它自己的体量**，而那个体量也在索引的合计里。
`pnpm docs:index` 的顺序是 `make-doc-index.mjs && make-round-index.mjs` ⇒ **轮次导读写完的瞬间，索引就陈旧了**。
实测：**连跑两次**后两个生成物都稳定（第二次数字与第一次相同），门禁转绿。

**(c) 处置**：本轮**先记清读数**（不把"记得跑两次"写进纪律）；**修法是把顺序倒过来**（轮次导读先、索引后——
前者只扫盘与台账、不读索引，后者自指但内部已迭代到不动点）⇒ **与第 23 项同批**（同一族：让工具链自洽，
而不是靠人记得多跑一次）。已登记为 [05 §四](05-登记与本轮不做.md) **第 24 项**。

**(d) 顺带一条**：这条陈旧**正是 [`P-61`](05-登记与本轮不做.md) 那条守卫当场抓到的**——它报的原文就是
"跑 `pnpm docs:index` 重新生成，并把结果一起提交"。**新守卫生效的第一天就抓到了一次真实的静默分叉。**
