# 验收与门禁

> 本文件回答**「这一步算不算做完」**。它同时是 P1（建检查）的设计书、各阶段的验收标准、
> 以及"合流主干"的稳定定义。判定口径的来源是各阶段文档，不在此复述。

## 一、阶段 P1：三条新检查（**先于改内容**）

**为什么先做**：本轮的核心风险是"改完之后再次分叉"。所以先把"分叉"变成**会失败的断言**，
再改内容——这与仓库既有风格一致（`ADR 0001` 的铁律都是可执行检查，而不是口头约定）。

### 检查 1：契约常量单点声明
- **机制**：在 `docs/doc-index.json` 里登记一张"常量 → 唯一声明处"的表（`constantCheck`：`c₃` 逐档位锚值、
  `ELEMENT_MODEL_G5` 的 `overlay`、`EXPORT_TICK_LENGTH_PX`、`HEADER_HEIGHT_PX`、性能阈值 `1 ms`/`2 ms`、
  诊断码表条目数、轴/条色值等）；由 `scripts/check-constants.mjs` 扫描
  **L1 文档 + `packages/**` + `apps/**` + `scripts/**`**，在**非声明处**发现同一字面量即报错
  （值不同还标出"错值"，值相同标"重复陈述"）。
- **为什么必须有**：这是唯一能拦住 [基线与决策](01-基线与决策.md) §五里那类分叉的机制。
  现有 809 例测试**结构上抓不到**它（CONTRIBUTING 自己写过"三处都各自自洽时没有任何单测会抓到"）。
- **负向对照（必须有牙）**：在现状上运行必须**翻红**，并列出：

  | 期望被点名的位置 | 期望被判定的错值 |
  |---|---|
  | `docs/02-adr/0007-渲染几何与裁剪契约.md` | `116 / 70 / 89` |
  | `docs/02-adr/0008-列身份所有权与拖拽交互契约.md` | `6 · rows + 12` |
  | `docs/00-baseline/裁决记录.md`（P-32 结论列） | `c₄ = 3·rows + 12` |
  | `packages/render-core/src/count.ts` | `3·rows + 12`、`每帧固定 12` |
  | `packages/render-core/SPEC.md` | `114 / 69 / 88` |
  | `scripts/measure-render.mjs` | `120 / 88 / 93` |
  | `apps/web/src/components/GanttChart.vue` | `TICK_LENGTH_PX = 6`、`EDGE_STUB_PX` 的 8、`#7a8699`/`#2e75b6` |
  | `apps/web/src/components/TaskTable.vue` | `#cfe3fa` |
  | `packages/render-core/src/svgExport.ts` | `COLOR` 表里与 `manifest.ts` 重复的 5 个色值 |

### 检查 2：精简层预算 + 入口封闭性
- **机制**：`doc-index.json` 增加 `layer: slim|archive`（每份文档一条）与 `contextBudget`
  （`slimKb: 100`、`mustReadKb: 25`、`entryCapKb: 6`、`entry: docs/README.md`）；判定落在
  `check-docs.mjs` 的「分层预算与入口封闭性」：
  （a）`sum(KB of layer==slim 且 非 userFacing 且 非 budgetExempt) ≤ slimKb`，超预算时**列出最大的若干份**
  （不是只报一个总数）；`mustRead: true` 的三份（台账 + 当前规划 + 待定清单）另按 `mustReadKb` 判；
  （b）**解析 `docs/README.md` 的全部链接，断言目标都属于 `slim`**——文件链接必须"已登记且 slim"，
  目录链接要求目录下**已登记**的文档全为 slim（目录下未登记的 .md 只警告：evidence 一类存量的分层登记属 P2）；
  另加 `userFacing`（用户手册）与 `budgetExempt`（v0.2 临时施工计划）两个标记，两者不计入预算但列在报告里。
- **为什么必须有**：没有它就只是"口头分层"，而精简层当前即便剔除全部历史仍有约 595 KB。
- **负向对照（实测，2026-10-07）**：在现状上**翻红**——精简层 **578.1 KB > 100 KB**（另有用户手册 18.1 KB、
  临时计划（本批 ≈79 KB）被豁免；后者随计划目录增删而变）、必读 **74.2 KB > 25 KB**、入口页 **12 处文件链接指向归档层**
  （`首版-记录-*` 4 处、`附录/*` 5 处、`需求基线`/`评估报告`/`证伪实验计划` 3 处）**加 2 处目录链接**
  （`02-adr/`、`02-adr/附录/`）的目录里含 7 份归档物；`apps/web/evidence/` 的 15 份未登记文档只警告。

### 检查 3：归档层的"不得当当前值引用"（可判定的那一半）
- **机制**：不做语义判断，只做两个可判定项：
  （a）**跨层引用必须带标记词**——L1 文档（`layer==slim`）里的归档层链接，其**链接文本或同一行**必须含
  `历史` / `原文口径` / `细则` / `依据` / `存档` 之一，否则报错，且**按文档聚合**（报 N 处 + 3 个例子，
  不逐条刷屏）。两处不重复报：**入口页**由检查 2 的封闭性负责，**v0.2 临时计划目录**合流后整体删除；
  例外登记在 `doc-index.json` 的 `crossLayerCheck.allow`（每条必须带 reason）。
  （b）**`R*` 存档的轮次上界从台账推导**——把 `check-docs.mjs` 里硬编码的 `round <= 26` 换成"台账轮次列的
  最大值"，跑绿时**在摘要行点名旧硬编码**（"上界 R47 由台账推导，旧实现硬编码 26"）；台账轮次列**解析为空
  即报错**（否则上界静默变成 0、覆盖检查成了恒真式）；另有机械信号：L1 文档提到超出台账上界的轮次 ⇒ **警告**。
- **负向对照（实测，2026-10-07）**：摘要行点名旧上界 26（现推导为 **R47**，R02–R47 覆盖无缺口 ⇒ 旧实现下
  **21 个轮次**不受覆盖检查）；**305 处**缺标记词的跨层链接分布在 **17 份文档**（最重：台账 72、当前规划 65、
  `render-core/SPEC.md` 49、`README.md` 31、`CONTRIBUTING.md` 16）；警告命中 `首版能力顺序.md:304` 提到 **R50**
  而台账上界是 R47——正是 P0 记下的"R48–R50 被引用却未登记"。

### 顺带修掉的既有缺陷（同属 P1，因为它们是同一处脚本）
1. `check-docs.mjs` 的 `allowlist.set(rule.path + …)` 死代码（`doc-index.json` 只有 `pathRegex`/`targetRegex`）
   —— 已删；**更关键的是它背后的语义错误**：旧实现只把 `targetRegex` 拿去做两次 `test`（一次对 target、
   一次对 path），`pathRegex` **从未参与**，于是"白名单"比登记的宽得多。现改为 **`pathRegex ∧ targetRegex`**。
2. 白名单缺口的补齐：P0 记的"**12 处**引用已删 spike 目录"实测是 **6 处链接 + 6 处散文提及**；6 处提及
   旧实现完全看不见（提及扫描只覆盖**代码**、且只认 `.md` 后缀）。现把提及扫描扩到**全部被索引 markdown +
   目录形态**，并补齐两条白名单规则（`g0-s4-svg-clipping` 与 `g7-export-probe`），每条带 reason。
3. `g7-export-probe` 的白名单条目**已补**；3 份入库证据的"迁移说明"里**本来就写着**"该探针目录随 G7 落地删除"
   ⇒ 来源链是自解释的，无需改证据文本（正文不改写）。
4. `DOC-SPEC.md` 被合并的两行已拆开、"四层模型"已改为**五层**（`P-27` §2 的登记/契约/判定/记录/待定），
   并把三份基线文档显式标为**归档层**；§五 的表补了"上界由台账推导"与提及扫描的范围，
   另加一条指针说明三条新检查的规范措辞由 **D1** 补入。

## 三、"稳定"的可判定定义（合流标准）

**五条同时成立**，缺一不可：

1. **测试通过**：`pnpm test` 全绿且例数不减。**计数口径只有本行这一处**——**判据与验收类**文档
   （含 [入口](README.md) §三）一律指回本行、不复述数字，因为复述过的第二份已经腐烂过一次；
   **带时点的基线/记录快照不在此列**（如 [基线与决策](01-基线与决策.md) §一 的"P0 实测基线"，
   它记的就是当时读数，本就该保持原样）。沿革：P1 写下这句时 55 spec / 809 例
   → C7-f 后 57 / 846 → **P4-c 的 golden 钉子后为 57 spec / 847 例**（**2026-10-08 本机实测全绿，15.7 s**）。
2. **文档与代码一致，且由门禁检查**——不是人工声称：三条新检查 + `docs:check` 全绿。
3. **完整门禁九步全绿**，且**至少一次是在干净检出上**跑绿的（`git clone` 后 `pnpm install && pnpm gate`）。
   这一条特别针对 `c74ad52` 的修复：它把 `build` 前移到 `typecheck` 之前，但**从未在干净检出上验证过**，
   而 `v0.1.0` 仍带旧序 ⇒ **必须有一次真实运行**。
   **读数（2026-10-08）**：`pnpm gate` 九步在**工作区**上全绿（Node v26.7.0 / pnpm 10.34.6 / Chrome 154.0.8037.95 /
   Python 3.14.5 + `openpyxl 3.1.5`）；**"干净检出"那一半仍未取得**（本机 `origin` 当前访问不通，见 §七），
   是 **P5-d** 的动作——工作区绿不能代替它（`dist/` 已在盘上，而干净检出里没有）。
4. **精简层达标**：≤ 500 KB（必读 ≤ 34 KB；构成与 `generated` 不计入的口径见 R53/P-55），且入口只引用精简层。
   **读数（2026-10-08）**：精简层 **495.2/500 KB**、必读 **32.9/34 KB**、`docs:check` **警告 0**、常量命中 **0**
   ⇒ **余量只剩 4.8 KB / 1.1 KB**：P5 新增的任何文档只能进**记录层或临时计划层**
   （临时计划实测 420.5 KB，`budgetExempt` 不计入），不得进精简层、更不得进必读三份。
5. **经过 review**：人工 review 的结论写进记录层（谁、何时、过了哪些点、有无遗留）。

**另需**：`v0.2` 为 **annotated** tag，报文即发布说明初稿（沿用 v0.1.0 的做法：范围 / 门禁 / 复验结论 /
明确未做 / 验证环境）。

## 四、证据纪律（记录制）

**问题**：`README` 自己的口径是"换机器 / 换 Chrome 大版本 / headed / DPR>1 都会改变绝对值，
引用时必须连口径一起读"；而 P2/P3 的改动会**必然作废**四份记录制证据（拖动 / 对齐 / 主口径 / 持久化）
与两处 golden 字节数。零散改动会让它们被反复作废。

**纪律**（沿用 `P-41 §9(a)`、`P-44 §9(a)` 的先例）：

1. **同批次集中重取**：把会作废证据的改动**排进同一批**（常量单点化 + 轴元素相关的拆分），
   **只作废一次**；
2. **重取前先声明**"本次将作废哪几份证据"，重取后在记录层逐份登记新的环境与数字；
3. **golden 口径不变，取字节级**；`c₃` 锚值若因轴元素模型未动而**原样通过**，
