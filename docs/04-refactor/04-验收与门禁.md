# 验收与门禁

> 本文件回答**「这一步算不算做完」**。它同时是 P1（建检查）的设计书、各阶段的验收标准、
> 以及"合流主干"的稳定定义。判定口径的来源是各阶段文档，不在此复述。

## 一、阶段 P1：三条新检查（**先于改内容**）

**为什么先做**：本轮的核心风险是"改完之后再次分叉"。所以先把"分叉"变成**会失败的断言**，
再改内容——这与仓库既有风格一致（`ADR 0001` 的铁律都是可执行检查，而不是口头约定）。

### 检查 1：契约常量单点声明
- **机制**：在 `docs/doc-index.json` 里登记一张"常量 → 唯一声明处"的表（`c₃` 逐档位锚值、
  `ELEMENT_MODEL_G5` 的 `overlay`、`EXPORT_TICK_LENGTH_PX`、`HEADER_HEIGHT_PX`、性能阈值 `1 ms`/`2 ms`、
  诊断码表条目数等）；由 `scripts/check-docs.mjs`（或新脚本）扫描 **L1 文档 + `packages/**` 源码 + `scripts/**`**，
  在**非声明处**发现同一字面量即报错。
- **为什么必须有**：这是唯一能拦住 [基线与决策](01-基线与决策.md) §五里那类分叉的机制。
  现有 809 例测试**结构上抓不到**它（CONTRIBUTING 自己写过"三处都各自自洽时没有任何单测会抓到"）。
- **负向对照（必须有牙）**：在现状上运行必须**翻红**，并列出：

  | 期望被点名的位置 | 期望被判定的错值 |
  |---|---|
  | `docs/02-adr/0007-渲染几何与裁剪契约.md` | `116 / 70 / 89` |
  | `docs/02-adr/0008-列身份所有权与拖拽交互契约.md` | `6 · rows + 12` |
  | `docs/00-baseline/裁决记录.md`（P-32 结论列） | `c₄ = 3·rows + 12` |
  | `packages/render-core/src/count.ts` | `3·rows + 12`、`每帧固定 12` |
  | `packages/render-core/SPEC.md` | `114 / 69 / 88` |
  | `scripts/measure-render.mjs` | `120 / 88 / 93` |
  | `apps/web/src/components/GanttChart.vue` | `TICK_LENGTH_PX = 6`、`EDGE_STUB_PX` 的 8、`#7a8699`/`#2e75b6` |
  | `apps/web/src/components/TaskTable.vue` | `#cfe3fa` |
  | `packages/render-core/src/svgExport.ts` | `COLOR` 表里与 `manifest.ts` 重复的 5 个色值 |

### 检查 2：精简层预算 + 入口封闭性
- **机制**：`doc-index.json` 增加 `layer: slim|archive` 与 `contextBudget`；
  （a）`sum(bytes of layer==slim) ≤ contextBudget`；
  （b）**解析 `docs/README.md` 的全部链接，断言目标都属于 `slim`**（归档层的引用只能出现在 L1 正文的"依据/细则/历史"上下文里，入口页不指过去）；另加 `userFacing` 标记，用户手册默认不计入"开发上下文"预算。
- **为什么必须有**：没有它就只是"口头分层"，而精简层当前即便剔除全部历史仍有约 595 KB。
- **负向对照**：在现状上运行必须**翻红**并给出超预算的清单（预期：精简层候选约 595 KB ≫ 100 KB，
  且入口页当前链到 `00-baseline/裁决R*.md` 一类归档物）。

### 检查 3：归档层的"不得当当前值引用"（可判定的那一半）
- **机制**：不做语义判断，只做两个可判定项：
  （a）**跨层引用必须带标记词**——L1 文档里的归档层链接，其**链接文本或同行**必须含
  `历史` / `原文口径` / `细则` / `依据` / `存档` 之一，否则报错；
  （b）**`R*` 存档的轮次覆盖从台账推导**——把 `check-docs.mjs` 里硬编码的 `round <= 26`
  改成由台账条目推导上界（现状缺口：R27–R47 的 29 份存档不受保护）。
- **负向对照**：在现状上运行必须点名 `check-docs.mjs` 的硬编码上界，并至少命中一处不带标记词的跨层链接。

### 顺带修掉的既有缺陷（同属 P1，因为它们是同一处脚本）
1. `check-docs.mjs` 的 `allowlist.set(rule.path + …)` 死代码（`doc-index.json` 只有 `pathRegex`/`targetRegex`）；
2. 白名单缺口的补齐：**12 处**引用已删 spike 目录的位置不在白名单内；
3. `g7-export-probe` **完全没有白名单条目**，而 3 份入库证据把它写成生成者（来源链断裂）
   ⇒ 要么补条目并注明"探针目录已删"，要么改证据文本；
4. `DOC-SPEC.md` 表格里被合并的两行、以及"四层模型"与 `P-27` 的"五层"不一致（属 D1，但同批受理）。

### P1 的验收
| 项 | 判据 |
|---|---|
| 三条检查存在且**有牙** | 在 `main` 的现状上**全部翻红**，输出可读的失败清单（不是只报"有 X 处"） |
| 既有门禁不被破坏 | `pnpm docs:check` 在**加检查之前**绿；加检查后红；在 D 批修完后**再次绿** |
| 不可被静默绕过 | 三条检查都进 `pnpm gate` 的 `docs:check` 步；**缺 Python/Chrome 不影响的步骤不得跳过**（沿用 P-12 口径） |
| 反向保护 | 每条检查都配一个"修好后必须绿"的钉子用例（可放在检查脚本的自检里，或写进 [登记与本轮不做](05-登记与本轮不做.md) 的验收记录） |

| **P5** | 九步门禁全绿 + review + `v0.2` tag | 见 §三 |

## 三、"稳定"的可判定定义（合流标准）

**五条同时成立**，缺一不可：

1. **测试通过**：`pnpm test` 55 spec / 809 例（或更多）全绿。
2. **文档与代码一致，且由门禁检查**——不是人工声称：三条新检查 + `docs:check` 全绿。
3. **完整门禁九步全绿**，且**至少一次是在干净检出上**跑绿的（`git clone` 后 `pnpm install && pnpm gate`）。
   这一条特别针对 `c74ad52` 的修复：它把 `build` 前移到 `typecheck` 之前，但**从未在干净检出上验证过**，
   而 `v0.1.0` 仍带旧序 ⇒ **必须有一次真实运行**。
4. **精简层达标**：≤ 100 KB（必读 ≤ 25 KB），且入口只引用精简层。
5. **经过 review**：人工 review 的结论写进记录层（谁、何时、过了哪些点、有无遗留）。

**另需**：`v0.2` 为 **annotated** tag，报文即发布说明初稿（沿用 v0.1.0 的做法：范围 / 门禁 / 复验结论 /
明确未做 / 验证环境）。

## 四、证据纪律（记录制）

**问题**：`README` 自己的口径是"换机器 / 换 Chrome 大版本 / headed / DPR>1 都会改变绝对值，
引用时必须连口径一起读"；而 P2/P3 的改动会**必然作废**四份记录制证据（拖动 / 对齐 / 主口径 / 持久化）
与两处 golden 字节数。零散改动会让它们被反复作废。

**纪律**（沿用 `P-41 §9(a)`、`P-44 §9(a)` 的先例）：

1. **同批次集中重取**：把会作废证据的改动**排进同一批**（常量单点化 + 轴元素相关的拆分），
   **只作废一次**；
2. **重取前先声明**"本次将作废哪几份证据"，重取后在记录层逐份登记新的环境与数字；
3. **golden 口径不变，取字节级**；`c₃` 锚值若因轴元素模型未动而**原样通过**，
   这本身就是"未改行为"的最强证据（应写进 P3 的验收记录）；
4. **不设会抖动的硬阈值**：记录制里新增的判据要么是"存在性/形状"，要么带覆盖度自证
   （沿用 `P-41` 的"没测到不再记 ✅"口径）；
5. **环境三件套**：每份证据必须写明浏览器版本 + headed/headless + DPR + 视口 + 档位 + 数据集 + 轮数。
   （顺带修：`measure-render.mjs` 现在把主口径证据的视口写成 `1280×640`，而实际是 `1280×800`——
   见 [代码重构](03-代码重构.md) 的 C1。）
