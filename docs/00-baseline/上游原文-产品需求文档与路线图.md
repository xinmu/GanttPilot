# 第一部分：产品需求文档（PRD）
## 1. 产品概述
### 1.1 一句话定位
> 把 Excel 里长大的计划，变成专业排程的甘特图，一键输出可编辑的汇报 PPT——个人和小团队用得起、学得会的开源项目计划工具。
### 1.2 目标用户
| 画像 | 典型场景 | 核心诉求 |
|------|---------|---------|
| 咨询顾问 / 交付 PM | 给客户做计划、周度汇报 | 导出质量 > 编辑深度 |
| 互联网中小团队 TL | 排期、向上汇报 | 轻量上手快，不学排程理论 |
| 自由职业者 / 乙方 | 项目交付管理 | 单人闭环、免费开源 |
### 1.3 问题与价值主张
目标用户的真实工作流存在三个断点：
1. **Excel 太平面**——无排程引擎、无依赖推演、改一处全靠手动核对；
2. **MS Project 太重**——昂贵、桌面端、学习成本高；
3. **汇报出口没人管**——截图贴 PPT 模糊且不可编辑。
价值主张 = **Excel 的轻 + Project 的引擎 + PPT 的出口**，产品叙事收敛为：“**做完计划，汇报 PPT 已经好了**”。
### 1.4 竞争格局
| 维度 | 开源甘特库 | GanttProject 等 | MS Project | 商业 SaaS（TeamGantt 等） | 本产品 |
|------|-----------|----------------|-----------|--------------------------|--------|
| 排程引擎（CPM/关键路径） | 无/弱 | 有，桌面端陈旧 | 极强 | 中 | 中强（完整 CPM，砍掉资源求解） |
| Web 交互 | 中 | 弱 | 弱（桌面） | 强 | 强 |
| PPTX 原生可编辑导出 | ✗ | ✗ | ✗ | ✗ | **✓（核心差异化）** |
| xlsx 无损往返 | ✗ | 弱 | 弱 | 中 | **✓（一等公民）** |
| 价格 | 免费 | 免费 | 高 | 订阅 | 免费开源（MIT） |
开源赛道结论：**“Excel 导入 → 排程引擎 → 可编辑 PPTX 导出”这条完整链路在开源界目前无人覆盖**，是本项目的立足点。
## 2. 产品原则与非目标
产品原则（写入 README，防功能蔓延）：
1. **替用户排程，而非教用户排程**：默认视图不暴露 ES/LS/浮动时间等概念（藏于“高级”开关）；
2. **所见 = 所导出**：导出由数据投影生成，不走截屏路线；
3. **本地优先**：无账号、无服务端也可使用全部核心功能。
非目标（明确不做）：
1. 协作编辑（OT/CRDT、实时通道、冲突合并）；
2. 资源求解（自动资源均衡、固定工时/单位/工期三态调度、资源池）；
3. 企业级功能（项目组合、工时单、跨项目依赖、组织资源视图）；
4. .mpp 读写（封闭格式；以 MS Project XML 导入对冲）；
5. 数据规模承诺（单项目 ≤ 2,000 任务 / 3,000 依赖封顶）；
6. Excel 公式/宏解释（导入时一律扁平化为值）。
## 3. 用户故事（P0 验收锚点）
| ID | 用户故事 | 验收要点 |
|----|---------|---------|
| US-1 | 我把 200 行任务清单的 xlsx 拖进网页，3 秒内看到带依赖连线与关键路径的甘特图 | 常见结构（缩进层级或 WBS 编号列 + 日期 + 前置任务列）可导入；列映射向导 ≤ 3 步 |
| US-2 | 某任务延期 3 天，我立即看到下游被推迟、关键路径变化、里程碑是否受威胁 | 拖拽期间下游实时跟随（≥ 30fps）；松手后 ≤ 200ms 完成重算与冲突标记 |
| US-3 | 导出 PPT 后图形可编辑（改色、挪位、连线跟随），而不是一张截图 | PowerPoint 2016+ / Office 365 / WPS 打开：任务条为原生形状、依赖线为 connector 且拖动任务条时跟随（Keynote 尽力兼容） |
| US-4 | 断网/无服务时产品依然完整可用 | 本地优先：核心功能零后端依赖，文档本地自动保存 |
| US-5 | 我改坏了计划，能回到 10 分钟前的版本 | 本地自动保存 ≤ 5s 间隔；快照可按时间点恢复 |
**首次使用旅程（转化主路径）**：打开在线 Demo → 拖入 xlsx → 3 秒出图 → 拖拽感受“下游跟着动” → 导出 PPT。首页与新手引导的全部设计均服务于该旅程。
## 4. 功能需求
### 4.1 优先级总表
**P0（MVP 必须）**
| 模块 | 能力 |
|------|------|
| 数据模型 | WBS 层级任务树（自动编号、Tab/Shift+Tab 调级、折叠）、核心字段（名称/日期/工期/进度/里程碑/备注）、4 类依赖（FS/FF/SS/SF）+ lag、建边检环、无日期节点容错（WBS 友好） |
| 调度引擎 | CPM 正逆向（ES/EF/LS/LF、总浮动/自由浮动）、关键路径高亮、增量重算、循环依赖阻断 |
| 视图渲染 | 甘特条/进度/里程碑菱形/汇总条、左表右图分屏、行内编辑、依赖连线（正交路由 + 类型箭头）、日/周/月/季刻度缩放、虚拟滚动 |
| 交互 | 拖拽三语义（改开始/改工期/整体移动）、拖拽建线、撤销重做（手势级事务合并）、冲突即时提示 |
| xlsx 往返 | 导入（缩进/编号双解析 + 向导）、导出（影子 sheet）、round-trip 一致性；CSV 尽力导入（降级定位，不承诺无损） |
| 导出 | SVG（语义化）、PNG（多倍率）、PPTX 原生形状（模板 A/B/C） |
| 持久化 | 本地自动保存、本地快照/时间点恢复 |
**P1（差异化/完整性）**：任务约束（不得早于等）、手动/自动排程双模式、基线（1 组 + 对比视图）、筛选/分组/排序、PPT 主题跟随（读取用户模板）、MS Project XML 导入、键盘操作流、批量操作、可选云同步（自部署）、飞书 L0/L1。
**P2（backlog，不预先排期）**：网络图（PERT）、资源直方图 + 过度分配检测、成本字段、多组基线、自定义字段、任务拆分、打印分页、PWA 离线安装、飞书 L2/L3、插件机制。
### 4.2 P0 验收标准（DoD）
**调度引擎（独立包，零 DOM 依赖）**
- 测试矩阵：4 关系类型 × lag（正/负/0）× 跨层级依赖 × 日历例外，与 MS Project XML 计算结果黄金比对一致；
- 性能基准 @1,000 任务 + 1,500 依赖：全量 CPM ≤ 100ms，拖拽局部重算 ≤ 10ms/帧。
**xlsx 往返协议**
- 层级表达：缩进式 或 WBS 编号列，二者皆可；
- 依赖列语法：`编号[FS|SS|FF|SF][±lag]`，分号分隔多前置；
- 影子 sheet `__gantt_meta__`：内部任务 ID、依赖边表、日历设置、视图状态；解析优先级：影子 ID > 编号；
- round-trip：核心字段 100% 无损；依赖在有影子 ID 时 100%、纯编号表达 ≥ 95%；
- 边界：不解析公式/条件格式/宏。
**PPTX 原生导出（不可降级为贴图）**
- 形状映射：任务条 = 圆角矩形、里程碑 = 菱形 preset、依赖 = connector（吸附连接点）、父子 = group（局部坐标系换算正确）；
- 单位：像素 → 英寸 → EMU 统一仿射变换，页面尺寸（16:9/A4）可配；
- 兼容矩阵：Office 2016+ / 365 / WPS 必过，Keynote 尽力；降级预案：connector 异常时退化为折线形状；
- 模板规格：A = 单页总览（甘特 + 图例 + 自动摘要：完成率/里程碑数/关键节点表）；B = 按 WBS 一级分阶段多页；C = 里程碑 roadmap 时间线页。
**渲染与交互**
- 1,000 任务虚拟滚动首屏 ≤ 1s，拖拽 ≥ 30fps（目标 60fps）；
- 一次手势 = 一个 Command（含事务），Ctrl+Z 一步回退整次连锁变更；
- 违反依赖的拖拽：默认吸附到约束边界 + 冲突标记，可切换为“允许 + 标红”。

## 6. 数据模型与核心概念
单文档 JSON 模型（版本化 schema，支持迁移）：
```jsonc
{
  "version": 3,
  "project": { "name": "...", "calendarId": "...", "startDate": "..." },
  "calendars": [ { "id", "workDays", "exceptions": [] } ],
  "tasks": [ { "id", "parentId", "name", "startDate?", "duration?",
               "progress", "milestone", "manual", "constraints": [] } ],
  "links": [ { "id", "from", "to", "type": "FS|SS|FF|SF", "lagDays": 0 } ],
  "baselines": [ { "id", "snapshot": {} } ]
}
```
调度引擎为纯函数：`compute(tasks, links, calendars, constraints) → Schedule`，是全系统唯一排程真相源；所有变更经命令层唯一通道进入。
## 7. 技术架构
### 7.1 分层
```
┌─ 平台适配层（可选）  本地模式 / 托管版 / 飞书网页应用（同一前端）
├─ 云服务模块（可选）  同步 / 快照（远期，独立于核心）
├─ 渲染层             Canvas（条形/刻度）+ SVG（连线/选中态），虚拟化
├─ 视图模型层         RenderProjection + ExportProjection 双投影（纯函数）
├─ 交互层             手势状态机 + 乐观更新
├─ 命令层             Command / 事务 / 撤销栈（变更唯一入口）
├─ 计算层             CPM / 约束 / 日历 / 检环（纯函数，独立包）
└─ 数据层             文档模型 + Schema 迁移 + 本地持久化
```
### 7.2 三条铁律
1. **计算层为独立包**，零 DOM/框架依赖，独立测试矩阵（核心资产 #1）；
2. **双投影架构**：视图模型层同时产出渲染投影与导出投影，三导出器（SVG/PNG/PPTX）共享几何计算，保证“所见 = 所导出”（核心资产 #2、#3：xlsx 往返协议、PPTX 形状引擎）；
3. **本地优先**：第 0–5 层不依赖任何网络服务；云端能力为可选外挂模块，不影响核心可用性。
### 7.3 技术栈（建议项，非强制）
| 层 | 建议 | 理由 | 可替换性 |
|----|------|------|---------|
| 语言 | TypeScript | 类型系统对调度引擎正确性价值极高；AI 辅助编码质量最佳 | 计算层可按任意语言独立实现（如未来做 WASM/Rust），包接口不变即可 |
| 前端 | React | 生态与 AI 生成质量 | 可换 Vue/Svelte，仅影响渲染层与交互层 |
| PPTX 生成 | pptxgenjs（MIT） | 原生形状/connector 支持完整 | 低 |
| xlsx 读写 | ExcelJS（MIT） | MIT 友好、维护活跃 | 注意：SheetJS 社区版 npm 分发受限，不建议 |
| 部署 | 纯静态 | GitHub Pages / OSS Hosting | — |
选型约束：**所有运行时依赖必须为 MIT/Apache-2.0 等 OSI 许可**，引入前做 license 审查并记入 `THIRD_PARTY_NOTICES`。

# 第二部分：路线图（ROADMAP）
## 14. 产能模型与前提
开发模式：**单人 + AI 辅助编码**。产能评估基于如下模型：
| 工作类型 | AI 加速程度 | 策略 |
|---------|------------|------|
| UI 搭建、样式、样板代码、CRUD、文档 | 高（3–5×） | 放开 AI 生成，人工抽查 |
| 调度算法、xlsx 往返、PPTX OOXML 细节 | **低**（调试与正确性验证仍靠人） | 测试先行 + 黄金用例比对 + 人工审查 |
| 产品决策、视觉打磨、社区运营 | 无 | 保留人工时间预算 |
前提假设：全职单人投入；所有“正确性关键”模块以测试护栏推进。总口径：**约 40 周（9–10 个月）达成 v1.0**；每阶段内置 20% 缓冲。
## 15. 阶段总览

## 16. 阶段详述
### M0（W1–12）：核心引擎与编辑器
- W1–2：数据模型 / Schema / 命令层骨架；引擎 v0（FS + lag + 检环）；**仓库与 CI 护栏先行建立**（AI 辅助开发的前提是测试门禁）；
- W3–6：完整 CPM（4 关系 + 浮动 + 关键路径 + 增量重算）；测试矩阵与 MS Project 黄金用例同步建立；
- W7–9：Canvas 条形 + SVG 连线渲染、多级刻度、虚拟滚动；
- W10–12：拖拽三语义 + 建线 + 撤销重做（事务合并）+ 冲突提示。
**内置降级序列**（工期告急按序砍，不影响退出条件）：仅保留 FS → 刻度分档去动画 → 虚拟化阈值降至 500 任务。
### M1（W13–20）：导出闭环 → v0.1 首发内测
- W13–14：双投影架构落地；SVG / PNG 导出；
- W15–17：PPTX 形状引擎（先模板 A）+ Office/WPS 兼容矩阵手动测试；
- W18：模板 B/C + 主题跟随（P1 项视余量）；
- W19–20：xlsx 导入（双解析 + 向导）+ 导出（影子 sheet）+ round-trip 自动化测试；**v0.1 发布**（tag + 发布说明 + 中文社区发帖 + 邀请 10–30 名种子用户）。
**降级序列**：模板 B/C 延后至 M2 → 主题跟随延后 → PPTX 分辨率先锁 16:9。
### M2（W21–28）：分发与部署形态 → v0.5 公测
- W21–22：GitHub Pages 官方 Demo（全功能、纯前端）；自部署文档（Docker/静态托管两路）；
- W23–24：Monorepo 拆包发布（engine / xlsx-protocol / pptx-renderer 三包上 npm，各自 README 与独立测试）；
- W25–26：P1 编辑器能力：约束、手动/自动排程、基线、筛选分组；
- W27–28：本地快照/时间点恢复 UI；issue 模板与贡献指南；**v0.5 发布**。
**降级序列**：筛选分组延后 → 基线延后（快照先行占位）→ 拆包发布只发 engine 包。
### M3（W29–40）：互操作、稳定与社区 → v1.0
- W29–32：MS Project XML 导入（覆盖 80% 常见字段）+ 导入回归测试集；
- W33–35：飞书 L0 网页应用（提审预留 4 周，与开发并行；依赖托管实例或自部署指引）；
- W36–37：性能与稳定性冲刺（2,000 任务压测、脏文件模糊测试、无障碍基础）；
- W38–40：文档站（用户手册 + 协议规范）、案例征集、**v1.0 发布**（semver 稳定承诺：v1 起数据 schema 保证迁移）。
**降级序列**：飞书 L0 延后至 v1.x → XML 导入收窄至 FS 依赖 → 案例征集转线上问卷。
## 17. 版本策略与依赖关系
- 版本号：`0.x` 快速迭代（可含破坏性变更，schema 提供迁移脚本）；`v1.0` 起遵循 semver，数据格式向后兼容；
- 独立包：engine / xlsx-protocol / pptx-renderer 各自 semver，主应用通过包版本组合交付；
- 并行机会：飞书提审（行政流程）、文档撰写、社区运营与开发并行；
- P2 backlog 在 v1.0 后按社区 issue 投票数据插队，不预先排期。
