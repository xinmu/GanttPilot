### P-43 三个缺陷的裁定与修法

**0. 共同点：三处都是"界面承诺了语义不提供的东西"，或反过来。**

| # | 报文 | 判定 | 类别 |
|---|---|---|---|
| ① | 汇总条两端拖不动，但光标会变成 `col-resize` | **确认（缺陷）** | **两个真相源**：光标按 `zonesFor`（几何）判、手势按 `beginGesture`（语义）判 |
| ② | 里程碑右半区拖动改工期 ⇒ 图上仍是菱形、左表工期已变 | **确认（业务逻辑缺陷）** | **patch 漏了不变量**：`resize-duration` 的 patch 不含 `milestone`，而 `isMilestone` 优先看该标记 |
| ③ | 刷新短暂抖动、重置持续抖动、再点恢复 | **确认（缺陷）** | **自激环**：状态栏换行 ⇒ 变高 ⇒ 窗格变矮 ⇒ 视图重裁 ⇒ 状态栏文案里的数字又变 ⇒ 再决定换行 |

**1. 汇总条：**判定区、手柄、连接点、光标**全部撤下**（"可拖性"收敛到 `zonesFor` 一处）。**

维护者的裁决（逐字要点）：**汇总条两端不能拖动（成立）**；"汇总条两端没有手柄"**不对**——光标会变样式，误导用户。

- 修法：`zonesFor` 对 `kind === 'summary'` 返回 `{ edgeL: null, move: null, edgeR: null }`（**整条没有判定区**）；
  `cursorForPointer` 对汇总整条返回 `default`；`rowHandlesFor` 的 `connectPoints` 对汇总返回 `[]`；
  `linkEntryFor` 对汇总返回 `null`；`count.ts` 的两路计数（分类累加 + 逐项枚举）**成对收紧**
  （`ELEMENT_MODEL_G5.perRenderedRow = 3` 是**上界**，值不变）；
- 为什么连"整体移动"也不给：汇总的日期是**子树聚合结果**，改它要改子树（`beginGesture` 早有此守卫）
  ⇒ 光标不该承诺任何动作。

**2. 里程碑：工期恒为 0；菱形只可移动（P-43 的人工裁决）。**

维护者的裁决（逐字要点）：**两个候选都不同意**——"节点一旦被标为'里程碑'，**工期恒定为 0**，
**不可由左表或条体修改，除非先解除'里程碑'标记**；菱形只可拖动位置，不可拉长工期，**鼠标形状也不应变化**"。

| 面 | 修法 |
|---|---|
| 拖拽 | `dragModeOfZones` 的里程碑分支恒 `move`（**删掉**"右半 = `resize-duration`"）⇒ 光标整条 `move`、不随位置变化 |
| 左表 | `editToCommand` 的 `duration` 列：`task.milestone === true` ⇒ **拒绝**（`ok: false`），文案："里程碑的工期恒为 0：请先在「里程碑」列改为"否"，再修改工期" |
| 出口 | **先在「里程碑」列解除标记**（该列本来就可编辑：`EDITABLE_COLUMNS` 含 `milestone`），再改工期 |
| 不变量 | 这不是新语义：文档层**早就有** `TASK_MILESTONE_WITH_DURATION`（warning，原文"里程碑的 `durationDays` 应为 0"）⇒ 本条的实质是**把已有的 warning 变成"UI 不提供入口"** |

**一条必须一起读的既有口径**：`isMilestone` 的判据是 **`里程碑标记 ∨ durationDays === 0 ∨ ef ≤ es`**
（[domain.ts](../../packages/render-core/src/domain.ts)，与 SCHEDULE.md §一.1 一致）⇒ **解除标记后工期仍为 0 的行
在图形上仍是菱形**——"解除标记"是**必要条件而非充分条件**，还要把工期设到 ≥1 才会画成条。
（"标记是唯一开关"属**引擎语义变更**，本轮**不做**，理由见 §5。）

**3. 状态栏：`flex-wrap: wrap` → **永远单行**（自激环的驱动项）。**

维护者的观察（逐字要点）："抖动区域主要是在**右侧纵向滚动条**和**底部状态栏**，怀疑是状态栏中的文本长度
恰好在换行临界值，而纵向滚动条也会占用其渲染空间，换行会出现滚动条占空间，不换行滚动条不出现，
于是滚动条是否出现和状态栏是否换行相互影响，无法稳态。"

**与代码完全吻合，并且被量出来了**：

- [App.vue](../../apps/web/src/App.vue) 的 `.status` 原本是 `display: flex; flex-wrap: wrap`；
- 而状态栏文案里含**视图派生的数字**（可见行 / 渲染行 / 渲染边 / 元素 / 诊断数 …）⇒
  **窗格尺寸变 ⇒ 视图重裁 ⇒ 数字变 ⇒ 文案长度变 ⇒ 换行与否变 ⇒ 窗格尺寸变**；
- **实测（本机 headless 打包产物，负向对照）**：旧口径下状态栏高 **98 px（首屏）/ 133 px（重置后）**，
  修后 **28 px（单行）**——即"换行"不只是理论：它**真的**在两种高度之间摆。

修法：`.status { flex-wrap: nowrap; overflow: hidden; }` + `.status > span { white-space: nowrap }` +
最长的那一段（第一段）`flex: 0 1 auto; min-width: 0; overflow: hidden; text-overflow: ellipsis`
⇒ **高度与文案长度无关**（从构造上消灭驱动项）。**不做** `scrollbar-gutter: stable`：它会给窗格永久留出
15 px，改变 `c₃` 与既有记录制数字（先例：`c₃` 只取决于"窗格宽 ÷ `pxPerDay`"）。

**4. 汇总端点的依赖：文档层容忍 + warning + 图形层忽略（原样保留 `edge-ignored`）。**

维护者的裁决：**同意**"文档层继续容忍 + 报 warning"，且**不因文档层错误地填入了关系而在图形层建线**，
"应在 warning 之后忽略"。**落地取舍**（本轮的选择）：**保持现状的 `edge-ignored` 样式**（灰线），
理由是"完全不画"会牵动 [ADR 0007 §11 第 7 项](../02-adr/0007-渲染几何与裁剪契约.md)、
元素预算的回填锚值（dense 夹具按设计含 20 条、演示计划含 1 条汇总端点边）以及 **G7 已收口的 golden 与 WPS 证据**
（导出 connector 数 14 → 13）——**发布前不重开已收口块**。"彻底不画"登记为 **v0.5 候选**。
**本轮真正落地的是"入口侧"**：§1 已把汇总行的连接点与建线入口撤下 ⇒ **新建**这样一条依赖已不可能；
导入/手写进来的仍由 warning + 灰线承接（"UI 不给入口 ≠ 不支持读入"）。

**5. 状态栏布局稳态：判据进 `pnpm gate`，并附已证判别力的负向对照。**

`smoke:build` 新增「**布局稳态**」（首屏 + **点一次"重置演示数据"之后**各一次）：

| 判据 | 内容 |
|---|---|
| **收敛**（60 帧） | `(根 clientHeight, 根 scrollHeight, footer 高度, 窗格 clientWidth/clientHeight/scrollHeight)` 的组合在 60 帧内**只有一种取值**；根元素不得出现纵向滚动条 |
| **单行**（判别力来源） | footer 高度 ≤ `getComputedStyle` 现推的单行上界（字号 × 1.6 + 上下 padding + 上边框）；实测上界 **32 px** |
| **高度与文案长度无关** | 把**现有** span 的文本追加 200 字 ⇒ 高度必须不变（探针随后还原文本并复核） |

**负向对照（跑完即还原）**：把 `.status` 换回 `flex-wrap: wrap` ⇒ 冒烟**失败**：
`状态栏不是单行：高 98 px > 单行上界 32 px`（首屏）与 `高 133 px > 单行上界 32 px`（重置后）⇒ **判据有判别力**。
> 落地时的一处**方法学教训**：探针的第一版是**新建一个 `<span>`** 塞进 footer——而 `scoped` 样式会给页面的
> span 加 `data-v-*` 属性，新建的那个不带属性、**绕过了页面 CSS**，于是它量到的不是真实机制（旧口径也能"通过"）。
> 修法：**修改现有 span 的文本**再量。这条与 P-32 的"选择器跟着旧 DOM 走"同族：**探针本身也必须在被测口径之内**。

**6. 与既有裁决的关系。** **不取代、不修改**任何 `Dn/Rn/Tn/Pn` 条目；ADR 正文只加**指针行**，
增补全在附录（[0008 §2](../02-adr/附录/0008-增补.md)）；**不放宽**任何 DoD；
`ELEMENT_MODEL_G5` 的**上界不变**（值未改，只是实际发射量按行类型收紧），
`scaleInvariance` 的四个锚值按既有口径**第二次平移**（122 → **118**，即每个窗口少 4 个元素 = 2 个汇总行 × 2 个连接点），
比值与"与规模解耦"的结论不变。

**P-43 的明确不做**

1. **不改 `durationDays === 0` 也是里程碑**这条引擎口径（"标记是唯一开关"是引擎语义变更：
   会影响 xlsx 导入的 0 工期行、`milestoneCount`、US-2 与回归判据的规模）；
2. **不给"汇总端点依赖"做彻底不画**（登记为 v0.5：要重开 ADR 0007 §11 锚值与 G7 golden/WPS 证据）；
3. **不加 `scrollbar-gutter: stable`**（会给窗格永久留 15 px，改变 `c₃` 与既有数字）；
4. **不给汇总行做任何鼠标交互**（连"整条 `move`"也不给：它的日期是聚合结果）；
5. **不改 `editToCommand` 里 `milestone` 列自身的语义**（解除标记仍然允许——那是唯一的出口）。
