## 第五十三轮：精简层的构成口径与预算重设

| 项 | 内容 |
|---|---|
| 裁决 | **P-55**：① 明确「精简层」的**构成口径**；② 新增 `generated` 标记——**可推导的生成物不计入预算**；③ `contextBudget.slimKb` **100 → 500** |
| 依据（实测，D7.6） | 精简层 **488.7 KB**，构成为：**契约（10 份 ADR）221.8** + **包规范 156.1** + 基线/规范 64.9 + 判定 26.8 + 登记 19.2；其中**可推导的生成物 13.7 KB**（`首版-文档索引.md` 8.8 + `轮次导读.md` 4.9，两者都由 `pnpm docs:index` 从索引/台账/存档推导）⇒ 剔除后 **475.2 KB** |
| 为什么剔生成物 | 生成物的内容**已经**在 `doc-index.json`、台账与按轮次存档里计过一遍；再计一次就是**重复计数**。这与 R52 给必读定的"**可推导的不进必读**"是同一条纪律在两个预算上的应用 |
| 为什么**不**迁走 ADR / 包规范 | **决策 3（契约归位）** 明确：**ADR 写决策 / 边界 / 代价 / 明确不做，包规范写实现口径与验证矩阵**——它们是"**当前契约**"，**必须在精简层**（注入新会话时要能读到"现在必须怎么做"）。把它们迁进归档层等于宣布"当前契约不进注入包"，与决策 3 直接冲突 |
| 上限取值 | **500 KB** = 实测 **475.2** + 约 **5%** 余量（≈130 条台账条目或等量的契约增补）。再往上就该走"**拆分或迁移**"，而不是继续调 |
| 明确不做 | ① **不迁 ADR / 包规范**（决策 3）；② **不把生成物当可注入内容**（它们是查阅物，不是判定与契约）；③ **不改任何契约文本** |
| 待定 | **无新增未决项**；[待定清单](../01-roadmap/首版-待定清单.md) 继续 **0 条** |

### 两条纪律（与 R52 同文，一并写进 [DOC-SPEC](../DOC-SPEC.md) §4.4）

1. **先迁移或剔除，再调上限**；
2. **上限必须由实测推导、并在裁决里写明构成**（本条即给出构成表）。
