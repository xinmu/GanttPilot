### P-34 演示口径＝小型手写演示计划；1,000 任务夹具退为测量/测试口径

**为什么定**（三条，按重要性）：

1. **导出与演示的失败模式是"看不清"而不是"算不对"**：现状页面默认文档是 `dense` 夹具
   （1,000 任务 / 1,500 依赖），日档内容宽度 **10,612 px**（同一视口口径：1,265 px 宽的图表窗格）、
   文档诊断 **951 条** + 排程诊断 **31 条**。
   G7 的模板 A 是**单页总览**（甘特 + 图例 + 自动摘要），拿它当导出主体只会得到一张糊图；
   演示（README 动图、在线 Demo、真机复验）同样讲不清「导入 → 出图 → 拖动 → 导出」这条链。
2. **两条口径的价值相反，不能合并**：演示要**单页可读**（行数、跨度、四类关系的可辨识度是卖点），
   规模要**逼近上限**（"1,000 任务首屏 ≤ 1 s"、"2,000 任务存储占用"是性能声明的载体）。
   合并的代价在本轮之前已经显形：`fixtures.ts` 的注释写着"演示数据、测量口径与测试共用同一份生成器"，
   于是"1,000 任务 / 1,500 依赖"这句话在演示里是负担、只有在测量里才是判据。
3. **G7 的 golden 需要一个稳定且可人工复核的主体**：出口条件⑤要求"同一文档两次导出结构一致
   （golden 文件比对）"；golden 的文档必须小到能逐形状人工核对，并且**零随机**。

**定下的形状**（数值住在 `packages/render-core/src/demoPlan.ts`，判据由 `demoPlan.spec.ts` **进 `pnpm gate`**）：

| 项 | 值 |
|---|---|
| 行数 | **15**（3 阶段汇总 + 10 任务 + 2 里程碑） |
| 依赖 | **14** 条，FS / SS / FF / SF **四类齐备**；含负 lag（`FS −1`）与正 lag（`SS +1`、`SS +2`、`FS +1`、`FS +2`） |
| 进度形态 | 三阶段 **82% / 24% / 0%**（已完成 / 进行中 / 未开始三档俱全，供模板 A 的自动摘要） |
| 跨度 | 序号 **0–35**，**≤ 40 个工作日**；同一视口口径（1,265 × 720、行高 24）下日档 `contentWidth` **1,372 px**、周档 **1,265 px**（= 窗格宽，整幅不滚动），15 行 × 24 px = **360 px 高**（720 px 视口整幅可容） |
| 日期锚定 | 只有链路起点 `t1` 显式给 `startDate`（锚点情形①）；其余任务靠传播定位 |
| 文档诊断 | **error 0**；良性 warning 恰 **11 条**（全为 `TASK_DURATION_WITHOUT_DATES`，DM-05 的合法表达） |
| 排程诊断 | **0 条**（刻意不出汇总端点边，因而不产生 `LINK_SUMMARY_ENDPOINT`） |
| 确定性 | 零 `Math.random`；两次 `createDemoPlanDocument()` 逐字节一致 |

**落点**：

- `packages/render-core`：新增 `src/demoPlan.ts`（演示口径的**唯一定义处**）、`src/index.ts` 导出
  `createDemoPlanDocument`、新增 `src/demoPlan.spec.ts`（**8 例**，进 `pnpm gate`）；
- `apps/web`：`useProject.createDemoDocument()` 指向演示计划；`App.vue` 的重置改为
  **按实际文档派生计数**（旧的 `project.reset(createPrimaryDemoDocument())` 与写死的
  "1,000 任务 / 1,500 依赖"一并删除）；**删除 `apps/web/src/demo.ts`**——它的三处导出已全无调用点，
  其中 `demoDatasetChoices` / `createSmallDemoDocument` 是死代码，注释却声称工具栏有"换夹具"（界面里并不存在）；
- `scripts/smoke-build.mjs`：新增"打包产物里的默认文档仍是小型计划（8 ≤ 任务 ≤ 40）"的断言——
  这是唯一能抓到"产物仍然开在大夹具上"的门禁；
- 文档：`render-core/SPEC.md` §二/§九 登记演示口径与两类夹具的分工；路线图 G7 段冻结 golden 主体。

**明确不做**（登记避免"看起来已完成"）：

- **不加界面切换**：大夹具在界面里不可达，只由记录制测量（`?dataset=`）与各包 spec 使用；
- 不改 `DATASETS` / `REFERENCE_DATASET` / `scaleGradient`：任一既有的 1,000 / 2,000 任务判据保持原样；
- 不做 `scripts/make-sample.mjs` 的"演示计划 xlsx 样本"（导入演示与 README 动图归 G7 / G8）；
- **不迁移已落库会话**：浏览器里已有的大夹具会话仍由 G6 的恢复路径拿回（[ADR 0009 §4](../02-adr/0009-持久化契约.md)），
  要看到新的演示计划需点"重置演示数据"或用新 profile——这是诚实口径，不是缺陷。
