### P-42 批次③的三项

**0. 一句话。** 三项都是"**挂了三轮的口径**"：不是能力缺口，而是**没人决定过的事**——
① 表头带里允许放什么（跨 P-23 → P-24 → P-32 原样承接）；② 手柄与连接点的外观（P-32 遗留 1）；
③ 键盘入口的归属（P-32 遗留 3）。三项的共同点是**都不阻塞发布**，共同的风险是**继续挂着**。

**1. 表头带的内容：口径闭合（只承载时间刻度）。**

| 项 | 内容 |
|---|---|
| 裁定 | 表头带的**内容集合** = **时间刻度**（刻度线 + 日期文本）；**未来若要放"档位/单位提示"必须先在本附录登记**；底色、边框、栏高、两栏对齐与分隔线**不属于**这个集合（它们是纯视觉打磨，随改随走、不需登记） |
| 为什么算口径而不是打磨 | 判据要能回答"带里有没有不该有的东西"。今天可判定的部分是 `axis-labels-not-in-header`（刻度文本必须落在带内 ⇒ "带里写日期"是**规定动作**）；**"带里出现了别的文本"没有判据** ⇒ 本口径把它变成一条**登记义务**：新增带内内容 = 先改附录（并同步判据），而不是悄悄加一行文字 |
| 落地 | [ADR 0007 §15.3](../02-adr/0007-渲染几何与裁剪契约.md) 加一行指针；[附录 §2](../02-adr/附录/0007-增补.md) 记口径；待定清单 `P-23` 该行结转 |
| 代价（明确接受） | 没有加"带内禁止其他文本"的**自动判据**（要做就得给记录制加一个"带内文本元素计数 + 白名单"的采样器）；**换取的是**这条口径终于可以被回答、被引用，而不是每轮重新讨论一次 |

**2. 连接点的可见图形：正方形 → 圆（**维护者的人工微调**）。**

维护者的报文（逐字要点）：**现状**是"连接点手柄为与条体等高的正方形白框"；
**建议改为**"直径较条体高度略小的圆圈"。裁定照此执行，并把它做成**可判定的几何**：

```
connectDiameterFor(bounds, rowHeight)
  = max(CONNECT_MIN_DIAMETER_PX,            // 6：退化条上也看得见
        min(CONNECT_SIZE_PX,                // 12：可见 ⊆ 命中盒
            barHeightOf(bounds, rowHeight) - 2 * CONNECT_DIAMETER_GAP_PX))   // 略小于条高
圆心 = (connectLeftEdgeFor(bounds, side) + CONNECT_SIZE_PX / 2, bounds.y)
```

| 行类型 | 条高 | 直径 |
|---|---|---|
| 标准叶子条 | 14.4 | **12**（= 上限，略小于条高） |
| 汇总条 | 8.4 | 6.4 |
| 里程碑（菱形） | 12 | 10 |

**三条不变量**（判据写在 `interaction.spec.ts`，**进 `pnpm gate`**）：① 圆心在**命中盒中点**上（跨在条端上）；
② 圆心竖向 = **条心**（不是行顶——P-32 第二次复验的根因）；③ **可见 ⊆ 命中盒**（`diameter ≤ size`）。

**为什么命中区一行未改**：`connectSideAt` / `connectRevealFor` / `rowHandlesFor` 的命中判定**本来就只按 x**
（P-32 第三次复验的结论），而圆的外接盒正是那个 `<rect>` 的替代物 ⇒ §16.7 的三条结论
（"看得见的图形一定点得中"、可用宽度 14 → 20 px、内侧不抢端点判定区）**继续成立**。

**落地面**：`GanttChart.vue` 的 `<rect rx="2">` → `<circle :cx :cy :r>`（DOM 标签变了，
因此记录制侧的三个选择器改为**不限定标签**的 `.connect-point`——先例是 P-32 落地时"选择器跟着旧 DOM 走"
造成过假阴性）；`measure.ts` 的 `collectHandleSample` 新增 `connectTag` / `connectBox`，
并在打包产物上判"DOM 真的是 `<circle>`""可见盒是正方形且 ≤ 命中盒边长"。

**代价（明确接受）**：可见面积变小（标准条 144 → 113 px²，约 −21%；汇总/里程碑行更多），
换来的是**形状语言分离**：圆 = 连接点、短竖线 = 端点手柄、方块 = 条体。
**命中可用宽度不变**（仍 20 px），元素预算不变（`c₄ = 6·rows + 12` 一字未改）。

**3. 键盘可及的手势入口：归 v0.5，本版闭合。**

| 项 | 内容 |
|---|---|
| 裁定 | `Tab` / 方向键改期与键盘建线**归 v0.5**——它已在[《首版能力顺序》§五](../01-roadmap/首版能力顺序.md) 由 P1-07/08（键盘操作流、批量操作）承接；**本版不再列为未决**（未决项的定义是"还没定"，而这里"归属已定"） |

| 落地 | 待定清单 `P-32` 该行结转；README 的"已知限制"不再新增条目（v0.5 计划已在路线图 §五 列明） |

**4. 实测（打包产物 / Chrome 154 / `--headless=new` / DPR 1 / 基视口 1280×800）。**

`--drag` 的手柄段（本轮新增的两行是形状口径的直接证据）：

| 量 | 值 | 判据 | 判定 |
|---|---|---|---|
| DOM 连接点条数（指针所在行） | 2 | = 2（按需显形） | ✅ |
| 从连接点按下进入建线 | 是 | 必须为"是"（R4 的修法） | ✅ |
| **连接点的 DOM 形状** | **`<circle>`** | = `circle`（P-42 的圆点口径） | ✅ |
| **连接点可见盒（宽 × 高）** | **12 × 12** | 正方形（圆的外接盒）且 ≤ `CONNECT_SIZE_PX` | ✅ |
| 条体中部 / 端点 / 连接点光标 | `move` / `col-resize` / `crosshair` | 三分类 | ✅ |
| 位移判据 | `startDate 2026-10-08` = 期望 | 拖 3 个工作日 | ✅ |

`--align` 复核（换 DOM 标签后**逐档位仍全绿**，证明"圆点"没有动到两栏几何与命中反算）：
`day` / `week` / `month` 各 6 个位置 **失败 0**、最大行差 **0.001 px**、覆盖 ✅/✅、机制为空；
resize 迁移（1280×800 → 1024×640）窗格 **374×587 → 118×377**、位置存活、机制为空。

> **一条如实登记的口径**：本轮 `--drag` 的**帧间隔 p95 = 37.6 ms**（判据 ≤33.3 ms，证据里记 ⚠️）。
> 它与 [P-41 §8(b)](裁决R40.md) 记的同一现象同源——**机器当时有多忙**（同一会话里"变造回旧口径"实测 36.6 ms，
> 两种口径同量级）。本轮**保留该快照**（而不像 P-41 那样恢复旧版）：因为**形状口径的证据只能由本轮产生**，
> 而形状读数（标签、包围盒、命中入口）与负载无关；帧间隔是**记录项**（⚠️），不是本轮判据。

**批次③的明确不做**

1. **不给"带内其他文本"加自动判据**（口径 + 登记义务为主；要做就是记录制加一个白名单采样器）；
2. **不改命中区、判定区与显形规则**（P-32 三次复验的结论必须原样保住——改形状的代价一旦外溢到命中，
   就是"看得见却点不中"的重演）；
3. **不给圆点加悬停高亮/动画**：连接点是**按需显形**的（指针靠近才出现），再叠一层悬停态会让
   "何时出现"的判据变复杂；这项归纯打磨，需要时另立口径；
4. **不做键盘路径**（归 v0.5 的键盘操作流）。
