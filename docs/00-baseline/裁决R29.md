### P-30 提示条不得比它描述的事实活得更久

**1. 报文（维护者，2026-10-04）**：**有改进**——提示不再常驻；**未解决**——实操"提示出现 → 修改 → 提示不消失"，
预期"提示出现 → 修改 → 提示消失"。给出的完整口径是：**回退栈不为空时提示不应出现**，**退回到栈底时也不出现**，
**只有在栈底尝试回退时才给提示**。维护者同时否决了"完全不提示（静默失效）"的降级方案。

**2. 根因**：[P-28](裁决记录.md) 落的是 [P-21](裁决记录.md) §3 的**窄口径**（"成功的 `undo()`/`redo()` 清提示"）——
它只修了撤销/重做这一条通道，而提示条描述的是**状态**（回退栈里有没有东西）：只要状态前进（编辑、拖动、折叠、
导入、重做…），「没有可撤销的步骤」就已经不成立，与"这一步是不是通过撤销推进的"无关。

**3. 裁决**：把提示条的迁移做成**一条纯规则**并**进门禁**（`viewText.ts` 的 `noticeAfterDispatch`，唯一实现处）：

| 情形 | 结果 | 理由 |
|---|---|---|
| **失败** | 换成失败提示 | 提示**唯一**的产生时机：只有"尝试了但没成功"才报 |
| **成功且 `changed`** | **清掉失败提示**（`info` 不动） | 状态前进了一步，失败提示描述的事实已被推翻 |
| **成功但没改**（恒等 patch / 同位置调级） | **原样保留** | 状态没前进（无操作不压栈），提示的事实可能仍成立 |

由此得到维护者要求的不变量：**回退栈非空 ⇒ 不会挂着「没有可撤销的步骤」**；**退回到栈底那一步是成功的 ⇒ 不出现它**；
**只有"在栈底再回退"这一次尝试**才会产生它。**不采用**"完全不提示"的降级方案。

**4. 与既有裁决/ADR 的关系**：**不取代、不修改**任何 `Dn/Rn/Tn/Pn`；[P-21](裁决记录.md) §3 的原文继续有效
（它是"清提示"这条要求的出处），本条只把它的**口径**补全为"**随状态前进而清**"；`P-29`（提示清空是否加宽）
**由本条收口**，台账状态改为 `已闭`；**不改 ADR 正文**（提示条是应用层呈现，不是契约）；不放宽任何 DoD。

**5. 代价（明确接受）**：

- 失败提示的**寿命变短**：任何一次成功且真的改了文档的命令都会把它抹掉——这正是要求；
- **`info` 与 `error` 不再对称处置**（呈报不被无关操作抹掉）⇒ 规则多一档，已在判据里逐档写死；
- DOM 层（提示条是否真的从状态栏消失）**仍不在 `pnpm gate`**：`apps/web` 没有判据入口
  （P-19 遗留 3 / P-21 遗留 4），只能人工 + 记录制的脚本化预验（`tmp/`，已 gitignore）。
