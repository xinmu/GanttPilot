### P-36 G7 的落地口径、实测数字与出口条件判定

**落地面（三层，逐层都有判据）**：

| 层 | 落点 | 判据（进 `pnpm gate`） |
|---|---|---|
| 几何 / SVG / 摘要 | `packages/render-core` 的 `exportView.ts` / `svgExport.ts` / `exportSummary.ts` | `export.spec.ts`（**19 例**）：全量渲染、`contentWidth` 不被视口宽抬升、等比适配 + 贴边、SVG 逐值同源、无交互图元、两次逐字符一致、图例/摘要与适配同源、完成率与引擎 `summaryProgress` 互证、可读性阈值与提示分档、**两组负向对照** |
| PPTX 模板 A | `packages/pptx-renderer` 的 `units.ts` / `ooxml.ts` / `template.ts` / `fingerprint.ts` + [`PPTX.md`](../../packages/pptx-renderer/PPTX.md) | `template.spec.ts` + `index.spec.ts`（**13 例**）：`p:sldSz` 与声明一致、id 全树唯一、锚点站点合法且指向存在的形状、一级组 `chOff/chExt` 与 `off/ext` 等比、**无 `cxnSpLocks`**、golden 逐字节、**四组负向对照**、降级② `custGeom`、可读性纪律（1,000 行不画标签） |
| 应用接线 | `apps/web` 的 `useExport.ts` + `Toolbar.vue` + `App.vue` | `smoke:build`（打包产物）：导出面板存在、**首屏主 chunk 不含 pptxgenjs**、**真的点三次导出**并校验落盘文件（SVG 内容/PNG magic/PPTX zip magic） |

**实测数字（记录制；口径与数字一起读）**：

1. **模板 A 产物（Node，`scripts/export-pptx.mjs`）**：演示计划 · week 档 **14,929 字节**、
   sha256 `7edabe9fe8993dc78cfda76dc600d7854e1e0bdb3cf7f1e082400a3a7cf927d1`；**两次导出逐字节一致**
   （day / week / `--degrade` 三档均 `twoRunIdentical: true`）。文档 15 行 / 14 依赖。
2. **WPS 真机（产品产物，[报告](../../packages/pptx-renderer/evidence/template-a-demo-wps.md)）**：
   **两次独立冷开均无修复弹窗**（slides=1）；`Slide.Export` 出 1600×900 PNG（127,413 → 拖动后 127,692 字节）；
   `SaveAs` 另存成功（19,868 → 20,080 字节）；另存后 **`stCxn`/`endCxn` 各 14 条全存活**、
   **14/14 条 connector 的端点（归一到形状名）逐条一致**；`cxnSpLocks` 补丁 0 处 ⇒ WPS 0 处；
   **拖动 `bar-t1`（L/T 各 +120）后 `dep-l1` 的 `Δoff.x=144288`、`Δoff.y=216887`、`dep-l2` 的 `Δoff.x=650247`**，
   且 preset 由 `bentConnector3` 变为 `bentConnector5` 并带 `flipH/flipV/adj` ⇒ **不是平移，是重新走线**。
3. **浏览器（打包产物，进 `pnpm gate`）**：入口 chunk **189.54 kB**，`pptxgenjs` 单独成 chunk
   **272.63 kB**（gzip 94.70 kB）⇒ 导出库**不进首屏**；`smoke:build` 真的驱动控件导出
   SVG/PNG/PPTX 三件产物并逐件校验（这是"浏览器里点下去能不能出文件"的唯一判据）。
   `pnpm gate` 全绿：**53 spec / 761 例**（本轮 **+2 spec / +31 例**：`export.spec.ts` 19 +
   `template.spec.ts` 8 + pptx-renderer 入口面 4）。

**落地期抓到并修掉的真缺陷（1 条，值得记）**：

- **`normalizePptx` 用了 JSZip 的 `nodebuffer`**：Node 侧 13 条结构/golden 判据全绿，
  而在**浏览器**里 `nodebuffer` 不可用（它依赖 Node 的 `Buffer`）⇒ 打包产物里点"导出 PPTX"没有任何文件。
  修法：全链路改用 `uint8array` + `TextEncoder`/`TextDecoder`。
  *这条正是 P-9/P-17 分层要抓的东西：Node 侧判据**结构上**覆盖不到"浏览器里这个类型存不存在"，
  而 `smoke:build` 的端到端点击当场抓到。*

**两条实测发现（留给后续，不改本轮实现）**：

1. **模板 A 的任务条在真 `p:grpSp` 里**，因此 WPS 的顶层 `Slide.Shapes` **不列** `bar-*`
   （顶层只有文本框 + `grp-s1/2/3` + `dep-*`）。取证与人工复验都必须"进组"（脚本用递归 `GroupItems` 的
   `Get-WpsShapeByNameDeep`）；**产品化建议**：把"进组"这层补进 S1 的 `wps-common.ps1`（本轮未动它）。
2. **`Pres.SaveAs(x)` 之后 WPS 仍持写锁**：不能"另存后立刻解包副本"（实测 `used by another process`）。
   取证脚本因此改成**两次会话**（冷开 → PNG → 另存 → 关 WPS → 解包），副产品是"打开无修复"验的是两次冷开。
   字节层事实同时记录：WPS 另存后 `slide1.xml` 字节不同（41,151 → 39,813 字符，`<p:cSld name="Slide 1">` 的 name 被丢、
   空白被规范化），但**结构计数逐项一致**；包内条目 20 → 22（新增 `docProps/custom.xml`、`ppt/theme/theme2.xml`）。

**出口条件逐条判定**（路线图 G7；证据分层见 [PPTX.md §七](../../packages/pptx-renderer/PPTX.md)）：

| # | 出口条件 | 判定 | 依据 |
|---|---|---|---|
| ① | SVG 与 PNG 导出与屏幕所见一致（几何同源，非截屏） | **通过** | 门禁：`export.spec.ts` 的逐值同源 + 两组负向对照；记录制：`smoke:build` 真的导出 SVG/PNG 并校验 |
| ② | WPS 打开无修复弹窗；任务条/里程碑为原生形状 | **通过（COM 口径）** | 两次独立冷开无异常；条 = `roundRect`、里程碑 = `diamond` preset（结构断言 + WPS 打开） |
| ③ | WPS 中拖动任务条，connector 端点跟随（G1-a 的产品化验证） | **通过（COM 自动化口径，P-4 认可）**；**人工真机拖动待维护者复验** | 拖动后 `dep-l1`/`dep-l2` 的 `xfrm` 重算 + preset 变化；人工复验时注意"任务条在组里，需先进 `grp-s1`" |
| ④ | group 坐标正确（父子分组无偏移、无修复弹窗） | **通过** | 门禁：`chExt == ext`、组内含正确子集合、非等比必被检出；记录制：WPS 打开另存后形状集合与锚点逐条存活 |
| ⑤ | 模板 A 可重复生成：同一文档两次导出结构一致（golden 比对） | **通过（字节级）** | `template.spec.ts` 逐字节相等 + `scripts/export-pptx.mjs` 三档 `twoRunIdentical: true` |
