## 第五十一轮：门禁步骤顺序修正

| 项 | 内容 |
|---|---|
| 裁决 | **P-53**：采"**改序**"方案——`scripts/gate.mjs` 的 `STEPS` 把 `build` 由第 4 位**提到第 2 位**（紧随 `lint`）、`typecheck` 顺延为第 3 位；`.github/workflows/ci.yml` 同步把 `Build` 提到 `Typecheck` 之前 |
| 依据 | 远端 CI **首次真实运行**即在 **Typecheck** 一步失败（job 计时 20 秒），而**同一条 `pnpm typecheck` 在本地是绿的**；根因：`dist/` 不入库（`.gitignore`），而消费者的类型检查经包清单的 `types`/`exports` 解析工作区依赖 ⇒ **干净检出上 `typecheck` 跑在任何 `.d.ts` 存在之前**。故障形态与最小复现见 [0001-增补 §1.1–§1.3](../02-adr/附录/0001-增补.md) |
| 产出 | `scripts/gate.mjs`、`.github/workflows/ci.yml`、[0001-增补 §1](../02-adr/附录/0001-增补.md)、[ADR 0001 正文](../02-adr/0001-本地质量门禁与零框架依赖护栏.md) 的「相关裁决」补登、本文件、台账行 `P-53` |
| 语义 | **不变**：「推送前必须全绿」的硬门槛、三条零框架/零 DOM 铁律、许可审计的两种口径**一处未改**；改的只是**次序** |
| 代价（明确接受） | 最贵的一步（构建）提前 ⇒ 机械性错误的暴露**晚于**构建；整链耗时增加（秒数只登记在记录层，**不写进契约**） |
| 同批订正 | 正文里两处与事实不符的陈述按实况改写：① `ci.yml` 并非"跑同一条 `pnpm gate`"（它**弱于** `pnpm gate`，差集见 [登记与本轮不做](../04-refactor/05-登记与本轮不做.md) §二）；② 该文件"未经真实运行验证"已不成立（2026-10-06 真实运行并失败） |
| 待定 | **无新增未决项**；[待定清单](../01-roadmap/首版-待定清单.md) 继续为空 |
| 本轮不做 | ① 把 `ci.yml` 收敛成"直接调用 `pnpm gate`"（需 runner 具备无头 Chrome，且离线单文件两步在 `ubuntu-latest` 上可用）；② `ci.yml` 的 Node 版本与本地收敛。两者未定 ⇒ 仍是**人工维护的不变量**：改 `STEPS` **必须**同步 `ci.yml` |

### 回归判据

`STEPS` 里 `build` 必须**早于** `typecheck`；等价的最小检查是
"**删掉全部 `dist` 之后 `pnpm gate` 仍全绿**"（即门禁对干净检出是自洽的）。

> **为什么改序、而不是让类型检查不依赖产物**：给消费者包加 `tsconfig` 的 `paths` 指向源码，会让类型检查
> 对着**源码**而不是**发布出去的声明文件表面**判定，从而丢掉"发布出去的 `.d.ts` 是否真的够用"这一条；
> 而 `exports`/`types` 本身就是已冻结的契约面。改序保留该判定，代价只是次序。
