## 第五十二轮：必读层的口径与预算调整

| 项 | 内容 |
|---|---|
| 裁决 | **P-54**：① 把「必读」的**口径**明确为 **台账的登记本体（条目表 + 未决摘要）+ 当前规划 + 待定清单**；② `contextBudget.mustReadKb` 由 **25 → 34** |
| 依据（实测，D7.5 迁移后） | 台账登记本体 **18.9 KB**（移出「轮次导读」后）+ [当前规划](../01-roadmap/首版能力顺序.md) **12.0 KB**（已是 ≤12 KB 的目标态）+ [待定清单](../01-roadmap/首版-待定清单.md) **1.2 KB**（只承载未决）⇒ **实测下限 32.0 KB**。原 25 KB 是决策 2 的**建议值**，给定时台账还没有 66 条条目、也没有分轮次存档的规模 |
| 为什么不是"砍台账" | 台账的**条目表就是登记本体**（66 条、一行一条、结论 ≤80 字），砍它等于砍登记。**可推导/历史的部分本轮已全部移出**：`轮次导读`（52 行）→ 生成物 [轮次导读](轮次导读.md)（由按轮次存档的 `## 第N轮` 标题 + 台账「轮次」列推导）；`已闭结转行`（22 行）→ [首版-记录-待定清单](../01-roadmap/首版-记录-待定清单.md)（记录层）。两项合计 **19.3 KB** 的移出，是 34 KB 这个数的前提 |
| 上限取值 | **34 KB** = 实测 **32.0** + 约 **11 条台账条目**的余量（条目与轮次线性，每条 ≈0.18 KB）。**这不是"提高上限掩盖膨胀"**：本轮的体量增长是**登记量**（66 条裁决）而非冗余，冗余部分已按"拆分或迁移"处理 |
| 明确不做 | ① **不砍台账条目表**；② **不把当前规划 / 待定清单移出必读**（判定层与未决住所必须在注入包里）；③ **不改任何既有条目的结论列** |
| 待定 | **无新增未决项**；[待定清单](../01-roadmap/首版-待定清单.md) 继续 **0 条** |

### 本次口径调整的两条纪律（沿用 [DOC-SPEC](../DOC-SPEC.md) §4.1 第 5 条）

1. **降低必读体量的动作永远优先于调上限**：先"拆分或迁移"（本轮移出 19.3 KB 的可推导与历史内容），
   再按**实测下限**重设上限；
2. **上限必须由实测推导、并在裁决里写明构成**（本条即范例：18.9 + 12.0 + 1.2 = 32.0 ⇒ 34）。
