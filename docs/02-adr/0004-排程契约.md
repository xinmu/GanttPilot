## 背景

G2 是首版卖点本体：条形位置、连线端点、SVG/PPTX 坐标**全由它推导**（裁决 P-1 / T-3 修正）。
它同时是 **G3**（导入后出图）、**G4**（几何与裁剪）、**G7**（双投影）的公共输入 ——
因此它的形状必须**一次冻结**，否则三个下游会各自推一遍，"唯一排程真相源"在渲染层就被破。

S3 已把下面这些面**定完并实测**（[S3 结论 §八](../../spikes/g0-s3-cpm-perf/结论.md)）：
数据布局（CSR 邻接 + 类型化数组）、算法（Kahn 检环 + 正向/逆向两趟）、
日期承载（工作日序号，日历不进热路径）、容量扩容（地平线不足时 2× 重建）、
验证基建（不变量 / 手工用例 / 跨语言差分 / 计时骨架）与 DoD 数值（全量 p99 ≤ 1 ms；
**该数值的"在哪跑"与断言口径由 [附录细则 §1](附录/0004-增补.md) 于 P-38 修订为
"p50 ≤ 1 ms 且 p99 ≤ 2 ms"——数值不变，拆成两条各管一件事**）。

**但 S3 的模型里没有"锚点"这一层。** `spikes/g0-s3-cpm-perf/src/model.ts` 的 `Schedule` 只有
ES/EF/LS/LF/浮动/关键，**无前置任务一律从序号 0 起算**，`clampedStarts` 只是"0 截断"的计数。
而文档里有日期（DM-02），G1.2 还明确留了两处"归 G2 解释"的诊断
（`TASK_DURATION_WITHOUT_DATES`、`LINK_SUMMARY_ENDPOINT`）。也就是说：

> **"文档日期如何进入传播"是 G2 唯一没有被 spike 覆盖的设计面**，也是本 ADR 的主要对象。

契约的先例：ADR 0002 §8 让"日历校验直接调用 `Calendar` 构造器"、ADR 0003 §4 让命令层直接复用
`validateDocument` —— **同一类事实只能有一个实现**。本 ADR 沿用该手法：排程侧的汇总端点语义
**直接对齐 G1.2 已发布的 `LINK_SUMMARY_ENDPOINT` 诊断**，不新造一套规则。

## 决策

### 1. 输入形状 `compute(document, calendar, anchors?)`；`constraints` 与 `manual` **不进签名**

```ts
/** 会话内锚点（G5 的拖拽"允许 + 标红"）：taskId → 工作日序号。不进文档、不落盘。 */
interface SessionAnchor {
  readonly taskId: string;
  readonly startOrdinal: number;
}

function compute(
  document: ProjectDocument,
  calendar: Calendar,
  anchors?: readonly SessionAnchor[],   // v0.1 唯一的可选入参
): ScheduleResult;
```

**理由**：

- EN-06 的原文签名含 `constraints`，但 DM-08/DM-09 的语义已按 R-3 推到 v0.5。
  **把未启用的语义写进公共签名，只会得到"测了但没有语义"的死条目**；
- v0.5 的接入点已由 §2 的**锚点解析独立成步**隔离：约束 = 锚点的另一种来源、手动模式 = 锚点的一种来源。
  这正是 [评估报告 G-3/G-4（立项期依据）](../00-baseline/评估报告.md) 要求的"P0 引擎结构不得被 P1 推翻"；
- 文档里 `constraints` 非空或 `manual === true` 时，由**适配层**给出诊断（`constraintsUnused`），
  而不是让内核带着一个空分支跑。

**代价**：v0.5 要扩一次签名（**加可选参数**，不改数据布局、不改 `Schedule` 形状）。明确接受。

### 2. 锚点规则：**前置优先**（自动任务的文档日期是"用户输入缓存"，不是排程结果）

按任务分四类（汇总任务除外，见 §3）：

| 情形 | 排程语义 | 诊断 |
|---|---|---|
| ① 无前置、有日期 | `ES = 文档 startDate 的序号`（锚点） | — |
| ② 无前置、无日期 | `ES = 项目起点`（§4；DM-05 容错） | `undated`（warning） |
| ③ 有前置 | `ES = max(全部入边约束)`，**文档日期被忽略** | `dateOverridden`（warning，仅当与文档日期不同） |
| ④ 有前置**且被会话锚定** | `ES = max(锚定序号, max(入边约束))` | 锚定早于入边约束时 `anchorConflict`（warning） |

- **为什么选"前置优先"**：与 D-4 已定的 **MS Project 惯例**一致；"下游跟着动"这条主叙事在**所有图上**成立
  （备选的全任务锚定在"文档日期比推导更晚"的常见脏数据上会让前置提前不带动下游）；
  导入的常见结构（日期与依赖自洽）在此规则下**零感**；
- **代价与弥补**：推导覆盖用户手填日期，所以 `dateOverridden` 是**必须**的（G3 导入报告与 G5 冲突标记共用同一码表）；
- **会话内锚点（情形④）**：IX-05 已裁决"默认吸附 + 可切换允许并标红"。选"允许"时，用户拖到的位置必须有地方存，
  否则下一次传播会把它推回去。v0.1 不引入 `manual`/`constraints` 的语义，因此锚点走 `compute` 的 `anchors` 入参：
  **它是会话状态、进命令日志、不进文档序列化**（`compute` 绝不修改入参）。未知 `taskId` → `anchorUnknown` 诊断；
  > ⚠️ **形状是否扩展已裁决为「不扩」**（[P-45（历史裁决）](../00-baseline/裁决R44.md)）：
  > `resize-duration` 拖动期"下游也所见即所提交"**不需要**把工期塞进锚点——它由应用层把
  > **未提交文档副本**喂给 `compute` 的**第一个入参**承担（`SessionAnchor` 一字未改）。
  > 理由：锚点**不落盘**（[ADR 0009](0009-持久化契约.md) §6）⇒ 扩形状没有跨会话收益；
  > 而本条下面的 v0.5 计划会**重做锚点解析**，届时多一个"只服务渲染的字段"是纯负担
  > （与本节 §1 拒绝把 `constraints` 写进签名的理由同族）。机制见
  > [ADR 0008 附录细则 §3](附录/0008-增补.md)。**v0.5 重做锚点解析时若要重新考虑扩形状，须先撤销本指针。**
- **排程结果不写回文档**（回答 [ADR 0003](0003-命令层与事务契约.md) §影响与 [SCHEMA.md](../../packages/engine/SCHEMA.md) §五 的开放项）：
  文档只存输入，`Schedule` 永远是派生值。于是撤销只需回退**输入 + 会话锚点**，命令层不需要为级联引入新形状
  （ADR 0003 §6 已刻意避免复合命令）；
- **导出（G3）写排程结果**：这是本决策的直接推论——导出的 Excel 与甘特图一致，
  且"导出 → 再导入"得到同一 `Schedule`（自往返幂等，属 G3 的验收项，见第二轮待定项 #3）。
  文档内的 `startDate` 对情形③**保持"用户输入"语义不变**（引擎从不改写文档）；
  > ⚠️ **本条的"写排程结果"部分已被订正**（裁决 P-14 / [ADR 0006](0006-xlsx-协议契约.md) §3：
  > 导出写**文档数据**，一致性判据改为 `compute()` 深比较）——详见本文件 §影响 的 G3 行。
- **`endDate` 是派生显示值，工期为准**：文档 `endDate` 与「`startDate` 起算 `durationDays` 个工作日」
  不一致时只给 `info`（`endDateStale`）——**不报错、不改写**（校验从不改写文档，ADR 0002 §3）。

### 3. 汇总任务 = 派生；里程碑 = 工期 0 且**参与**传播

- **汇总任务 = 有子任务的任务**（`hasChildren`），**不参与排程**：其日期/进度/工期由子树聚合；
- 依赖边端点是汇总任务时：**保留 G1.2 已有的 `LINK_SUMMARY_ENDPOINT` 为 `warning`、不升级为 `error`**
  （否则要改已冻结的校验行为，且与"校验只报告、从不改写"的口径冲突），
  并且该边**在传播中被忽略**（等同不存在），排程侧产出同名诊断 —— **同一事实只有一个实现口径**；
- **里程碑（`milestone: true` / `durationDays === 0` 的叶子任务）照常参与传播**：它是 US-2"里程碑威胁可见"
  与 G7"里程碑清单"的对象，不是装饰；
- 派生值由**引擎**产出（不是渲染层）：汇总条的起止、汇总进度、里程碑计数若让 G4 与 G7 各算一遍，
  唯一真相源就破了。

### 4. 项目起点、负 lag 越界与 `clampedStarts`

**项目起点**（三级回落）：

1. `project.startDate` 非空 → 它的工作日序号；
2. 否则 → 全部**锚点序号**的最小值；
3. 全无日期信息（空项目/全无日期）→ `Calendar.baseDay`（序号 0，退化情形）。

> **不变量**：起点**不得**由日历的容量参数（`baseDay`、地平线长度）决定，**除非**文档完全没有日期信息。
> 否则"挪动文档日期"会改变截断结果，golden 与差分比对会因容量差异**假失败**
> （与 [S3 §八 第 10 条](../../spikes/g0-s3-cpm-perf/结论.md) 警告的 `dayOfOrdinal(k)` 语义是同一个坑）。

**负 lag 越界**（[S3 §五.4](../../spikes/g0-s3-cpm-perf/结论.md)）：`ES < 项目起点` 时
**截断到项目起点** + **计数 + 诊断**（`clampedStart`，含 `taskId`）——
**不阻断排程、不改写文档、不产出负序号**（负序号在 G1.1 已定为无定义）。

**理由**：v0.1 没有浮动的消费者（EN-01/02/03 延后 v0.5），"允许负数序号"等于在没有验收标准时
把负浮动的定义提前定死；而"拒绝文档/拒绝该边"与 G-3 的"约束不阻断排程"惯例相反 ——
用户在 Excel 里写一个 `FS-3`，不该炸掉整次导入。诊断进入 G3 的问题清单（G-8）与 G5 的冲突标记。

### 5. `Schedule` 形状（**序号承载**）

```ts
interface Schedule {
  readonly taskCount: number;

  // —— 序号空间（工作日序号；负序号无定义）——
  es: Int32Array;                      // 叶子任务：第一个工作日序号
  ef: Int32Array;                      // 排他结束序号 = es + duration
  anchored: Uint8Array;                // 1 = 位置由锚点决定（§2 情形①②④）
  driven: Uint8Array;                  // 1 = 文档日期被推导覆盖（§2 情形③）

  // —— 汇总任务派生值（叶子任务为 -1）——
  summaryEs: Int32Array;               // 子树 ES 最小
  summaryEf: Int32Array;               // 子树 EF 最大
  summaryProgress: Float64Array;       // 子树工期加权进度；权重为 0 时为 NaN

  readonly milestoneCount: number;     // G7 模板 A 的摘要用
  readonly projectStart: number;       // 项目起点序号（§4）
  readonly projectFinish: number;      // max(ef)

  readonly clampedStarts: number;      // 计数，与 clampedStart 诊断同源
  readonly diagnostics: readonly Diagnostic[];
}
```

- **只出序号**：ISO 由 `Calendar.isoOfOrdinal` 翻译（G4/G7 各自调用）——
  `Calendar` 是**唯一**的序号 ↔ 日期翻译器（G1.1 已冻结）；
- **`computeInto` / 预分配复用**按 [S3 §八 A.3](../../spikes/g0-s3-cpm-perf/结论.md) 保留（热路径零分配），
  但**公共 API 只暴露纯函数形态**，复用缓冲是实现细节；
- **诊断码表（v0.1）**：`undated`、`dateOverridden`、`clampedStart`、`anchorConflict`、`anchorUnknown`、
  `summaryIgnored`（对齐 `LINK_SUMMARY_ENDPOINT`）、`endDateStale`、`constraintsUnused` ——
  以上全部 `warning`/`info` 级；**`cycle` 是唯一的阻断级**，且不产出排程（§6）；
- **确定性**：同一文档 + 同一 `anchors` → 同一 `Schedule`；**绝不修改入参**（`document` 与 `calendar` 只读）。

### 6. 检环 API 与失败形状

- `compute` 遇成环：**不产出排程**，返回失败结果（成环路径的任务 id 序列）——DM-04/EN-05；
- **建边预检**（G5 的即时反馈、G3 的导入丢弃）：

  ```ts
  function wouldCreateCycle(
    links: readonly DocumentLink[],
    candidate: DocumentLink,
  ): { readonly cyclic: boolean; readonly path: readonly string[] };
  ```

  **返回路径而不是布尔**：G-7 已裁决"高亮成环路径"，而算路径必须用图的内部表示（CSR 是唯一真相源）——
  让 G5 自建图会使真相源分叉；
- **导入的成环边丢弃 + 进问题清单**（G-7 已裁决的行为）发生在 **G3**；本契约只提供判定与路径；
- **交互契约**（是否允许"强制建边"、文案、高亮样式）留 **G5 开工前**定，**不阻塞 G2**。

### 7. 容量、地平线与扩容

- 序号空间由 `Calendar` 的地平线界定；容量按 `horizonDaysFor(Σ工期 + Σ正 lag)` 规划（G1.1 已冻结），
  不足时 `withHorizon(2×)` 重建重算（[S3 §八 C.11](../../spikes/g0-s3-cpm-perf/结论.md)）；
- **扩容必须对调用方不可见**：同一输入无论是否触发扩容都得到同一结果。
  单测口径照 G1.1 的成例（"先抛错、扩容后与直接构造大窗口逐项相同"）。

### 8. 范围：只交**全量**传播 + 受影响闭包查询（增量移出 v0.1）

- 依据裁决 P-12 第 2 条：全量重算最差 p99 = **60.3 µs**（P-6 / S3），对 G5 的"引擎侧 ≤ 1 ms/帧"
  有约 **16×** 余量；深链上增量与全量本就同阶（13.7 µs vs 22.8 µs）——
  **v0.1 没有需要增量算法的场景**；
- 但 G5 的"不做整表重建"需要一个**纯结构**查询：

  ```ts
  function affectedClosure(document: ProjectDocument, taskIds: readonly string[]): readonly string[];
  ```

  （迭代 DFS 收集后继闭包，同一份 CSR。）它**只断言结构性事实**（闭包规模、深链覆盖全图），
  **不加时序门禁** —— 会抖动的 p99 断言只制造假失败（照 G1.2 的 `documentPerformance.spec.ts`
  与 [ADR 0003](0003-命令层与事务契约.md) §8 的成例）；
- **增量传播**（闭包内逆后序重算）**移出 v0.1**：若 G5 的浏览器实测整帧不达标再引入，届时以实测为依据。
  [S3 §八 B.7](../../spikes/g0-s3-cpm-perf/结论.md) 按此映射解读（**证据层不改写，映射由裁决 P-12 承担**，
  同 P-10 第 3 条的手法）。

### 9. 验证策略与门禁（R-4 落地）

| 层 | 内容 | 门禁判据 |
|---|---|---|
| ① 不变量 / 性质 | `EF = ES + duration`、四类关系边界方程、lag 传递性、`anchored`/`driven` 与文档日期的一致性、汇总值 = 子树聚合 | 随机 ≥ 1,000 图全过 |
| ② 手工推导用例表 | 4 关系 × lag（正/负/0）× 跨层级 × 日历例外 × 无日期节点 × 汇总端点 | 逐条声明式期望值 |
| ③ 跨语言差分 | 与独立 Python 参照实现逐字段比对（S3 的 `reference/cpm_reference.py` + 文件式 IPC） | ≥ 1,000 图 + 200 成环图，**0 不一致** |
| ④ 性能 | 1,000 任务 / 1,500 依赖全量传播 **p50 ≤ 1 ms 且 p99 ≤ 2 ms**（EN-08 的 100 ms 保留为产品侧不回归天花板；口径于 [附录细则 §1](附录/0004-增补.md) 由 P-38 修订：中位数管"实现退化"、尾部管"并行争用"） | Node 24 参照机 |
| ⑤ 负向对照 | 正确性侧（打坏期望值 / 语义必须被检出）与性能侧（已知更慢的实现必须被量出差别） | **必须有**，否则判据可能是恒真式 |

**资产归宿与 CI 口径（裁决 P-12 第 6 条）**：

- 参照实现落 **`tools/cpm-reference/`** —— `engine` 包内**不放非 TS 资产**（与三包的边界规则一致）；
- 差分测试**进 `pnpm gate`**；**缺 Python 3 时该步失败，而不是跳过**
  （"全绿为合并硬门槛"不得被静默跳过破坏）。Windows 上 `python` 可能是 `.bat` 垫片、
  `spawnSync` 返回 **9009** 而非 `ENOENT` —— 必须显式处理（[S3 §五.7](../../spikes/g0-s3-cpm-perf/结论.md)），
  静默跳过是**实测过的真实风险**，不是理论风险；
- 随机**种子固定**，且种子随失败信息一起打印（否则复现失败要靠猜）。

## 备选方案与为何未采用

| 方案 | 未采用原因 |
|---|---|
| **全任务锚定**：`ES = max(文档日期, 入边约束)` | 与 D-4 的 MS Project 惯例相反；且在"文档日期比推导更晚"的常见脏数据上会**让"推迟下游"这条主叙事失效**（前置提前不带动下游） |
| 有前置任务也以文档日期为准 | 等于依赖不约束日期，传播内核失去意义（首版卖点空洞） |
| 显式 per-task 锚定开关（`manual` / `constraints`） | R-3 已把语义推 v0.5；v0.1 只做**会话内锚点**（不进文档） |
| 排程结果写回文档 | 文档被派生值污染：往返、命令日志、导出三处都要处理"缓存 vs 输入"的分叉；G5 的撤销单元会膨胀为级联形状 |
| 允许负序号（负浮动的雏形） | EN-01/02/03 延后 v0.5，v0.1 无消费者；提前定死"浮动"的定义而没有任何验收标准 |
| 负 lag 越界直接拒绝文档 / 拒绝该边 | 与 G-3"约束不阻断排程"的惯例相反；Excel 里一个 `FS-3` 不该让整次导入失败 |
| 汇总任务独立参与传播 | 同一事实两个真相源（自身日期 vs 子树聚合），且与 G1.2 已发布的 `LINK_SUMMARY_ENDPOINT` 文案矛盾 |
| 汇总端点升级为 `error` | 要改已冻结的校验行为，且与"校验只报告、从不改写"（ADR 0002 §3）冲突 |
| `constraints` 进 v0.1 签名（收下但忽略） | 公共签名里出现"测了但没语义"的死条目；接入点已由 §2 的锚点解析隔离，不需要靠签名占位 |
| 增量传播进 G2 出口条件 | 已达标（全量 p99 60.3 µs ≤ 1 ms，16× 余量）；为一个达标指标增加实现面与门禁面 |
| 检环只返回布尔、路径由 G5 自算 | G5 需复建图，图表示出现两个真相源（G-7 已要求"高亮成环路径"） |
| 差分测试"缺 python 则跳过" | 破坏"全绿为合并硬门槛"；且 Windows 上缺 python 表现为退出码 9009，静默跳过是实测风险 |
| 纯 JS 第二实现（不引入 Python） | 放弃跨语言差分这一最值钱的正确性证据（两侧同时犯同一语义错误的概率显著更高） |
| 给闭包 / 增量加时序门禁 | 会抖动的断言只制造假失败；结构性事实（闭包规模、`driven` 集合）同样有判别力 |

## 影响

- **G2**：本 ADR 是**开工前置**；G2 内不再做设计决定，出口条件含"实现与 ADR 0004 一致"。
- **G3**：导入后直接接 `compute` 得到可渲染的 `Schedule`；成环边丢弃 + 诊断清单
  （`cycle`/`clampedStart`/`undated`/`dateOverridden` 共用码表）。
  > **订正（裁决 P-14 / [ADR 0006](0006-xlsx-协议契约.md) §3）**：本行原写的"**导出写排程结果**"
  > 已被取代——导出写**文档数据**；"与甘特图一致"的判据改为"把导出物重新导入后
  > `compute()` 逐字段深比较相等"。理由：排程结果写进文件后即为文档日期，会被锚点情形③推导覆盖
  > 并报 `dateOverridden`，使"自往返幂等"取决于"导出的是哪一次 `Schedule`"。
  > **本 ADR 的其余冻结内容不变**（原文不改写，订正由 P-14 承担）。
- **G4**：几何只读 `Schedule` 的**序号** + `Calendar` 翻译；汇总条与里程碑读**引擎派生值**，不自己聚合；
  `affectedClosure` 支撑"不做整表重建"与缓存失效（与 ADR 0003 §影响 的 `journalScope` 同源）。
- **G5**：IX-05 的"允许 + 标红"由**会话锚点**承载（`compute` 的 `anchors` 入参）；
  一次手势 = 一次 `compute` + 一条命令/一个事务；检环路径由 `wouldCreateCycle` 提供。
- **G6**：持久化的是**文档 + 命令日志**（§2：排程结果不入文档）；**会话锚点是否跨会话恢复留待 G6**
  （与 R-2 的 L2/L3 一起定）——若不做，需在 README 已知限制中写明"钉住的位置重开不保留"。
- **G7**：双投影共享 `Schedule` 几何，导出物与屏幕所见一致（几何同源）；模板 A 的摘要读 `milestoneCount`
  与 `summaryProgress`。
- **明确延后（v0.5+）**：LS/LF、总浮动/自由浮动、关键路径（EN-01/02/03）；`constraints`/`manual` 语义（DM-08/09）；
  增量优化；Worker 化；多日历（R-1）。
- **新增依赖**：**运行时零依赖**；开发侧新增 **Python 3** 前置，**仅**门禁的差分步骤需要（裁决 P-12 第 6 条）。
- **落地期的口径补齐**：G2 实现时发现本 ADR 未写明的口岸（`ScheduleResult` 形状、文档序索引与 `-1` 哨兵、
  工期解析优先级、项目起点第②级取哪些日期、有效图 vs 结构图的两种口径、容量规划入口、两处有意抛出等），
  全部落 [ADR 0005](0005-排程内核落地补齐与结果形状.md)；**本 ADR 的冻结内容一字未改**。
- **不改动**：文档形状（G1.2 已冻结）、命令层形状（G1.3 已冻结）、`Calendar` 的公共 API（G1.1 已冻结）。
