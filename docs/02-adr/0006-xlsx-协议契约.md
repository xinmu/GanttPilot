## 背景

G3 是「**字节流 ↔ 文档**」的双向协议：把用户手里的 xlsx 解析成 `ProjectDocument`，把文档写成规范的 xlsx。
S2 已经把"能不能"回答完了（可见列自足 + ExcelJS 读写成立、WPS 两种往返逐字段相等），
剩下的风险**全部是口径**：同一份需求存在两种以上都说得通的实现，而下游（G4/G5/G7/G8）会各自引用。

本 ADR 的作用与 [ADR 0004](0004-排程契约.md) 对 G2 的作用相同：**把形状与语义在开工前冻结，G3 内不再做设计决定**。
契约若需变更，追加 ADR 并同步 [首版能力顺序 §三 G3](../01-roadmap/首版能力顺序.md)。

三条先行约束（S2 实测，**硬性**）：

1. **日期必须用 `Date.UTC(y, m-1, d)` 构造**（本地零点构造会写出带小数的序列号，Excel 显示**前一天**——本仓库已三次复现）；
2. **不能比对数字格式码的文本**（WPS 会把 `yyyy-mm-dd` 转义为 `yyyy\-mm\-dd`），只判"是否日期格式"；
3. **不能依赖部件哈希、`styles.xml` 体积、zip 条目顺序、`alignment.indent` 取值**（WPS 会重写整个容器）。

## 1. 契约边界：协议层交什么，不交什么

- 本块只交 **`@ganttpilot/xlsx-protocol` 的纯函数**：字节流 ↔ 文档、列探测、结构化诊断；
- **不交任何 UI**：列映射向导、拖拽导入、下载与打开文件的对话框都在 `apps/web`；
  协议层**不接触 DOM**（"三包零框架、零 DOM"铁律不变），文件 I/O 与 Blob 构造由调用方负责；
- 协议层**不渲染、不排版、不算排程**；`Schedule` 由调用方用 G2 的 `compute()` 得到。

**公共 API（形状冻结，命名可微调但语义不可变）**

```ts
import type { Calendar, ProjectDocument, DocumentDiagnostic } from '@ganttpilot/engine';

/** 导入：字节流入，文档 + 问题清单出。绝不抛错报告用户级问题。 */
function importXlsx(
  bytes: Uint8Array | ArrayBuffer,
  options?: ImportOptions,          // 列映射（向导第 2 步）、sheet 选择、日历规格
): ImportResult;

/** 导出：文档入，字节流出（规范化：规范列序 / 规范日期 / 规范依赖语法）。 */
function exportXlsx(document: ProjectDocument): ExportResult;

/** 列探测：给向导第 1–2 步用（识别了哪些列、还差什么、建议映射）。 */
function detectColumns(
  bytes: Uint8Array | ArrayBuffer,
): ColumnDetectionResult;

type ImportResult =
  | { readonly ok: true;  readonly document: ProjectDocument; readonly diagnostics: readonly XlsxDiagnostic[] }
  | { readonly ok: false; readonly diagnostics: readonly XlsxDiagnostic[] };

type ExportResult =
  | { readonly ok: true;  readonly bytes: Uint8Array; readonly diagnostics: readonly XlsxDiagnostic[] }
  | { readonly ok: false; readonly diagnostics: readonly XlsxDiagnostic[] };

/** 协议层诊断：与文档侧/排程侧同形，多一个"定位"维度。 */
interface XlsxDiagnostic {
  readonly code: XlsxDiagnosticCode;              // 闭集，见 §7
  readonly severity: 'error' | 'warning' | 'info';
  readonly message: string;
  readonly locator?: {
    readonly sheet: string;                       // 工作表名
    readonly row?: number;                        // 1 基，与 Excel 行号一致
    readonly column?: string;                     // 规范列名（如 '前置任务'）
    readonly address?: string;                    // A1 形式（如 'F12'），便于直接跳转
  };
  readonly taskId?: string;                       // 已落到文档里时带上
}
```

**字节口径**：入参接受 `Uint8Array | ArrayBuffer`；**出参一律是 `Uint8Array`**。
两者都不使用 Node 的 `Buffer` 类型——三包不引入 `@types/node`，`Buffer` 不得出现在公共签名里（它是 `Uint8Array` 的子类，调用方传入天然兼容）。

**"问题清单"只有一个数组**：最终展示给用户的清单 = 协议诊断 + `validateDocument` 诊断 + `compute` 诊断**三层拼接**，
UI 只认一个有 `severity` 的数组。协议层不合并、不重写另两层的码（[ADR 0005](0005-排程内核落地补齐与结果形状.md) §10 的同一手法）。

## 2. 列契约（规范工作表形态）

- **单工作表**，表名 `任务`（可见；**无影子表、无隐藏表**——T-2 已删除 `__gantt_meta__`）；
- 首行表头，**9 列规范列序**（导出固定此序；导入按列名匹配，不要求列序相同）：

| # | 表头 | 必需性 | 导出形态 | 语义 |
|---|---|---|---|---|
| 1 | `WBS` | **与缩进式二选一**（见 §6） | 文本 `1` / `1.2` / `1.2.3` | 层级来源；每段为十进制整数，无前导零，段数 ≤ 20（`MAX_OUTLINE_DEPTH`） |
| 2 | `任务名称` | **必需** | 文本，原样 | 任务名 |
| 3 | `开始` | 可选 | 真日期 + 格式 `yyyy-mm-dd` | `startDate`；空 = 缺失 |
| 4 | `完成` | 可选 | 同上 | `endDate`；**派生显示值**（工期为准，ADR 0004 §2） |
| 5 | `工期` | 可选 | 整数（工作日） | `durationDays`；空 = 缺失（不是 0） |
| 6 | `前置任务` | 可选 | `编号[FS\|SS\|FF\|SF][±lag]`，分号分隔 | 依赖边；见 §4 |
| 7 | `进度` | 可选 | 数字 `0..1` + 数字格式 `0%` | 分数；空 = 未知（`null`，**不是 0**） |
| 8 | `里程碑` | 可选 | 布尔（`t="b"`） | `milestone`；空 = `false` |
| 9 | `备注` | 可选 | 文本，原样 | `notes`；空 = `null` |

- **不导出**：`id`、`parentId`、`collapsed`、`manual`、`constraints`、`baselines`、项目级字段（项目名可进文档属性，见 §5）；
  这些要么是派生值、要么语义未启用（DM-08/09 归 v0.5）、要么属于应用状态；
- **空值 = 单元格缺失**（不写空串）；写空串视为"缺失"但要给 `XLSX_INFERRED_EMPTY_CELL`（`info`）——**容忍而不静默**（ADR 0002 §2 的同一口径）；
- **汇总行可以没有日期与工期**（DM-05）；协议层不下发"汇总行必须填什么"的规则。

## 3. 导出写**文档数据**，不写排程结果

**决策**：导出物承载的是**文档（输入）**；`Schedule` 只用于渲染与 PPTX（G4/G7）。

**理由**：

- [ADR 0004](0004-排程契约.md) §影响原写"导出（G3）写排程结果：导出 → 再导入得到同一 `Schedule`"。
  该表述与"导出 = 规范化 schema 输出"（路线图 G3）**不能同时无条件成立**：
  若导出写排程结果，则对"有前置任务"的行，这些日期在导入后是**文档日期**，
  而 `compute()` 的锚点情形③会**推导覆盖**它们并报 `dateOverridden`（[SCHEDULE.md](../../packages/engine/SCHEDULE.md) §四.3）——
  "同一 `Schedule`"这条判据会退化成"取决于导出的是哪一次的 `Schedule`"。
- 写文档数据让"导出物"与"排程结果"保持**一个真相源**：排程永远是派生值（ADR 0004 §2）。

**"与甘特图一致"的可测形式**（替代原表述，作为出口条件）：

```ts
const scheduleA = compute(原始文档, createScheduleCalendar(原始文档));       // 图上的结果
const imported  = importXlsx(exportXlsx(原始文档).bytes).document;          // 往返回来的文档
const scheduleB = compute(imported, createScheduleCalendar(imported));
// 判据：scheduleA 与 scheduleB 逐字段深比较相等（含 diagnostics 的码与 taskId 集合）
```

**注**：往返**不要求**文本级相等（用户可能改了列宽、Excel 会重写容器），只要求**语义等价**（T-2 的新往返要求）。

## 4. 单元格容差（闭集）

"导出形态"是单一确定形态；"导入必须接受"是一个**闭集**——不在集合内的形态一律给诊断，**不做猜测**。

| 字段 | 导入必须接受 | 仍不接受的形态 → 诊断 |
|---|---|---|
| 日期 | ① 真日期（序列号）；② 整数数值序列号；③ ISO 文本 `yyyy-mm-dd`；④ `yyyy/m/d` | **空串 / 纯空白** → 缺失 + `XLSX_INFERRED_EMPTY_CELL`(info)；**自 1899-12-30 起序列号 < 1**（1900 年前） → `XLSX_DATE_OUT_OF_RANGE`(error)；**非日期的数字**（如 `45123` 落在合法区间内即按序列号解读，超出区间报错）；**带时刻的日期**（序列号非整数）：取**其日期部分**（按 UTC），并报 `XLSX_DATE_HAS_TIME`(warning)；无法解析的文本 → `XLSX_DATE_UNPARSABLE`(warning) |
| 工期 | 数值；数值文本 | **小数**（如 `3.5`）→ `XLSX_DURATION_NOT_INTEGER`(error)，**不四舍五入**；**负数** → `XLSX_DURATION_NEGATIVE`(error)；`0` **合法**（里程碑）；空 = 缺失 |
| 进度 | 数字或数值文本，**≤ 1 视为分数、> 1 视为百分数**；`50%` 文本 | `< 0` 或 `> 100`（百分数口径）→ `XLSX_PROGRESS_OUT_OF_RANGE`(error)；非数值 → `XLSX_PROGRESS_UNPARSABLE`(warning) |
| 里程碑 | 布尔；`是`/`否`；`TRUE`/`FALSE`（大小写不敏感）；`1`/`0`（数值与文本） | 其他值 → `XLSX_MILESTONE_UNRECOGNIZED`(warning)，该任务取 `false` |
| 依赖 | 半角 `;` 与**全角 `；`**；类型可省（默认 `FS`）；**空片段容忍**（`1;;2` 与结尾分号）；4 类关系；`±lag`；负 lag | 语法错 / 未知编号 → `XLSX_DEPENDENCY_UNPARSABLE`(warning)，**丢弃该条**；**自环** → `XLSX_DEPENDENCY_SELF_LOOP`(warning)；**重复边**（同 from/to/type）→ `XLSX_DEPENDENCY_DUPLICATE`(warning)，只保留首条；**端点为汇总任务** → 保留该边 + `XLSX_DEPENDENCY_SUMMARY_ENDPOINT`(warning)（与文档侧 `LINK_SUMMARY_ENDPOINT` 同判据） |
| 文本 | 原样字符串（含 `=`/`+`/`-`/`@` 前缀、emoji、超长文本） | **与文档语义相关的前后空白** → `XLSX_TEXT_TRIMMED`(info)；**不设长度上限**（超长文本已在 S2 fixture 中通过） |

**导出侧的转义取舍**：**不做**公式注入转义。依据 S2 §六.3——危险前缀文本经 ExcelJS 以**共享字符串**落盘（`t="s"`），
WPS 保存前后都**从未**被解释为公式。CSV 路径不受此条豁免（见 §9）。

**三方容器口径**：ExcelJS 读回的单元格值有三类——`null`（空）、标量（文本/数字/布尔/`Date`）、**公式对象**（`{formula, result}`）。
**公式对象单独处理**（§5），绝不落进"标量"分支。

## 5. 公式：只读缓存值，扁平化，绝不解释

- 只读公式单元格的**缓存结果**（`result`）；**永不**读公式文本、永不自研求值器、永不写公式回导出物（NG-06 / XL-08）；
- 公式存在但**无缓存值**（ExcelJS 给 `{formula, result: undefined}`，等价于 `null`）：
  按"**值缺失**"处理 + `XLSX_FORMULA_WITHOUT_CACHED_VALUE`(**info**)；
- 该诊断必须与排程侧 `undated` **并列展示**、不合并——"文件里本来就空着"与"公式没算出值"是两件事；
- 导出物**只写值**，因此导出的文件不依赖 Excel 的重算设置（不设 `fullCalcOnLoad`）。

**独立互证**：openpyxl 3.1.5 在 `data_only=False` 下读出公式文本、`data_only=True` 下读出缓存值、
无缓存值时读出 `None`——与本条的语义完全同构（G3 的差分测试即建立在这一致性上）。

## 6. 层级解析：双解析的优先级与冲突

- **两条解析路径**：`WBS` 编号列（主）与**缩进式**（`alignment.indent` 仅作**显示**——S2 有专门断言"清空缩进后解析结果不变"）；
- 导入时：有 `WBS` 列 → 用编号解析；无 `WBS` 列 → 尝试缩进式；
- **两者同时存在且结论不一致** → `XLSX_LEVEL_CONFLICT`(warning)，**以编号为准**并**记录冲突行**（不静默择一）；
- 缩进式只在"**同一列内、按行递增/递减**"的意义上成立；**解析不得依赖缩进的具体数值**（只依赖相对深度），因为 WPS 会改写 `alignment.indent` 的取值；
- 层级结果照 ADR 0002 的规则产出：全量重编号（`reindexDocument()`），并保证"父节点先于子节点出现在文档序"。

## 7. 导入问题清单与诊断码表（闭集）

**最终报告 = 三层诊断拼接，单一数组**

| 层 | 来源 | 码空间 | 定位维度 |
|---|---|---|---|
| ① 协议层 | `importXlsx` | `XlsxDiagnosticCode`（本 ADR §7 闭集） | `{sheet, row, column, address}` |
| ② 文档层 | `validateDocument(document)` | `DocumentDiagnosticCode`（ADR 0002） | `{path, taskId, linkId}` |
| ③ 排程层 | `compute(document, calendar)` | `ScheduleDiagnosticCode`（ADR 0004 §5） | `{taskId, linkId}` |

**协议层码表（闭集；不为新原因随手开码，需要时追加 ADR）**

| code | severity | 触发 |
|---|---|---|
| `XLSX_SHEET_NOT_FOUND` | error | 指定/期望的工作表不存在 |
| `XLSX_HEADER_ROW_INVALID` | error | 表头行无法识别（多行表头、合并单元格表头导致的形态异常） |
| `XLSX_REQUIRED_COLUMN_MISSING` | error | 必需列缺失（`任务名称`；`WBS` 与缩进式**同时**缺失） |
| `XLSX_UNRECOGNIZED_COLUMN` | warning | 列名未匹配到任何规范列（**列出全部**，交向导第 2 步人工映射） |
| `XLSX_ROW_MISSING_NAME` | error | 行有其它内容但任务名为空 |
| `XLSX_DATE_UNPARSABLE` | warning | 日期单元格无法解析 |
| `XLSX_DATE_OUT_OF_RANGE` | error | 序列号 < 1（1900 年前）或超出可表示域 |
| `XLSX_DATE_HAS_TIME` | warning | 序列号非整数（带时刻），按 UTC 取日期部分 |
| `XLSX_DURATION_NOT_INTEGER` | error | 工期为小数 |
| `XLSX_DURATION_NEGATIVE` | error | 工期为负 |
| `XLSX_PROGRESS_UNPARSABLE` | warning | 进度非数值 |
| `XLSX_PROGRESS_OUT_OF_RANGE` | error | 进度小于 0 或大于 100（百分数口径） |
| `XLSX_MILESTONE_UNRECOGNIZED` | warning | 里程碑值不在容差集合内（取 `false`） |
| `XLSX_DEPENDENCY_UNPARSABLE` | warning | 依赖片段语法错或编号未知（丢弃该条） |
| `XLSX_DEPENDENCY_SELF_LOOP` | warning | 依赖指向自身 |
| `XLSX_DEPENDENCY_DUPLICATE` | warning | 同 from/to/type 重复（只保留首条） |
| `XLSX_DEPENDENCY_SUMMARY_ENDPOINT` | warning | 依赖端点为汇总任务（保留边；排程侧另有 `summaryIgnored`） |
| `XLSX_LEVEL_CONFLICT` | warning | 编号列与缩进式结论不一致（以编号为准） |
| `XLSX_CYCLE_EDGE_DROPPED` | warning | 成环边被丢弃（带成环路径） |
| `XLSX_FORMULA_WITHOUT_CACHED_VALUE` | **info** | 公式无缓存值，按缺失处理 |
| `XLSX_INFERRED_EMPTY_CELL` | **info** | 空串/纯空白，按缺失处理 |

**成环边丢弃（确定性，且不得用 `compute` 兜底）**

- **排序口径**：解析出的**全部边按「文档行序 × 单元格内前置出现顺序」**逐条处理；
- 对每条候选先调 `wouldCreateCycle(已接受的边, 候选)`：`cyclic === true` → **丢弃该条** + `XLSX_CYCLE_EDGE_DROPPED`（消息里带 `path`）；否则接受；
- **丢弃的边不回插**（不做"删一条再试另一条"的回溯）；
- **理由**：`compute` 遇环时**整个失败**且失败结果的诊断面只有一条 `cycle`（[SCHEDULE.md](../../packages/engine/SCHEDULE.md) §八末），
  所以"先 compute、失败再补救"这条捷径**不存在**；而丢弃顺序若不确定，"自往返一致"会变成偶发失败。

**导入产物必须是合法文档**：`importXlsx` 内部调 `validateDocument`；有 `error` 级诊断 → 返回 `{ok:false, diagnostics}`
（**不抛异常**——异常控制流无法承载"逐条收集问题文案"，ADR 0003 §4 已定同一取舍）。
导入写库时**必须**经命令层的 `document.replace`（唯一变更通道，ADR 0003）。

## 8. 落盘形态与日期/工期口径（与 ADR 0002 对齐）

- 文档落盘仍是 **ISO 日期 + 工作日工期**；工作日序号**只出现在引擎入参边界**（ADR 0002 §1）；
- 日期一律 `Date.UTC(y, m-1, d)`；**禁止** `new Date(y, m-1, d)` 与任何带时刻的 `Date`（S2 §三.4，本仓库三次复现）；
  代码里**必须**就地注释原因，并有一条负向用例；
- `durationDays` 与 `startDate`+`endDate` 三者不一致时：**工期优先**（照 ADR 0004 §2 / SCHEDULE.md §四.2），
  协议层**原样存日期**、**不做算术修正**，不一致由排程侧 `endDateStale`(info) 呈现；
- **文本原样**：导入不做 trim（除 §4 的判定用途）、导出不转义、不改换行。

## 9. CSV：尽力导入（XL-07）

- 接受：逗号分隔、可选双引号包裹、UTF-8（含 BOM）、首行表头；
- **不支持**（明确诊断而非错误解析）：多行单元格、分隔符嗅探、`.xls`(BIFF)；
- CSV 导入**复用同一套列契约、容差表与诊断码表**（不另立第二套规则）；
- **导出 CSV 不在 v0.1 承诺内**（D-2）；若日后实现，**必须**做公式注入转义（`=`/`+`/`-`/`@` 前缀）——
  这与 §4 对 xlsx 的豁免**不同源**：CSV 没有"共享字符串"这层保护。

---

## 10. 导出物的形式与确定性

- **单工作表 `任务`**，9 列规范列序（§2）；
- **规范日期**：`yyyy-mm-dd`；**规范依赖语法**：`编号[类型][±lag]`，多条以 `;` 分隔；
- **固定文档时间戳**：`created` / `modified`（以及任何可设的文档属性）**必须**取常量，
  **不得**来自当前时间——否则每次导出的部件内容都不同；
- **确定性判据取「部件指纹」**（条目名 + 各条目内容哈希的摘要），**不得**用整文件哈希：
  `exceljs` 会把写入时刻写进 zip 条目的 DOS 时间戳，跨秒重跑整文件哈希必然不同（S2 §六.2）；
- **允许（且有结构断言）的呈现属性**（白名单）：表头加粗、列宽、数字格式、**冻结首行**；
  **禁止**：批注、数据验证、条件格式、宏、图表、数据透视、图片、隐藏表；
  **每加一类呈现属性必须补一条结构断言**——历史上"需要修复"的提示多来自这一类别（且 G7 的导出物从 G3 起就交给用户直接打开）；
- **导出物的兼容口径**（沿用 P-4/P-5）：**WPS 为一等验证环境**；**Microsoft Excel / Google Sheets 备查、不阻塞**，
  且**不进入 G3 出口条件**；README 已知限制保留该声明。

---

## 11. 依赖与捆绑

- **ExcelJS 作为 `@ganttpilot/xlsx-protocol` 的运行时依赖**（`dependencies`，不是 `peer`/可选）；
- **浏览器侧必须动态导入**（`import()`），使该块**不进入首屏主 chunk**：实测 `dist/exceljs.min.js` = **925.5 KB min / 251.6 KB gzip**，
  且包内**无 ESM 入口**（`package.json` 只有 `main`（CJS）与 `browser`（UMD 单文件）），**不可 tree-shaking**；
- 本 ADR **不设 chunk 体积门禁**（首屏预算是 G4 的指标）；G3 的出口条件只要求**记录实测体积**；
- 版本**钉住 `exceljs@4.4.0`**（S2 的全部结论与本文的实测都建立在该版本上）；升级必须重跑：
  确定性（部件指纹）、日期序列号整数性、格式码解析三项证据；
- **"零 DOM 依赖"不因本依赖而放宽**：铁律约束的是**我们的源码**；依赖内部存在 `document.*`/`window.*` 探测代码（已实测），
  我们不调用它的 DOM 分支——这条差异**在此显式记录**，避免后来者误以为铁律被破坏；
- **许可与清单**：`exceljs@4.4.0` 为 MIT，其传递依赖（约 85 个包）须逐个落在 PRD-06 白名单内，
  过程走 `CONTRIBUTING.md` 的准入流程，并运行 `pnpm notices:write` 刷新 `THIRD_PARTY_NOTICES.md`；
- **退路（不阻塞本块）**：若 ExcelJS 停止维护，退路是 `fflate` + 自研 OOXML 读取器——
  本项目已在 S1 具备 OOXML 部件级补丁与取证的经验。

## 12. 验证与门禁

| 层 | 手段 | 位置 | 门禁判据 |
|---|---|---|---|
| ① 声明式期望值 | 列契约 / 容差表 / 依赖语法 / 诊断码的逐条用例（**内核无权改基准**，同 `schedule.manual.spec.ts` 的手法） | `packages/xlsx-protocol/src/*.spec.ts` | 逐条相等 |
| ② 自往返幂等 | 导出 → 导入 → 文档深比较 + §3 的 `Schedule` 深比较 | 同上 | 逐项相等（含"日期为 null 的节点"与未启用字段） |
| ③ 跨语言差分 | JS 协议产出 vs **Python `openpyxl`**（纯独立实现，只共享字段契约、不共享代码） | `packages/xlsx-protocol/src/*.differential.spec.ts` + `tools/xlsx-reference/` | 逐格一致；**缺 Python 3 即失败，不静默跳过**（同 ADR 0004 §9；Windows 上表现为退出码 9009） |
| ④ 负向对照 | S2 §三.1 的 5 条字节变造（改类型 / 改序列号 / 改进度 / 改表头 / 删行）+ "打坏期望值必须失败" | 同 ① | 全部被报出（判据有判别力） |
| ⑤ 结构哨兵 | LibreOffice headless 打开导出物、无修复标志 | `tools/` 或 CI 可选步骤 | **哨兵 ≠ 门禁**（[裁决 P-9](../00-baseline/裁决记录.md) 口径） |
| ⑥ 性能 | 200 行端到端（字节 → `Schedule`）**记录实测** | 同 ① | 对照"≤3 秒"给出数值；**不设会抖动的硬阈值** |

- 差分资产落 **`tools/xlsx-reference/`**（`xlsx-protocol` 包内不放非 TS 资产），与 `tools/cpm-reference/` 并列；
- **参照实现的 I/O 必须走 UTF-8 文件或 `PYTHONIOENCODING=utf-8`**：本机控制台码页会把中文显示成乱码（实测），
  靠 stdout 比对会得到假失败；
- 本块的规范说明落 **`packages/xlsx-protocol/PROTOCOL.md`**（与 `SCHEMA.md`/`COMMAND.md`/`SCHEDULE.md` 同构），G3 落地时产出。

## 备选方案与为何未采用

| 方案 | 未采用原因 |
|---|---|
| 导出写**排程结果**（ADR 0004 §影响的原文表述） | 导入后这些日期成为文档日期，会被锚点情形③推导覆盖并报 `dateOverridden`；"导出 → 再导入得同一 `Schedule`"因此取决于"导出的是哪一次 `Schedule`"，判据含混（§3） |
| 导出同时写"文档数据 + 排程结果"两组列 | 破坏"9 列规范列序"，并制造同一事实的两个真相源（排程结果永远是派生值，ADR 0004 §2） |
| 用 `compute` 的失败结果兜底成环边 | `compute` 遇环整个失败、诊断面只有一条 `cycle`（SCHEDULE.md §八末），无法逐条处理；丢弃必须在协议层自己定序（§7） |
| 解析公式文本自求值 | 自研公式解释器是明确非目标（NG-06），且 Excel 公式语义（含 `DATE`/`WORKDAY` 等）与工作日历耦合，成本与风险远高于收益（§5） |
| 危险前缀文本一律加 `'` 转义 | xlsx 路径上是**无因而加**：文本落为共享字符串，从未被当公式（S2 §六.3）；且转义会改变用户可见文本（§4） |
| 用整文件哈希做 golden 判据 | `exceljs` 把写入时刻写进 zip 条目时间戳，跨秒重跑必然不同 → "永远不一致"的假失败（S2 §六.2/§六.4） |
| 日期容差放宽到"任意可被 `Date.parse` 的文本" | `Date.parse` 对 `2026/10/5`、`10/5/2026` 的解读依赖实现与区域设置，会静默产出错误日期；容差表写成闭集才可断言（§4） |
| 工期小数四舍五入 | 静默改数；用户写 `3.5` 天时正确的行为是让他知道"这里只接受整数工作日"（§4） |
| 协议层顺带做"行内编辑/向导状态" | 三包零 DOM 铁律；向导状态属应用层，且会让协议层承担 UI 生命周期（§1） |
| 把 ExcelJS 放进 `apps/web` 而不是协议包 | 会让协议包无法自测（它必须能读写真实 xlsx），且把"协议实现"与"应用"耦合；正确做法是依赖进包、**动态导入**控体积（§11） |

## 影响

- **G3**：本 ADR 是**开工前置**；出口条件"实现与契约一致"指**与 ADR 0006 一致**（列契约、容差表、公式口径、
  成环丢弃顺序、导出物白名单、诊断码表）。落地时产出 `packages/xlsx-protocol/PROTOCOL.md` 与 §12 的六层证据。
- **ADR 0004**：§影响中"导出（G3）写排程结果"一句由本 ADR §3 **取代**；ADR 0004 的其余冻结内容不变，
  且**原文不改写**（裁决记录只增不改，P-14 承担订正说明）。
- **G4**：问题清单的形态（三层诊断拼接、`locator`）与"导入后接 `compute`"的用法在此固定；
  渲染层不重复实现列匹配（用 `detectColumns`）。
- **G5**：拖拽与编辑产生的"问题标记"与导入报告**共用** `locator`/`severity` 的展示口径。
- **G7**：导出物的**白名单**（§10）同样适用于 PPTX 之外的任何导出物；"部件指纹而非整文件哈希"的 golden 口径被模板 A 复用。
- **G8**：README 的已知限制与 `xlsx 导入/导出协议规范`（用户手册的一部分）直接引用本 ADR。
- **新增依赖**：运行时**首次**引入第三方依赖（ExcelJS 及其传递依赖）——需要 PRD-06 白名单核对与
  `THIRD_PARTY_NOTICES.md` 刷新；Python 3 在 G2 已是门禁前置，本块复用。
- **不改动**：文档形状（ADR 0002 冻结）、命令层形状（ADR 0003 冻结）、`Calendar`/`Schedule` 公共 API（G1.1/G2 冻结）。
