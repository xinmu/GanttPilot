# 依赖列语法与排程规则（用户手册 ②）

> 面向**使用者**：`前置任务` 那一列怎么写、写完之后甘特图会怎么算。
> 排程语义的**权威定义**在 [`SCHEDULE.md`](../../packages/engine/SCHEDULE.md) 与
> [ADR 0004](../../docs/02-adr/0004-排程契约.md)；本文只讲"用户视角的写法与预期"。
>
> 三份手册的分工：[① 导入与准备](导入与Excel准备.md)、**② 本文（依赖与排程）**、
> [③ 导出与离线单文件](导出与离线单文件.md)。

## 一、`前置任务` 一列的语法

```
编号[类型][±lag]
```

- **编号**：前置任务的 `WBS` 编号（例如 `1.2`）；
- **类型**：可省略（省略 = `FS`），四个取值见下表；
- **lag**：可正可负的工作日数（省略 = 0）；
- **多条**用**半角分号** `;` 分隔（`；` 全角也接受）；**空片段**会被容忍（`1;;2`、结尾分号）。

```
1.2                     ← FS + 0（最常用，省掉类型与 lag）
1.3SS+2                 ← 开始-开始、滞后 2 个工作日
1.4FF                   ← 完成-完成、无滞后
1.1[-1]                 ← FS、负 lag 1 个工作日（提前）
1.2;1.3SS+2;1.4FF-1     ← 三条一起
```

## 二、四类关系（各自意味着什么）

| 类型 | 全称 | 读作 | 约束（`s`=开始、`f`=完成，均为工作日序号） |
|---|---|---|---|
| `FS` | Finish → Start | "**A 完成后** B 才能开始" | `s_B ≥ f_A + lag` |
| `SS` | Start → Start | "A 一开始，B 也**可以**开始（可滞后）" | `s_B ≥ s_A + lag` |
| `FF` | Finish → Finish | "B **不能早于** A 完成" | `f_B ≥ f_A + lag` |
| `SF` | Start → Finish | "B 的完成不早于 A 的开始"（冷门，防顺序错误） | `f_B ≥ s_A + lag` |

**甘特图上的区分方式**：线型只有一种，**箭头形态**区分四类——

- **实心三角** = `FS` / `FF`；
- **开放箭头**（"→"形）= `SS` / `SF`；
- 再加**朝向**（箭头指向 +x 还是 −x）就有四种可辨形态。图例里有对应的图元。

## 三、排程是按什么算的（四条口径）

1. **只有叶子任务参与传播**；汇总（阶段）行的日期是**子任务的聚合结果**，
   因此"从阶段拉一条线"在排程里**等同不存在**（导入时会保留这条边并给 warning + 画成灰线）；
2. **日期只是锚点，工期才是准**：`完成` 是**派生显示值**——真正决定长度的是 `工期`（工作日数）。
   若 `完成` 与"开始 + 工期"不一致，导入会给一条 `endDateStale`（info），**并以工期为准、不回写文档**；
3. **项目起点**：所有没有日期锚点的任务从项目起点推；推到项目起点之前的会被**截断**并给一条
   `clampedStart`（warning）——**负数工作日序号无定义**；
4. **负 lag 会被截断到项目起点**：`ES = max(入边约束, 起点)`。

## 四、在界面上拖动时会发生什么

| 位置 | 语义 | 提交什么 |
|---|---|---|
| 条的**中部** | 整体移动 | 改 `startDate`（工期不变） |
| 条的**左端**（6 px 内） | 改开始 | 改 `startDate`（完成日跟着走） |
| 条的**右端**（6 px 内） | 改工期 | 改 `durationDays` |
| 条端外侧的**圆点** | **建线**（拉出一条依赖） | 插入一条 `link.insert` |

- **拖动期文档不写**：位置经会话锚点、工期经"未提交文档副本"进排程 ⇒ **下游实时跟随**；
  松手才提交**一条**命令 ⇒ **一次手势 = 一层撤销**（`Ctrl+Z` 一次整体退回）；
- **`Esc`** 取消整次拖动（不提交、不压撤销栈）；
- **必须命中条体**：同一行的空白处按下**不产生手势**（不会"点一下就把日期改了"）；
- **`吸附` / `允许` 两种策略**：`吸附`（默认）把候选夹到入边约束之前；`允许` 原样放行，
  早于约束时按 `anchorConflict` **标红**（"晚于约束"**不是**冲突——任务往后排正是你要的）；
- **汇总条不能拖、不能拉线**（光标 `default`）：它的日期是聚合结果；
- **里程碑（工期 0）只能整体移动**：菱形，左表「工期」列在标记为里程碑时**拒绝编辑**
  （唯一出口是先在「里程碑」列解除标记）。

> **拖动期的"所见"与"文档事实"是两件事**：左表显示的是**文档值**，
> 松手之后才更新；拖动期只有**图表**跟随。

## 五、诊断码：看到这些分别是什么意思

| 码 | 级别 | 含义与处置 |
|---|---|---|
| `cycle` | **error** | 依赖成环 ⇒ **整份文档不可排程**（这时只画占位与成环路径）。导入的成环边已按确定性顺序丢弃；手工建线会在松手前预检拒绝并高亮路径 |
| `anchorConflict` | warning | 拖动候选早于入边约束（"允许"模式下）；画红色描边 |
| `clampedStart` | warning | 日期/lag 早于项目起点，被截断到起点 |
| `undated` | warning | 既没有日期也没有前置 ⇒ 回落项目起点 |
| `dateOverridden` | warning | 文档日期被"前置优先"规则覆盖 |
| `summaryIgnored` | warning | 依赖端点是汇总任务（传播忽略，线画成灰色） |
| `endDateStale` | info | `完成` 与"开始 + 工期"不一致（工期为准） |
| `constraintsUnused` | info | 任务带了 `constraints` / `manual` 字段——**v0.1 不参与排程**（R-3 归 v0.5） |

## 六、v0.1 明确不做（与排程有关的部分）

- **CPM 分析层**：LS/LF、总浮动/自由浮动、关键路径高亮、增量重算（归 v0.5）；
- **任务约束**（不得早于/晚于、固定日期）与**手动/自动双模式**（归 v0.5）；
- **基线对比**、**筛选/分组/排序**（归 v0.5）；
- **资源**相关的一切（资源池、均衡、直方图）——见 README 的「非目标」；
- **把任务排到项目起点之前**（要它得走 v0.5 的约束/手动模式）；
- **同侧多线避让**（实测 70.7% 的边其竖向段穿过条形；这是"日后另立 ADR"的量化触发依据）。
