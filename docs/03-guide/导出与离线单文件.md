# 导出与离线单文件（用户手册 ③）

> 面向**使用者**：把图带出这个页面有两条路——**导出文件**（SVG / PNG / PPTX）与
> **离线单文件产物**（下载一个 HTML，双击即用、不需要联网也不需要装任何东西）。
>
> 契约的**权威定义**在 [ADR 0010 导出契约](../../docs/02-adr/0010-导出契约.md) 与
> [P-49（离线单文件）](../../docs/00-baseline/裁决R47.md)；本文只讲"怎么用、会得到什么、
> 什么地方不承诺"。
>
> 三份手册的分工：[① 导入与准备](导入与Excel准备.md)、[② 依赖与排程](依赖列语法与排程规则.md)、
> **③ 本文（导出与离线）**。

## 一、三种导出物

工具栏「导出」里选格式：

| 格式 | 内容 | 选项 |
|---|---|---|
| **SVG** | 语义化矢量图（含 `<title>`/`<desc>`、按行分组、`data-task-id`），**不含任何交互图元**（手柄/连接点/热区/覆盖层） | 「含图例与摘要」开关 |
| **PNG** | 同一张 SVG 光栅化（白底） | 倍率 1× / 2× / 3×（像素上限 32 MP） |
| **PPTX（模板 A）** | 单页总览 = 标题 + 甘特（含左列任务名）+ 图例 + 自动摘要 | 固定含图例与摘要（开关对它置灰） |

**几何与屏幕同源**（同一份视图模型，**不是截屏**）：条的位置、依赖线端点、刻度与周末灰度带
都取自同一个几何来源，因此"所见 = 所导出"是**结构性的**，不是"看着差不多"。

## 二、导出的三条口径（会影响你看到的结果）

1. **全量渲染 + 等比缩到单页**：导出**不分窗口**（屏幕上被滚动裁掉的行也在图里），
   折叠隐藏的行**不导出**。行数很多（如 1,000 行）时会被压到不可读——
   界面会给**提示**（建议切档/先折叠），**但不阻断导出**（你可能就是要一张全量图）；
2. **PPTX 只有模板 A**：一张 16:9 的单页总览。**模板 B/C、主题跟随、A4 页面**归 v0.5；
3. **PPTX 的连线由渲染引擎按"两端吸附点"重算**：它与 SVG 的折点**不保证逐点相同**——
   承诺的是"端点落在同一条边上"，以及"在 WPS 里拖动任务条时连线**跟着走**"。

### 2.1 PPTX 里的图面要素（为什么它看起来像一张真的甘特图）

- 日期**刻度**（**两级**：上级随档位，日/周档 `YYYY-MM`、月档 `YYYY`）；
- **周末/节假日灰度带** + **背景网格线**（在条形之下）；
- 任务条 = **圆角矩形**原生形状、里程碑 = **菱形** preset、阶段汇总 = 更矮的矩形；
- 依赖线 = **原生 connector**（`p:cxnSp` + 双端吸附 `a:stCxn`/`a:endCxn`）+ **箭头**
  （`FS`/`FF` 实心三角、`SS`/`SF` 开放箭头）；
- 左列任务名（**汇总加粗、子行按 WBS 缩进**）、**图例**（含色块与箭头图元）、**自动摘要**
  （任务/依赖/里程碑/完成率/里程碑清单）。

**永不为位图**：全部是可在 WPS/PowerPoint 里改色、挪位、重连的原生形状。

### 2.2 在 WPS 里核对"连线跟随"（一条提示）

模板 A 的任务条在**真实的 `p:grpSp` 组里**，因此在 WPS 里**要先点进组**（例如 `grp-s1`）
才能选中任务条；拖动之后，依赖线的端点会重新计算（走线可能从 `bentConnector3` 变成
`bentConnector5`——那是**重新走线**，不是坏了）。

## 三、兼容性：我们承诺什么、不承诺什么

| 环境 | 结论 |
|---|---|
| **WPS** | **必过**（两次独立冷开无修复弹窗、另存后 14/14 个吸附锚点存活、拖动任务条后端点重新走线）——这是**真机证据** |
| **Microsoft PowerPoint** | **未验证、不承诺**（备查、不阻塞）。输出是标准 OOXML、未用 WPS 私有扩展，但**在没有验证之前不对外承诺**其下的行为 |
| **Keynote** | **明确不保证**（Apple 官方兼容矩阵说明连接线会被导入为直线） |
| **Microsoft Excel / Google Sheets** | xlsx 往返**未验证、不承诺**（以 WPS 表格为准） |

## 四、离线单文件：下载一个文件，双击即用

### 4.1 它解决什么问题

此前的分发方式是"打包产物 + 一个本地 HTTP 服务"（`pnpm preview`）——**它把环境要求推给了用户**：
没有 Node 或 Python 的人拿到的是一堆打不开的文件。
单文件产物把"断网可用"从"**零后端依赖**"变成**字面成立**：
**一个 `.html` 文件，双击就用，不需要网络、不需要装任何东西、不需要托管。**

### 4.2 怎么得到它

```bash
node scripts/bundle-offline.mjs      # 产出 apps/web/dist-offline/index.html（**目录里只有它一个文件**）
```

体积约 **1.6 MB**（在线产物约 190 KB）：为了在 `file://` 下可用，`exceljs`（导入/模板）
与 `pptxgenjs`（导出）必须**内联**进同一个文件。**两套产物两张账**——
在线 Demo 的首屏预算是另一条线（首屏主 chunk 不含这两个库，这条断言照旧）。

### 4.3 实测结论（真机登记，[证据](../../apps/web/evidence/offline-single-file-chrome154.md)）

| 问题 | 结论 |
|---|---|
| `file://` 下**自动保存**能不能用 | **能**（IndexedDB 在这个场景下可用；写盘与读回都通过） |
| `file://` 下**导出/下载**能不能落盘 | **能**（SVG / PNG / PPTX / 模板下载都真的落盘） |
| 三条主链路 | **导入 / 拖动 / 导出全部可用** |
| 首屏 | **约 0.13–0.15 秒**（导航 → 界面可交互；单文件无网络请求） |
| 断网（拔网线/关 Wi-Fi） | 由"全部资源已内联 + 目录里只有一个文件"这条**结构性保证**成立；用 CDP 模拟断网时 Chrome 会拒绝 `file://` 导航，那是模拟器的边界（详见证据文件） |

### 4.4 已知限制（诚实声明）

- **会话锚点、滚动位置与档位不跨会话恢复**（与在线产物同一条口径：它们是视图状态）；
- **多标签页只做互斥停写 + 提示**，不做合并；
- **不支持触屏/移动端**（v0.1 的承诺环境 = 桌面鼠标 + 键盘）；
- 若你的浏览器策略**禁止 `file://` 页面使用存储或下载**，界面会**明示降级**（"本次会话不自动保存"/提示改用新标签页另存），
  **不会静默假成功**。

## 五、明确不做

- **不做 PWA / Service Worker**：单文件解决的是"**打开**"，不是"**安装**"（PWA 归 v0.5）；
- **不让单文件与在线产物同体积**（两套产物两张账）；
- **不在单文件里内置示例数据**（示例由「模板下载」覆盖，避免两个真相源）；
- **不做 Docker 容器化部署**（归 v0.5；评估见 [P-49 §4](../../docs/00-baseline/裁决R47.md)）。
