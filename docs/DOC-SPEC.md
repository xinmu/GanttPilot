# 文档规范（DOC-SPEC）

> 本文件**只规定「什么信息住在哪一层、怎么检查」**，不收录任何契约内容。
> 契约内容在 [docs/02-adr/](02-adr/) 与各包规范；判定在 [首版能力顺序](01-roadmap/首版能力顺序.md)；
> 裁决登记在 [裁决记录](00-baseline/裁决记录.md)。
> 权威裁决：`P-27`（第二十七轮，见 [裁决记录 §第二十七轮](00-baseline/裁决记录.md)）。

## 一、五层模型（P-27）

一句话：**判定（plan）在路线图；契约（decide）在 ADR；登记（register）在台账；过程与结果（act / result）在记录层；原始证据在 evidence/spikes；教训与未决各只在一处。**

| 层 | 回答的问题 | 住所 | 角色标记 |
|---|---|---|---|
| 登记 | 「定过什么、现在还算不算」 | `00-baseline/裁决记录.md`（台账）+ `00-baseline/裁决R*.md`（细则） | `register` |
| 契约 | 「必须怎么做、边界在哪」 | `02-adr/NNNN-*.md`、`docs/02-adr/附录/*`、各包 `SCHEMA/COMMAND/SCHEDULE/SPEC/PROTOCOL.md` | `contract` |
| 判定 | 「先做什么、怎样才算做完」 | `01-roadmap/首版能力顺序.md` | `plan` |
| 记录 | 「实际做了什么、实测数字与教训」 | `01-roadmap/首版-记录-*`、`02-adr/附录/*`、`apps/web/evidence/*`、`spikes/*/evidence/*` | `record` |
| 待定 | 「还没定的事」 | `01-roadmap/首版-待定清单.md`（全仓唯一） | `plan` |
| 基线（**归档层**） | 「上游原文怎么写的、当时怎么评估的」 | `00-baseline/{上游原文-产品需求文档与路线图,需求基线,评估报告,证伪实验计划}.md` | `baseline` |

> **五层就是上面第一列的前五行**（`P-27` §2 的原话：登记 / 契约 / 判定 / 记录 / 待定）。第六行是**归档层**的
> 来源文档——它不在五层之内，使命已完成，只允许作为「原文口径」被引用：`doc-index.json` 里登记为
> `layer: "archive"`，`contextBudget` 与入口封闭性据此判定（见 §五 与新检查说明）。
> 其中 `上游原文-*.md` 是**上游原文的逐字入库件**（决策 8）：它**没有规范效力**，只作「可校验来源」，
> 溯源与保真的规则见 §4.6。

**反重复规则（本规范的核心）**
1. 同一事实**只允许有一处权威陈述**；其他地方只能写指针（`见 [P-8](…)`），不得复述内容；
2. **验证矩阵/判据表只在一个地方登记**：产品级 DoD 在路线图 §六；包级矩阵在各包 `*/SPEC.md`/`SCHEDULE.md`；ADR 只登记「形状与语义」，不登记逐轮返工；
3. 逐轮返工史**只进记录层**，不进 ADR 正文、不进路线图的「内容/出口条件」段；
4. 基线文档不得承载「当前生效值」——引用它们时必须写明「原文口径，现状见 …」。

## 二、命名的反向映射规则

| 文件形态 | 规则 | 为什么 |
|---|---|---|
| 台账 | `裁决记录.md`（**不带轮次、不带版本号**） | 唯一权威登记处的入口，路径稳定，外部引用不改 |
| 存档细则 | `00-baseline/裁决R<起轮>-R<止轮>.md`，轮次用两位数字（`R01`） | 文件名可直接反推覆盖的轮次区间，`check-docs` 据此验证「每轮恰好一片」 |
| ADR | `02-adr/NNNN-主题.md`，增补 `02-adr/附录/NNNN-增补.md` | 与既有 P-3 的编号约定一致 |
| 落地记录 | `01-roadmap/首版-记录-G<块>.md` | 与能力块编号一一对应 |

> **与 P-3 的关系**：P-3 明写「文档不做版本号另存」「裁决类信息统一进 `裁决记录.md`」。
> 本轮的**例外经 `P-27` 显式授权**：**新增**按轮次区间命名的存档文件（不是把同一份文档另存成多版），
> 且台账仍是**唯一**登记处——存档只是细则，不承担登记职责。除该例外外 P-3 继续有效。

## 三、模板

### 3.1 台账行（`裁决记录.md` 条目表）

五列，一行一条：`ID | 轮次 | 结论 | 状态 | 细则`（无「主题」列——结论本身就是主题，避免重复）。

- `状态` 是**闭集**：`有效` / `已闭` / `取代`（必须在「结论」里写明被谁取代）/ `未决`（必须指向 `首版-待定清单.md` 的条目）；
- `细则` 一律写成 `[细则](文件.md#<条目 slug>)`，**必须带锚点**——不带锚点的指向会在拆分后静默落到文件顶部；
- 「结论」列从既有条目标题**逐字截取**，不新增转述。

### 3.2 存档文件（`裁决R*.md`）

```
# 裁决细则 R<起>–R<止>（<首轮主题> … <末轮主题>）

> 本文件是 [裁决记录](../00-baseline/裁决记录.md) 的**细则层**：覆盖第 X 轮到第 Y 轮，
> 逐字迁移、不改写。登记与状态见台账对应行；上/下一份：…
> 对应台账行：`D-n…`、`R-n…`、`T-n…`、`P-n…`

（原文逐段，一字不改）
```

- 一个 `## 第N轮` 标题段**整体**属于一份存档，不跨文件；
- 块首的 `---` 分隔线**归属其后的轮次**；正文行内内容不改；
- 不许按 `###` 切——`###` 里既有条目（`### P-n`）也有轮内小结（`### 修法…`）。

### 3.3 路线图能力块

`### G<n> 标题` + 依次四段：`> **状态**` / `**内容**` / `**出口条件**` / `**可延后**`，
末尾一行 `**细则**：→ 首版-落地记录/G<n>.md`（写成普通指向该文件的链接）。
**仅存的块**才有「状态」；已收口的老块写 `> **状态：已完成（本块仅存档，不随新裁决更新）。**`

### 3.4 ADR 增补节（`02-adr/附录/NNNN-增补.md`）

每节 `## §<编号> <标题>（P-<n> 增补）`，首行必须声明它与正文的关系：
「**新增**」或「**修订正文 §x 的实现方式（语义不变）**」。正文里留一行指针。

## 四、体量上限、增长纪律与七条纪律

上限登记在 `docs/doc-index.json`（唯一真相源），由 `pnpm docs:check` 判定。

### 4.1 增长纪律（五条）

1. **台账只追加行**，行有界（结论 ≤80 字）⇒ 体量与轮次线性、不膨胀；
2. **细则一轮一文件** ⇒ 单文件永远不随轮次长大；
3. **ADR 的追加段有明确规则**（见 §4.3）：**契约性**增补可以留在正文，但必须带轮次标记与附录指针；
   **记录性**内容（返工史、复验过程、落地记录）一律不进 ADR；
4. **记录层可以无限增长**（它就是历史），但**不得被上游引用为「当前值」**；
5. 任何文件触及上限时，**动作是拆分或迁移，不是提高上限**（提高上限必须在台账留一条新裁决）。

### 4.2 契约常量单点声明（纪律一）

每个契约常量（`c₃` 逐档位锚值、`c₄` 与 `overlay`、刻度长度、表头带高度、折点引出段、性能阈值 `1 ms`/`2 ms`、
诊断码表条目数、轴与条色值……）在 `doc-index.json` 的 `constantCheck` 里登记**唯一声明处**；
其余位置只允许两种写法：**指回声明处**，或**在例外表里带 `reason` 登记**。
判定：`scripts/check-constants.mjs`。值不同标「错值」、值相同标「重复陈述」——**位置本身就是错**。

### 4.3 ADR 追加段规则（收口 P1-d 记下的「规范与实际不一致」）

**允许**在 ADR 正文追加**契约性**增补段（不为此新建 ADR），四条同时成立：

1. 标题带轮次标记：`## §<编号> <标题>（P-<n> 增补）`；
2. 首行声明与既有节的关系，三选一且必须点名 `§x`：**新增** / **修订 §x 的实现方式（语义不变）** / **取代 §x**；
3. `02-adr/附录/NNNN-增补.md` 里有对应条目，**正文段与附录条目互相指针**（模板见 §3.4）；
4. **记录性内容不得进正文**：返工史、逐轮复验过程、「落地（记录）」、教训叙事一律进记录层或其附录。

> 本条**判定是人工**（D5 逐份过一遍），没有机械守卫：ADR 的基础编号各份不同（0006 用 `## 10.`、0007 用 `## 11.`），
> 靠标题编号机器判定会把基础节误报成追加段。原措辞「ADR 正文不再追加 §N」与实际不符
> （0005/0006/0007/0008/0010 都已有追加段），故改写为上面这条「允许但必须带指针」的规则。

### 4.4 精简层预算与入口封闭性（纪律二）

`doc-index.json` 的 `layer`（`slim` / `archive`，每份文档一条）与 `contextBudget` 是唯一真相源：
**精简层 ≤ 500 KB**、**必读 ≤ 34 KB**、**入口 `docs/README.md` ≤ 6 KB 且只引用精简层**；
`userFacing`（用户手册）、`budgetExempt`（v0.2 临时施工计划）与 **`generated`（可推导的生成物）**不计入预算，但都列在报告里。
判定：`check-docs.mjs` §8b（超预算时**列出最大的若干份**，不是只报一个总数）。

**「精简层」的构成口径**（[R53 细则](00-baseline/裁决R53.md)）：**契约（ADR）+ 包规范 + 判定 + 登记 + 规范/根文档**是它的主体
（实测：契约 221.8 + 包规范 156.1 + 基线 64.9 + 判定 26.8 + 登记 19.2 ≈ 475 KB）——**ADR 与包规范必须留在精简层**
（决策 3：它们是"当前契约"，注入新会话时要能读到"现在必须怎么做"）。

**两条硬边界**（[R52 细则](00-baseline/裁决R52.md) / [R53 细则](00-baseline/裁决R53.md)）：
- **可推导的不进预算**——生成物（[轮次导读](00-baseline/轮次导读.md)、[首版-文档索引](01-roadmap/首版-文档索引.md)）
  的内容已在 `doc-index.json` / 台账 / 存档里计过一遍，再计就是**重复计数**；它们标 `generated: true`；
- **历史不进预算**——归档层（`layer: archive`）本来就不计；台账的历史叙事、待定清单的已闭结转行都已在记录层。

达标动作是**先拆分或迁移（或剔除可推导项）**、再按**实测下限**重设上限，且**上限必须由实测推导并在台账留一条裁决**（`§4.1` 第 5 条）；

### 4.5 spike 生命周期（G4-S 先例 + 两条件 / 两级处置）

> **一个 spike 在满足以下全部条件后即可处置**：
> ① 其结论已**重新表达为进 `pnpm gate` 的 `packages/**` spec**，或测量协议已**移植进受维护的脚本**；
> ② 决策相关的数字已**冻结进 ADR / 计划文档**；
> ③ 全部引用已迁移或登记进白名单。
>
> **处置分两级（`R54`/`P-56`）——"还有没有用"与"能不能再生"是两件事**：
> - **可再生的探针代码 ⇒ 删除**：`src/`、`reference/`、`package.json` / `tsconfig.json` / `pnpm-lock.yaml`
>   ——凡"重跑一遍就能再得到"的，都不留在仓库里；
> - **结论与证据 ⇒ 留档**：`README.md` / `结论.md` / `evidence/**` 登记为**归档层**
>   （`role: record` + `layer: archive`），**不进任何注入包**。它们是**不可再生的外部工具观测**
>   （真机落盘的 XML、渲染 PNG、计时原始数据），也是主干代码注释里"为什么"的落点；
>   留档时只在文首加一条"探针代码已删"的处置说明，**不改写正文**。
>
> **删除后，正文里的历史引用保留原路径并加括注**（先例：「该目录已随 G4 落地删除，数字转入本包 spec」）；
> 指向已删文件的**链接**要么改成"原路径 + 括注"、要么登记进 `linkCheckAllowlist`
> （**继承式**：归档层路径族 × 失效目标目录，不给单条引用开口子）。
> **受维护的脚本不得反向依赖 spike 目录**——`scripts/wps-pptx-verify.ps1` 曾 dot-source 探针的
> `wps-common.ps1`，P2/D9 先把它逐字迁入 `scripts/wps-com.ps1`；否则条件 ① 永远差一步、spike 永远删不掉。

### 4.6 基线层的溯源与保真、仓库外路径与 gitignore 引用（纪律三 / 决策 8）

1. **基线层的「可校验」只指溯源与保真，不指当前口径**：
   - **溯源（硬规则）**：`00-baseline/` 里的**提取 / 重建件**必须指向它**所依据的那一版**上游原文——
     原文入仓（归档层、`layer: "archive"`），两者来源行互指并记版本 + 获取日期 + `sha256`；
   - **保真（一次性 + 争议时重取）**：「只做还原与标注 / 提取并重编号」是**提取件对自己的断言**，
     导入时校验过一次、结论进记录层；此后只在**某一段的可信度有争议**时按同一口径重取，不随轮次重做；
   - **不是一致性**：**原文没有规范效力**。当前口径以**裁决记录 + ADR + 包规范**为准；
     与原文的偏离（含决策 4 的两处降级）是**正常结果**、由裁决承载（先例：台账 `T-4`「改纯 SVG —— 成立，
     而且比原文方案更好」），**不要求回到原文**。每轮「重新确认基线」确认的是**裁决累计后的当前基线**；
   - **冻结**：已入仓的「提取件 ↔ 原文」对应关系**不得回改**（回改等于改写历史）；原文升版按**新裁决**处理，
     且**不并列存多版**（`P-3`）；
   - **适用范围**：只有自称提取 / 重建件的文档承担前两条（现为 `需求基线.md`）；`评估报告.md` 承担
     「引用原文处可回溯」；`证伪实验计划.md` 的依据是**评估报告**（§5.1–§5.3、§7 D-3），**不承担**本条。
2. **入仓原文的来源行**（判定见 `sourceLineCheck`）必须记：原始路径、文档版本、获取日期、
   与重建件的关系（「重建件的保真度以本原文为准」），以及**两个哈希**：
   - **原始文件 `sha256`**——入库时在本机量得；原始文件在仓库外，**不可在库复算**，只作历史留档；
   - **入库件正文 `sha256`**——内容起始标记（`sourceLineCheck.contentStartMarker`）**那一行之后**的全部内容、
     按 LF 归一化；**可在库复算**，改动入库正文会被判错（这就是"冻结"在门禁上的执行面）。
3. **本机绝对路径不得出现在可复现层**（`layer: slim` 或 `role: baseline`）的正文里
   （`C:\…` / `D:/…` / `~/…` / `/Users/…` / `/home/…`）：换机器、清下载目录、clone 仓库都会让它悬空。
   判定：`check-docs.mjs` §8d ⇒ **error**。归档 / 证据 / spike 层里的本机路径是「当时的机器事实」，
   记录制证据按先例不改写（`P-41 §9(a)` / `P-44 §9(a)`）⇒ 只出**一条聚合警告**（存量执行落 C8、D9）。
4. **被 `.gitignore` 覆盖的临时路径**（`temporaryPathPatterns`：`tmp/`、`*.tmp`）不得被当成「可复现引用」：
   同一行（或**紧邻的下一行**）出现声明词（`gitignore` / `不入库` / `可再生` / `临时` …）才算已注明，否则 ⇒ **warning**。
   **可再生的构建产物**（`dist/` / `node_modules/` / `out/`）**不在判定内**——文档引用它们是正常口径。
5. **例外表** `externalPathCheck.allow`：每条必须写 `kind`（闭集：`环境观测` / `来源元信息` / `产物说明` / `规范示例`）与 `reason`，
   且至少写 `path` 或 `pathRegex`（否则等于把整条守卫关掉）。例外**不等于修好了**，而是「这一处按裁决保留」；
   本规范自己必须写出被禁止的形态（上面第 3 条与 §五 第 10 行），故以 `规范示例` 登记一条**只对本文件生效**的例外。

### 4.7 包规范的「API 段」（纪律四，P4-a）

包规范（`packages/*/` 下的 `SPEC.md` / `SCHEMA.md` / `SCHEDULE.md` / `COMMAND.md` / `PERSISTENCE.md` /
`PROTOCOL.md` / `PPTX.md`）里的 API 段**点名了哪些符号**，就是这门包对外的**承诺面**——
因此它必须是**可判定的**：`apiSurfaceCheck` 逐个登记「规格文件 + 段标题 + 提取模式 + 候选数下限」，
由 `scripts/check-api-surface.mjs` 判定「规范点名的符号 ⊆ 包入口（`src/index.ts`）的导出面」。

三条写法约定（改写法等于改检查口径，**必须同批改 `doc-index.json` 的登记与下限**）：

1. **声明块要放在段标题的直属正文里**，到下一个标题为止——子节（`### x.y`）是"用法示例/语义讨论"，
   里面会引用**别的包**的函数（`PROTOCOL.md` §2.1 的 `applyCommand` 属 `engine`），不计入本包的承诺面；
2. 段内只认**围栏代码块**（`function NAME` / `type|interface|class|enum NAME` / 裸调用 `name(` / 整行裸名字）
   与**首格由反引号符号起头的表格**两种形态——散文里提到的符号名**不算**（否则规范一写解释就假阳）；
3. 行尾注释先剥掉再匹配（`SCHEDULE.md` 的 `// max(ef)` 曾把 `max` 变成假阳）。

**例外**（`apiSurfaceCheck.allow`，每条带 `reason`）只用于"事实已确认、但方向留给后续裁决"的项；
登记为例外的点名**每次运行都会打印**——不允许静默吞掉。**反向**（哪些导出算「发布承诺」、哪些是内部）
由 §4.8 的公开面分类负责。

### 4.8 公开 API 面的「发布承诺 / 内部」（纪律五，P4-b）

包的入口（`src/index.ts`）是**发布承诺面**，但入口里的符号**并不都是**承诺。判据**机械可重算**
（`scripts/check-api-surface.mjs` 的公开面分类；**规则只有下面五条，不留手工分类表**——反重复规则 1）：

| 类 | 判据（`check-api-surface.mjs` 重算） |
|---|---|
| **发布承诺** | 在 L1 文档的 **API 段**里被点名（= §4.7 的提取面）⇒ 文档给了保证，改动按契约流程走 |
| **内部·跨界** | 未点名，但被**别的包 / `apps/web` / `scripts`** import ⇒ 仍从入口导出，但**不是**对外承诺 |
| **内部·仓内** | 未点名，只在**自己包内**（含 spec）被 import ⇒ 实现细节（`align` 一族是特例：走内部子路径） |
| **结构性** | 无 import，但在仓内被引用（类型位置、常量表、文档）⇒ 形状的一部分（如判别联合的变体） |
| **零引用** | 全仓**既无 import 也无提及** ⇒ **error**：给消费者 / 在 L1 里点名 / 删掉（C5-b、C6-g 的先例） |

三条纪律：① **不新增零引用导出**（门禁拦）；② **「承诺」只能由 L1 点名产生**——代码里多导出不构成承诺；
③ **改「发布承诺」= 契约变更**（走 ADR 流程），改内部面只需保持仓内自洽。
计数每次 `pnpm docs:check` 重算并打印（故"多少承诺、多少内部"永久可查）；`apiSurfaceCheck.allow`
的**未被命中**项会打印警告（不复用为永久免检牌）。

### 4.9 门禁步骤契约的两处陈述（纪律六，P5-c2）

门禁的步骤与顺序有**两处陈述**：`scripts/gate.mjs` 的 `STEPS`（**权威定义**，改动它等于改门禁契约，
须同步 ADR 0001 与附录增补）与 `.github/workflows/ci.yml` 实际跑的那些步。此前这一致性**只写在
`ci.yml` 的文件头注释里**，而注释腐烂过一次，且**没有任何检查会在两边分叉时翻红**。

判据在 `scripts/check-gate-steps.mjs`（登记在 `gateStepsCheck`，接在 `pnpm docs:check` 的最后一步），
四条：① `ci.yml` 的 `pnpm` 步 **⊆ `STEPS`**；② 相对顺序是**子序列**（尤其 `build` 必须先于 `typecheck`）；
③ **缺的步集合与 `absent` 相等**（不是包含——只判子序列的话"删掉一步"仍然合法，而"登记为不跑、其实在跑"也要报）；
④ `prerequisites`（`pnpm install` 这类**前置动作**）与 `absent` 每条**带 `reason`**，未登记的前置动作也报。
**零依赖**：不引 YAML 解析器（只认单行 `run: pnpm <step>`），出现多行 `run: |` 块即**响亮地失败**。

### 4.10 记录制证据的作废与重取（纪律七，v0.2 收口迁移）

记录制证据（`role: record` / `layer: archive`，含 `-raw.json`）是**不可再生的外部工具观测**：

1. **同批次集中重取**：会作废证据的改动排进同一批、**只作废一次**；重取前**书面声明作废清单**，重取后逐份登记新的环境与数字。
2. **环境三件套**：每份证据写明**浏览器版本 + headed/headless + DPR + 视口 + 档位 + 数据集 + 轮数**——缺了就不是可复现的读数。
3. **golden 取字节级**：字节数与 `sha256` 要么被测试**钉住**，要么从文档里删掉；不许留一个没人守的数字。
4. **不设会抖动的硬阈值**：判据要么是"存在性 / 形状"，要么带**覆盖度自证**（"没测到"不许记 ✅）；
   若判据**自带竞态**，优先在**判据侧归一化**已知的非确定字段（把"不看什么"写进注释 + 配负向对照），
   而不是改产物字节（`N21` 的先例）。

## 五、检查

`pnpm docs:check`（`scripts/check-docs.mjs`，已接入 `scripts/gate.mjs`）：
| # | 检查 | 破了会怎样 |
|---|---|---|
| 1 | `docs/doc-index.json` ↔ 实际文档集合**双射** | 新文档漏登记 / 登记了不存在的文件 |
| 2 | 全部 markdown **相对链接目标存在**（含 `#` 前部分） | 搬迁后留下 404 |
| 3 | 全部**锚点可解析**（按 GFM slug 规则，含内联 code span 整段剥离、重复标题 `-1` 后缀） | 拆分的第二类静默破环 |
| 4 | 正文/注释/markdown 里的 `` `路径.md` `` 或**目录**提及若失效 → **警告** | 跨层引用漂移、来源链断裂（历史失效路径走 `linkCheckAllowlist`，每条必须带 reason） |
| 5 | 台账行格式、ID 唯一且连续、`未决` 行与待定清单**双向一致** | 台账与待定清单分叉 |
| 6 | 每个 `## 第N轮` 恰好被一份存档覆盖、每份存档名与内容区间一致；**轮次上界由台账推导**、每轮都要有存档 | 漏轮 / 重轮 / 上界写死后新存档不受检查 |
| 7 | `---` 不得是存档文件首行；URL 内不得出现全角字符 | 分隔线漂移、坏链 |
| 8 | 体量上限（按角色） | 膨胀复发 |
| 9 | 策略不变量：`README`/`CONTRIBUTING`/台账文首的「唯一登记处 / 不按版本另存」措辞与 `DOC-SPEC` 一致，且 P-27 例外条目存在 | 规范与实际再次分叉 |
| 10 | **本机绝对路径**（`C:\` / `D:/` / `~/` / `/Users/` / `/home/`）出现在**可复现层**（`layer: slim` 或 `role: baseline`）⇒ **错误**；出现在归档 / 证据 / spike 层 ⇒ **一条聚合警告** | 基线层被绑死在一台机器的下载目录上（决策 8） |
| 11 | 引用**被 `.gitignore` 覆盖的临时路径**（`externalPathCheck.temporaryPathPatterns`）且同一行（或紧邻下一行）无声明词 ⇒ **警告** | 把「维护者本机的草稿」当成可复现输入 |
| 12 | 入仓原文的**来源块**（必填项 + 内容起始标记）齐备、**入库件正文 `sha256` 复算一致**；提取件保留指向原文的链接且带标记词 ⇒ 不符即 **错误** | 「提取件 ↔ 原文」的对应关系被静默摘掉，或入库正文被回改（改写历史） |
| 13 | **生成物与来源一致**：`generated: true` 的文档**就地从来源重算**并**逐字节比对**；标了 `generated` 却没有渲染器 ⇒ **错误** | 生成物静默变旧（先跑生成器、后改来源），而检查读的是索引（C7-i 的 `N10`） |
| 14 | **证据层的「原始读数」所有权**：每条 `-raw.json` 必须在 `evidenceRawCheck.rawOf` 里登记（raw → 与它成对的那份 `.md`）⇒ 未登记**警告**；登记的 raw / of 不存在 ⇒ **错误**；两侧都有 `采集时刻` 时**逐位相等**（否则这份 raw 不是那份 `.md` 的读数）⇒ **错误**；有一侧没有（schema 不同）时**必须写 note** 说明配对依据 ⇒ 否则**警告** | 记录制证据的原始读数变成「文件在、没人指」的孤儿；或 raw 被下一次运行覆盖后，指向悄悄错位（C8-a） |
| 15 | **包规范的 API 段 ⇔ 实际导出面**（`scripts/check-api-surface.mjs`）：登记的每个 API 段里**点名**的符号必须在包入口（`packages/<pkg>/src/index.ts`）的导出面里 ⇒ 否则**错误**；段标题找不到、候选数掉到登记的 `minCandidates` 以下、入口解析不出导出 ⇒ **错误**；`allow` 缺 `reason` ⇒ **错误**（登记为例外的点名每次运行都打印） | 规范文档化了**不存在**的符号（`templateSheetNames()` 那类）；或"写法变了 ⇒ 检查恒真"的静默失效（纪律见 §4.7，P4-a） |
| 16 | **门禁步骤契约的两处陈述**（`check-gate-steps.mjs`）：`ci.yml` 的 `pnpm` 步 **⊆ `STEPS`**、相对顺序是子序列、**缺的步集合与 `absent` 相等**、`prerequisites`/`absent` 缺 `reason`、未登记的前置动作、多行 `run:` 块、`STEPS` 解析为空 ⇒ **错误**（纪律见 §4.9） | CI 悄悄少跑一步、或把 `build` 排到 `typecheck` 之后，而"远端绿"照旧 |
