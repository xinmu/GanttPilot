# 文档规范（DOC-SPEC）

> 本文件**只规定「什么信息住在哪一层、怎么检查」**，不收录任何契约内容。
> 契约内容在 [docs/02-adr/](02-adr/) 与各包规范；判定在 [首版能力顺序](01-roadmap/首版能力顺序.md)；
> 裁决登记在 [裁决记录](00-baseline/裁决记录.md)。
> 权威裁决：`P-27`（第二十七轮，见 [裁决记录 §第二十七轮](00-baseline/裁决记录.md)）。

## 一、五层模型（P-27）

一句话：**判定（plan）在路线图；契约（decide）在 ADR；登记（register）在台账；过程与结果（act / result）在记录层；原始证据在 evidence/spikes；教训与未决各只在一处。**

| 层 | 回答的问题 | 住所 | 角色标记 |
|---|---|---|---|
| 登记 | 「定过什么、现在还算不算」 | `00-baseline/裁决记录.md`（台账）+ `00-baseline/裁决R*.md`（细则） | `register` |
| 契约 | 「必须怎么做、边界在哪」 | `02-adr/NNNN-*.md`、`docs/02-adr/附录/*`、各包 `SCHEMA/COMMAND/SCHEDULE/SPEC/PROTOCOL.md` | `contract` |
| 判定 | 「先做什么、怎样才算做完」 | `01-roadmap/首版能力顺序.md` | `plan` |
| 记录 | 「实际做了什么、实测数字与教训」 | `01-roadmap/首版-记录-*`、`02-adr/附录/*`、`apps/web/evidence/*`、`spikes/*/evidence/*` | `record` |
| 待定 | 「还没定的事」 | `01-roadmap/首版-待定清单.md`（全仓唯一） | `plan` |
| 基线（**归档层**） | 「上游原文怎么写的、当时怎么评估的」 | `00-baseline/{需求基线,评估报告,证伪实验计划}.md` | `baseline` |

> **五层就是上面第一列的前五行**（`P-27` §2 的原话：登记 / 契约 / 判定 / 记录 / 待定）。第六行是**归档层**的
> 来源文档——它不在五层之内，使命已完成，只允许作为「原文口径」被引用：`doc-index.json` 里登记为
> `layer: "archive"`，`contextBudget` 与入口封闭性据此判定（见 §五 与新检查说明）。

**反重复规则（本规范的核心）**
1. 同一事实**只允许有一处权威陈述**；其他地方只能写指针（`见 [P-8](…)`），不得复述内容；
2. **验证矩阵/判据表只在一个地方登记**：产品级 DoD 在路线图 §六；包级矩阵在各包 `*/SPEC.md`/`SCHEDULE.md`；ADR 只登记「形状与语义」，不登记逐轮返工；
3. 逐轮返工史**只进记录层**，不进 ADR 正文、不进路线图的「内容/出口条件」段；
4. 基线文档不得承载「当前生效值」——引用它们时必须写明「原文口径，现状见 …」。

## 二、命名的反向映射规则

| 文件形态 | 规则 | 为什么 |
|---|---|---|
| 台账 | `裁决记录.md`（**不带轮次、不带版本号**） | 唯一权威登记处的入口，路径稳定，外部引用不改 |
| 存档细则 | `00-baseline/裁决R<起轮>-R<止轮>.md`，轮次用两位数字（`R01`） | 文件名可直接反推覆盖的轮次区间，`check-docs` 据此验证「每轮恰好一片」 |
| ADR | `02-adr/NNNN-主题.md`，增补 `02-adr/附录/NNNN-增补.md` | 与既有 P-3 的编号约定一致 |
| 落地记录 | `01-roadmap/首版-记录-G<块>.md` | 与能力块编号一一对应 |

> **与 P-3 的关系**：P-3 明写「文档不做版本号另存」「裁决类信息统一进 `裁决记录.md`」。
> 本轮的**例外经 `P-27` 显式授权**：**新增**按轮次区间命名的存档文件（不是把同一份文档另存成多版），
> 且台账仍是**唯一**登记处——存档只是细则，不承担登记职责。除该例外外 P-3 继续有效。

## 三、模板

### 3.1 台账行（`裁决记录.md` 条目表）

五列，一行一条：`ID | 轮次 | 结论 | 状态 | 细则`（无「主题」列——结论本身就是主题，避免重复）。

- `状态` 是**闭集**：`有效` / `已闭` / `取代`（必须在「结论」里写明被谁取代）/ `未决`（必须指向 `首版-待定清单.md` 的条目）；
- `细则` 一律写成 `[细则](文件.md#<条目 slug>)`，**必须带锚点**——不带锚点的指向会在拆分后静默落到文件顶部；
- 「结论」列从既有条目标题**逐字截取**，不新增转述。

### 3.2 存档文件（`裁决R*.md`）

```
# 裁决细则 R<起>–R<止>（<首轮主题> … <末轮主题>）

> 本文件是 [裁决记录](../00-baseline/裁决记录.md) 的**细则层**：覆盖第 X 轮到第 Y 轮，
> 逐字迁移、不改写。登记与状态见台账对应行；上/下一份：…
> 对应台账行：`D-n…`、`R-n…`、`T-n…`、`P-n…`

（原文逐段，一字不改）
```

- 一个 `## 第N轮` 标题段**整体**属于一份存档，不跨文件；
- 块首的 `---` 分隔线**归属其后的轮次**；正文行内内容不改；
- 不许按 `###` 切——`###` 里既有条目（`### P-n`）也有轮内小结（`### 修法…`）。

### 3.3 路线图能力块

`### G<n> 标题` + 依次四段：`> **状态**` / `**内容**` / `**出口条件**` / `**可延后**`，
末尾一行 `**细则**：→ 首版-落地记录/G<n>.md`（写成普通指向该文件的链接）。
**仅存的块**才有「状态」；已收口的老块写 `> **状态：已完成（本块仅存档，不随新裁决更新）。**`

### 3.4 ADR 增补节（`02-adr/附录/NNNN-增补.md`）

每节 `## §<编号> <标题>（P-<n> 增补）`，首行必须声明它与正文的关系：
「**新增**」或「**修订正文 §x 的实现方式（语义不变）**」。正文里留一行指针。

## 四、体量上限、增长纪律与四条纪律

上限登记在 `docs/doc-index.json`（唯一真相源），由 `pnpm docs:check` 判定。

### 4.1 增长纪律（五条）

1. **台账只追加行**，行有界（结论 ≤80 字）⇒ 体量与轮次线性、不膨胀；
2. **细则一轮一文件** ⇒ 单文件永远不随轮次长大；
3. **ADR 的追加段有明确规则**（见 §4.3）：**契约性**增补可以留在正文，但必须带轮次标记与附录指针；
   **记录性**内容（返工史、复验过程、落地记录）一律不进 ADR；
4. **记录层可以无限增长**（它就是历史），但**不得被上游引用为「当前值」**；
5. 任何文件触及上限时，**动作是拆分或迁移，不是提高上限**（提高上限必须在台账留一条新裁决）。

### 4.2 契约常量单点声明（纪律一）

每个契约常量（`c₃` 逐档位锚值、`c₄` 与 `overlay`、刻度长度、表头带高度、折点引出段、性能阈值 `1 ms`/`2 ms`、
诊断码表条目数、轴与条色值……）在 `doc-index.json` 的 `constantCheck` 里登记**唯一声明处**；
其余位置只允许两种写法：**指回声明处**，或**在例外表里带 `reason` 登记**。
判定：`scripts/check-constants.mjs`。值不同标「错值」、值相同标「重复陈述」——**位置本身就是错**。

### 4.3 ADR 追加段规则（收口 P1-d 记下的「规范与实际不一致」）

**允许**在 ADR 正文追加**契约性**增补段（不为此新建 ADR），四条同时成立：

1. 标题带轮次标记：`## §<编号> <标题>（P-<n> 增补）`；
2. 首行声明与既有节的关系，三选一且必须点名 `§x`：**新增** / **修订 §x 的实现方式（语义不变）** / **取代 §x**；
3. `02-adr/附录/NNNN-增补.md` 里有对应条目，**正文段与附录条目互相指针**（模板见 §3.4）；
4. **记录性内容不得进正文**：返工史、逐轮复验过程、「落地（记录）」、教训叙事一律进记录层或其附录。

> 本条**判定是人工**（D5 逐份过一遍），没有机械守卫：ADR 的基础编号各份不同（0006 用 `## 10.`、0007 用 `## 11.`），
> 靠标题编号机器判定会把基础节误报成追加段。原措辞「ADR 正文不再追加 §N」与实际不符
> （0005/0006/0007/0008/0010 都已有追加段），故改写为上面这条「允许但必须带指针」的规则。

### 4.4 精简层预算与入口封闭性（纪律二）

`doc-index.json` 的 `layer`（`slim` / `archive`，每份文档一条）与 `contextBudget` 是唯一真相源：
**精简层 ≤ 100 KB**（其中**必读 ≤ 25 KB** ＝ 台账 + 当前规划 + 待定清单）、**入口 `docs/README.md` ≤ 6 KB 且只引用精简层**；
`userFacing`（用户手册）与 `budgetExempt`（v0.2 临时施工计划）不计入预算，但列在报告里。
判定：`check-docs.mjs` §8b（超预算时**列出最大的若干份**，不是只报一个总数）。达标动作是拆分或迁归档层，**不是提高上限**。

### 4.5 spike 生命周期（从 G4-S 先例提炼，供后续 spike 复用）

> **一个 spike 目录可以在满足以下全部条件后整体删除**：
> ① 其结论已**重新表达为进 `pnpm gate` 的 `packages/**` spec**，或测量协议已**移植进受维护的脚本**；
> ② 决策相关的数字已**冻结进 ADR / 计划文档**；
> ③ 全部引用已迁移或登记进白名单。
> **删除后，正文里的历史引用保留原路径并加括注**（先例：「该目录已随 G4 落地删除，数字转入本包 spec」）。

### 4.6 仓库外路径、被 `.gitignore` 覆盖的路径与基线层校验（纪律三 / 决策 8）

1. **基线层必须可被原文校验**：`00-baseline/` 的三份来源文档是**二次产物**（`需求基线.md` 自称「结构化重建」），
   它们唯一能对照的基准是**上游原文** ⇒ 原文必须**入仓**（归档层、`layer: "archive"`），且按 `P-3` 冻结口径
   **只此一份、不做多版并存**。
2. **入仓原文的来源行**必须记：原始路径、文档版本、获取日期、`sha256`、与重建件的关系
   （「重建件的保真度以本原文为准」）。
3. **本机绝对路径不得出现在可复现层**（`layer: slim` 或 `role: baseline`）的正文里
   （`C:\…` / `D:/…` / `~/…` / `/Users/…` / `/home/…`）：换机器、清下载目录、clone 仓库都会让它悬空。
   判定：`check-docs.mjs` §8d ⇒ **error**。归档 / 证据 / spike 层里的本机路径是「当时的机器事实」，
   记录制证据按先例不改写（`P-41 §9(a)` / `P-44 §9(a)`）⇒ 只出**一条聚合警告**（存量执行落 C8、D9）。
4. **被 `.gitignore` 覆盖的临时路径**（`temporaryPathPatterns`：`tmp/`、`*.tmp`）不得被当成「可复现引用」：
   同一行（或**紧邻的下一行**）出现声明词（`gitignore` / `不入库` / `可再生` / `临时` …）才算已注明，否则 ⇒ **warning**。
   **可再生的构建产物**（`dist/` / `node_modules/` / `out/`）**不在判定内**——文档引用它们是正常口径。
5. **例外表** `externalPathCheck.allow`：每条必须写 `kind`（闭集：`环境观测` / `来源元信息` / `产物说明` / `规范示例`）与 `reason`，
   且至少写 `path` 或 `pathRegex`（否则等于把整条守卫关掉）。例外**不等于修好了**，而是「这一处按裁决保留」；
   本规范自己必须写出被禁止的形态（上面第 3 条与 §五 第 10 行），故以 `规范示例` 登记一条**只对本文件生效**的例外。

## 五、检查

`pnpm docs:check`（`scripts/check-docs.mjs`，已接入 `scripts/gate.mjs`）：

| # | 检查 | 破了会怎样 |
|---|---|---|
| 1 | `docs/doc-index.json` ↔ 实际文档集合**双射** | 新文档漏登记 / 登记了不存在的文件 |
| 2 | 全部 markdown **相对链接目标存在**（含 `#` 前部分） | 搬迁后留下 404 |
| 3 | 全部**锚点可解析**（按 GFM slug 规则，含内联 code span 整段剥离、重复标题 `-1` 后缀） | 拆分的第二类静默破环 |
| 4 | 正文/注释/markdown 里的 `` `路径.md` `` 或**目录**提及若失效 → **警告** | 跨层引用漂移、来源链断裂（历史失效路径走 `linkCheckAllowlist`，每条必须带 reason） |
| 5 | 台账行格式、ID 唯一且连续、`未决` 行与待定清单**双向一致** | 台账与待定清单分叉 |
| 6 | 每个 `## 第N轮` 恰好被一份存档覆盖、每份存档名与内容区间一致；**轮次上界由台账推导**、每轮都要有存档 | 漏轮 / 重轮 / 上界写死后新存档不受检查 |
| 7 | `---` 不得是存档文件首行；URL 内不得出现全角字符 | 分隔线漂移、坏链 |
| 8 | 体量上限（按角色） | 膨胀复发 |
| 9 | 策略不变量：`README`/`CONTRIBUTING`/台账文首的「唯一登记处 / 不按版本另存」措辞与 `DOC-SPEC` 一致，且 P-27 例外条目存在 | 规范与实际再次分叉 |
| 10 | **本机绝对路径**（`C:\` / `D:/` / `~/` / `/Users/` / `/home/`）出现在**可复现层**（`layer: slim` 或 `role: baseline`）⇒ **错误**；出现在归档 / 证据 / spike 层 ⇒ **一条聚合警告** | 基线层被绑死在一台机器的下载目录上（决策 8） |
| 11 | 引用**被 `.gitignore` 覆盖的临时路径**（`externalPathCheck.temporaryPathPatterns`）且同一行（或紧邻下一行）无声明词 ⇒ **警告** | 把「维护者本机的草稿」当成可复现输入 |

> **配置键**（唯一真相源都在 `docs/doc-index.json`）：`caps`、`layer`、`contextBudget`、`pendingList`、
> `linkCheckAllowlist`（每条带 `reason`）、`crossLayerCheck`（`markers` + `allow`）、`constantCheck`
> （唯一声明处 + 例外）、`externalPathCheck`（`errorScope` + `markers` + `temporaryPathPatterns` + `allow`）。
>
> **P1 建的三条检查与 D1 加的两项守卫**（都在同一步 `pnpm docs:check` 里）：
> ① 契约常量单点声明（`check-constants.mjs`；纪律见 §4.2）；
> ② 精简层预算与入口封闭性（`check-docs.mjs` §8b；纪律见 §4.4）；
> ③ 跨层引用必须带标记词（`check-docs.mjs` §8c：`历史` / `原文口径` / `细则` / `依据` / `存档`；入口页由 §8b 判，不指归档层）；
> ④ 仓库外路径与被 gitignore 覆盖的临时路径（`check-docs.mjs` §8d；纪律见 §4.6）。
>
> 脚本的 `--selftest`（`node scripts/check-docs.mjs --selftest`，当前 **18 例**；`node scripts/check-constants.mjs --selftest`）
> 是这四条的**反向保护**：每类判定都配一个「该绿就绿、该红就红」的合成用例。
