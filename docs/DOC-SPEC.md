# 文档规范（DOC-SPEC）

> 本文件**只规定「什么信息住在哪一层、怎么检查」**，不收录任何契约内容。
> 契约内容在 [docs/02-adr/](02-adr/) 与各包规范；判定在 [首版能力顺序](01-roadmap/首版能力顺序.md)；
> 裁决登记在 [裁决记录](00-baseline/裁决记录.md)。
> 权威裁决：`P-27`（第二十七轮，见 [裁决记录 §第二十七轮](00-baseline/裁决记录.md)）。

## 一、四层模型

一句话：**判定（plan）在路线图；契约（decide）在 ADR；登记（register）在台账；过程与结果（act / result）在记录层；原始证据在 evidence/spikes；教训与未决各只在一处。**

| 层 | 回答的问题 | 住所 | 角色标记 |
|---|---|---|---|
| 登记 | 「定过什么、现在还算不算」 | `00-baseline/裁决记录.md`（台账）+ `00-baseline/裁决R*.md`（细则） | `register` || 契约 | 「必须怎么做、边界在哪」 | `02-adr/NNNN-*.md`、`docs/02-adr/附录/*`、各包 `SCHEMA/COMMAND/SCHEDULE/SPEC/PROTOCOL.md` | `contract` |
| 判定 | 「先做什么、怎样才算做完」 | `01-roadmap/首版能力顺序.md` | `plan` |
| 记录 | 「实际做了什么、实测数字与教训」 | `01-roadmap/首版-记录-*`、`02-adr/附录/*`、`apps/web/evidence/*`、`spikes/*/evidence/*` | `record` |
| 待定 | 「还没定的事」 | `01-roadmap/首版-待定清单.md`（全仓唯一） | `plan` |
| 基线 | 「上游原文怎么写的、当时怎么评估的」 | `00-baseline/{需求基线,评估报告,证伪实验计划}.md` | `baseline` |

**反重复规则（本规范的核心）**
1. 同一事实**只允许有一处权威陈述**；其他地方只能写指针（`见 [P-8](…)`），不得复述内容；
2. **验证矩阵/判据表只在一个地方登记**：产品级 DoD 在路线图 §六；包级矩阵在各包 `*/SPEC.md`/`SCHEDULE.md`；ADR 只登记「形状与语义」，不登记逐轮返工；
3. 逐轮返工史**只进记录层**，不进 ADR 正文、不进路线图的「内容/出口条件」段；
4. 基线文档不得承载「当前生效值」——引用它们时必须写明「原文口径，现状见 …」。

## 二、命名的反向映射规则

| 文件形态 | 规则 | 为什么 |
|---|---|---|
| 台账 | `裁决记录.md`（**不带轮次、不带版本号**） | 唯一权威登记处的入口，路径稳定，外部引用不改 |
| 存档细则 | `00-baseline/裁决R<起轮>-R<止轮>.md`，轮次用两位数字（`R01`） | 文件名可直接反推覆盖的轮次区间，`check-docs` 据此验证「每轮恰好一片」 |
| ADR | `02-adr/NNNN-主题.md`，增补 `02-adr/附录/NNNN-增补.md` | 与既有 P-3 的编号约定一致 |
| 落地记录 | `01-roadmap/首版-记录-G<块>.md` | 与能力块编号一一对应 |

> **与 P-3 的关系**：P-3 明写「文档不做版本号另存」「裁决类信息统一进 `裁决记录.md`」。
> 本轮的**例外经 `P-27` 显式授权**：**新增**按轮次区间命名的存档文件（不是把同一份文档另存成多版），
> 且台账仍是**唯一**登记处——存档只是细则，不承担登记职责。除该例外外 P-3 继续有效。

## 三、模板

### 3.1 台账行（`裁决记录.md` 条目表）

五列，一行一条：`ID | 轮次 | 结论 | 状态 | 细则`（无「主题」列——结论本身就是主题，避免重复）。

- `状态` 是**闭集**：`有效` / `已闭` / `取代`（必须在「结论」里写明被谁取代）/ `未决`（必须指向 `首版-待定清单.md` 的条目）；
- `细则` 一律写成 `[细则](文件.md#<条目 slug>)`，**必须带锚点**——不带锚点的指向会在拆分后静默落到文件顶部；
- 「结论」列从既有条目标题**逐字截取**，不新增转述。

### 3.2 存档文件（`裁决R*.md`）

```
# 裁决细则 R<起>–R<止>（<首轮主题> … <末轮主题>）

> 本文件是 [裁决记录](../00-baseline/裁决记录.md) 的**细则层**：覆盖第 X 轮到第 Y 轮，
> 逐字迁移、不改写。登记与状态见台账对应行；上/下一份：…
> 对应台账行：`D-n…`、`R-n…`、`T-n…`、`P-n…`

（原文逐段，一字不改）
```

- 一个 `## 第N轮` 标题段**整体**属于一份存档，不跨文件；
- 块首的 `---` 分隔线**归属其后的轮次**；正文行内内容不改；
- 不许按 `###` 切——`###` 里既有条目（`### P-n`）也有轮内小结（`### 修法…`）。

### 3.3 路线图能力块

`### G<n> 标题` + 依次四段：`> **状态**` / `**内容**` / `**出口条件**` / `**可延后**`，
末尾一行 `**细则**：→ 首版-落地记录/G<n>.md`（写成普通指向该文件的链接）。
**仅存的块**才有「状态」；已收口的老块写 `> **状态：已完成（本块仅存档，不随新裁决更新）。**`

### 3.4 ADR 增补节（`02-adr/附录/NNNN-增补.md`）

每节 `## §<编号> <标题>（P-<n> 增补）`，首行必须声明它与正文的关系：
「**新增**」或「**修订正文 §x 的实现方式（语义不变）**」。正文里留一行指针。

## 四、体量上限与增长纪律

上限登记在 `docs/doc-index.json`（唯一真相源），由 `pnpm docs:check` 判定。

增长纪律（比上限更重要）：
1. **台账只追加行**，行有界（结论 ≤80 字）⇒ 体量与轮次线性、不膨胀；
2. **细则一轮一文件** ⇒ 单文件永远不随轮次长大；
3. **ADR 正文不再追加 §N**：契约变更写新 ADR，或**改写**受影响的那一节并在附录留增补记录；
4. **记录层可以无限增长**（它就是历史），但**不得被上游引用为「当前值」**；
5. 任何文件触及上限时，**动作是拆分或迁移，不是提高上限**（提高上限必须在台账留一条新裁决）。

## 五、检查

`pnpm docs:check`（`scripts/check-docs.mjs`，已接入 `scripts/gate.mjs`）：

| # | 检查 | 破了会怎样 |
|---|---|---|
| 1 | `docs/doc-index.json` ↔ 实际文档集合**双射** | 新文档漏登记 / 登记了不存在的文件 |
| 2 | 全部 markdown **相对链接目标存在**（含 `#` 前部分） | 搬迁后留下 404 |
| 3 | 全部**锚点可解析**（按 GFM slug 规则，含内联 code span 整段剥离、重复标题 `-1` 后缀） | 拆分的第二类静默破环 |
| 4 | 正文/注释里的 `` `路径.md` `` 提及若失效 → **警告** | 跨层引用漂移（历史失效路径走白名单） |
| 5 | 台账行格式、ID 唯一且连续、`未决` 行与待定清单**双向一致** | 台账与待定清单分叉 |
| 6 | 每个 `## 第N轮` 恰好被一份存档覆盖、每份存档名与内容区间一致 | 漏轮 / 重轮 |
| 7 | `---` 不得是存档文件首行；URL 内不得出现全角字符 | 分隔线漂移、坏链 |
| 8 | 体量上限（按角色） | 膨胀复发 |
| 9 | 策略不变量：`README`/`CONTRIBUTING`/台账文首的「唯一登记处 / 不按版本另存」措辞与 `DOC-SPEC` 一致，且 P-27 例外条目存在 | 规范与实际再次分叉 |
